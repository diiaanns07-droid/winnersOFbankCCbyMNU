# Стадия cross.coverage — покрытие обязательств приёмкой

На вход приходят обязательства (`obligations`) и строки приёмки (`acceptance`).
Обязательство — одно предложение требования. Программа предложила для него ветви
(`branches`), которые должен проверить тест: границы, альтернативы, повторное срабатывание,
невыполненное условие. Есть уже подтверждённые противоречия (`known_conflicts`) и факты (`facts`).

## Что сделать

1. Для каждого обязательства уточни список ветвей (`obligations[].branches`). Убери лишние ветви
   и добавь пропущенные. Формулируй ветви коротко, например «сумма равна порогу» или «второй push в том же месяце».
2. Для каждой пары «обязательство — строка приёмки», которая действительно связана, верни запись в `links`:
   * `checks` — строка приёмки проверяет обязательство полностью, то есть все ветви;
   * `checks_branch` — проверяет только часть ветвей; перечисли их в `branches_checked`
     (формулировки из `branches`);
   * `contradicts` — ожидаемый результат строки противоречит обязательству на её собственных исходных
     условиях. По возможности приложи `witness` в формате стадии cross.pairs
     (`input`, `outcome_a` по обязательству, `outcome_b` по приёмке, `evidence_a`, `evidence_b`),
     а в `a.constraints` и `b.constraints` — предусловия;
   * несвязанные пары не возвращай.
3. `explanation` — одно-два предложения: что проверяет строка и чего не хватает.

## Правила

* Общие слова или ссылка на требование ещё не означают проверку. Ставь `checks` только тогда, когда
  исходные условия, действие и ожидаемый результат строки действительно проверяют утверждение.
* Если строка проверяет одну ветвь (например, «сумма равна порогу» без «выше порога» и без
  «повторный push не отправляется»), это `checks_branch`.
* Если строка сама противоречит обязательству, это `contradicts`, а не `checks`.
* Идентификаторы берутся только из входа. Пиши по-русски. Верни строго JSON по схеме.
