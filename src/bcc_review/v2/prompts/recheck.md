Задание: пересмотр дефектов после ответов владельца

Владелец документа ответил на вопросы ревью (блок <ответы>). Каждый ответ — решение, которое будет вписано
в документ. Для каждого дефекта из блока <затронутые_дефекты> реши, что с ним станет, когда это решение
окажется в тексте требований.

Блок <остальные_дефекты> — существенные дефекты без ответа на их вопрос. Если какой-то ответ или общее
решение (Решение-N) прямо закрывает или меняет такой дефект, добавь решение и по нему (status resolved или
changed, by обязателен). Остальные дефекты этого блока не упоминай: они останутся открытыми.

Статусы:
- resolved — ответ однозначно задаёт недостающее правило или выбирает одну из конфликтующих сторон, и после
  его внесения в документ дефекта не останется. В reason назови ответ (Q-…) и объясни, почему проблема снята:
  какое значение теперь определено, какая сторона конфликта приведена к какой.
- changed — ответ снимает часть проблемы, но что-то остаётся: другая сторона конфликта, другая ветка, другой
  вход. Опиши в title и problem только то, что осталось, и поставь новую серьёзность по шкале. Если осталось
  мелкое следствие, серьёзность снижается; если для оставшейся части по-прежнему два места документа дают
  разные исходы на одном входе или ключевое правило не определено, серьёзность прежняя.
- open — ответ не касается сути дефекта, слишком общий («обсудим позже», «как обычно»), противоречит сам себе
  или не задаёт проверяемого правила. В reason объясни, чего не хватает.

by — ID ответов, которые прямо снимают дефект или его часть: «Q-03», «Решение-2». Для resolved и changed
by обязателен; для open — пустой список. Ответ на соседний вопрос, общее пожелание или ответ о другом входе
дефект не снимает.

conflicting_answers — если два ответа по этому дефекту противоречат друг другу (один ответ задаёт одно
значение, другой — другое для того же входа), перечисли их ID, например ["Q-02", "Решение-2"], а статус
поставь open: владелец должен выбрать один из них. Иначе — пустой список.

Пиши кратко: reason — одно-два предложения (до 300 символов): какое значение теперь определено и на каком
входе дефект больше не проявляется; title и problem заполняй только для changed, для resolved и open оставляй
пустые строки; severity для resolved и open — прежняя.

Будь честен: не закрывай дефект, если ответ не даёт конкретного правила для того входа, на котором дефект
проявляется. Проверь это на сценарии дефекта: подставь вход из сценария и убедись, что по ответу исход теперь
один. Не закрывай дефект только потому, что на связанный вопрос что-то ответили. Если у дефекта несколько
частей (две стороны, две ветки, два поля), а ответ закрывает одну — это changed, а не resolved.

Новые кандидаты (candidates): ответ может породить новый конфликт — выбранное правило противоречит другому
месту документа, которое раньше с ним не конфликтовало (критерию приёмки, контракту API, данным, другой части
документа). Опиши каждый такой конфликт как кандидата: в evidence — дословная цитата места документа, которое
теперь противоречит ответу, с номером строки; в problem — какой ответ (Q-…) с ним расходится; в scenario —
вход, на котором ответ и документ дают разные результаты. Не повторяй дефекты из обоих блоков дефектов.
Не считай конфликтом место, которое нужно просто переписать по ответу: старую формулировку того же правила,
прежний адрес, прежний пример, прежнее значение в таблице — их исправит редакция документа. Конфликт — это
когда ответ и другое правило, которое ответ не меняет, дают разные результаты на одном входе. Два ответа,
которые противоречат друг другу по одному дефекту, отмечай в conflicting_answers этого дефекта, а не
кандидатом. Таких конфликтов обычно 0–3. Если новых конфликтов нет — верни пустой список.

Пиши по-русски, для владельца документа: в reason, title и problem ссылайся на ответы (Q-…, Решение-N) и на
пункты документа их названиями, без номеров строк. Латинские имена полей, методов и адресов бери только из
документа и из ответов владельца, новых английских имён не придумывай.

Ответ — только JSON по схеме: {"decisions": [...], "candidates": [...]}.
