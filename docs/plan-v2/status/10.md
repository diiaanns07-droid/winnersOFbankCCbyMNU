# №10 — судья: статус

Ветка: `v2/10-judge` (рабочая `claude/relaxed-hamilton-o05z02`, каждый push дублируется).

## Сделано
* `src/bcc_review/v2/stages/judge.py` — этап `judge.run(ctx, candidates)`:
  предкластеризация кодом (тот же kind + те же требования + близкие строки; одно правило — один кластер),
  компактная подача при > 60 кандидатов, деление пакета при обрезке, проверка «каждый C-xxx ровно в одном
  месте», повторный короткий вызов для пропущенных, затем `rejected` «не рассмотрен судьёй» + предупреждение;
  evidence/sources из кандидатов (≤ 5 цитат, по строкам), `standard_refs` по критерию, защита шкалы
  (critical без сценария/последствий/blocks, ИБ, термины, шаблоны → major; ≤ 7 critical; «нет ID» — одно minor),
  приоритеты 1…7, чек-лист (таблица документа или 14 пунктов банка в коде, пропуски заполняет код),
  запасной реестр без модели, `compute_verdict()` по правилу CONTRACT §5.
* `src/bcc_review/v2/prompts/judge.md` — промпт судьи (подстановки `{{candidates}}`, `{{checklist}}`, `{{stats}}`).
* `tests/v2/test_10_judge.py` — 16 тестов на синтетике (70 кандидатов, дубли, ложные, сигналы правил, потери,
  обрезка, отказ модели, чек-лист, вердикт, анти-подгонка промпта).

## Как проверить
`python -m pytest tests/v2/test_10_judge.py -q`

## Выход этапа (дополняет CONTRACT 2.4)
`{"findings": [...2.4], "rejected": [...], "checklist": [{item, answer, comment, finding_ids}],
"verdict_summary": str, "fix_first": ["D-01", ...], "warnings": [...], "checklist_source": "document|bank"}`

`rejected[i]`: `{"candidate_id", "title", "source", "severity", "reason_code", "reason", "line", "lines"}`;
`reason_code`: `misread | exact_sense | resolved_elsewhere | unrelated | out_of_scope | no_quote | not_reviewed`.

## Просьбы
* №01: в `ctx.prompt("judge", candidates=…, checklist=…, stats=…)` подставлять эти три переменные;
  `ctx.llm.ask(..., max_output_tokens=16000)`; при обрезке ответа — исключение с `kind="truncated"`
  (или имя класса с `Trunc`) — судья делит пакет сам. Вердикт: можно звать `judge.compute_verdict(findings, status)`.
* №13: поля `rejected` и `checklist_source` выше; `fix_first` — порядок «исправить первым».
