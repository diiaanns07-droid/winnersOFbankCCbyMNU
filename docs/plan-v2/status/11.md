# №11 — вопросы владельцу, режим ответов, исправленное ТЗ

Ветка: `v2/11-clarify` (работаю в `claude/modest-archimedes-9v29rn`, каждый push дублирую в `v2/11-clarify`).

## Сделано
* `stages/clarify.py` + `prompts/clarify.md` — `clarify.run(ctx, findings) -> {"questions": [...]}`, 1 вызов.
  Код: цитаты сверяются (`quotes.verify_quote`, пока его нет — запасная сверка), выдуманная цитата заменяется
  цитатой дефекта; варианты «оставить как есть / на усмотрение / решить позже / <уточнить>» выбрасываются;
  2–4 варианта, иначе вопрос снят; связь с существующими D-…; блокирующий = есть critical или major из
  «исправить первым» (priority 1–7); блокирующие первыми; ≤ 10; ID Q-01…
  Поля вопроса: контракт 2.5 + `topic` (имя решения) и `evidence` (цитаты обеих сторон, сверены кодом).
* `stages/recheck.py` + `prompts/recheck.md` — режим `--answers`:
  `recheck.apply_answers(ctx, report, answers_path) -> {"clarification", "findings_after", "rejected_after"}`.
  Ответы: MD (`Q-01: B`, `Q-01: свой текст`, `Q-01 [тема]: …`, раздел «Решения»), JSON (4 формы).
  Тема в скобках перепривязывает ответ к вопросу с той же темой (номера меняются от прогона к прогону);
  неоднозначная тема → общее решение. Расплывчатые ответы («обсудим позже», «как обычно») не считаются.
  Модель решает `resolved|changed|open` только по затронутым дефектам, код игнорирует решения по остальным.
  Новые конфликты от ответов → кандидаты (цитаты сверены) → `judge.run` (пока судьи нет — приняты как есть).
  Вердикт «до/после» — одно правило кода (контракт, раздел 5): `recheck.verdict_rule`.
  `recheck.render_markdown(clarification, findings_after)` — готовый раздел «Уточнение: до и после».
* `stages/revise.py` + `prompts/revise.md` — режим `--revise`:
  `revise.run(ctx, findings, answers=clarification|None) -> {"rewrites", "revised_markdown", "stats"}`,
  `revise.write(report_path, result)` → `<отчёт>.revised.md`, `revise.render_markdown(result, file)` — раздел
  «было → стало». Правки применяет код: фрагмент ищется в строке (кавычки, тире, разметка), не найден — не
  применяется; пометки `[изменено: D-…]`, `[добавлено: D-…]`, `[удалено: D-…]`; строки таблиц и списков в стиле
  документа; правки внутри блоков кода помечаются после блока.
* `examples/v2/answers.md` — ответы по официальному документу (10 ответов с темой + 7 общих решений).

## Просьбы
* №01: проще всего — один вызов после clarify: `revise.run_modes(ctx, report, answers=ПУТЬ|None,
  do_revise=bool, report_path=путь_отчёта)` → поля для `report.json` + `markdown_sections` (готовые разделы).
  Или по отдельности: в pipeline после судьи вызвать `clarify.run(ctx, findings)`; при `--answers ФАЙЛ` —
  `recheck.apply_answers(ctx, report, ФАЙЛ)` и положить `clarification` в `report.json`; при `--revise` —
  `revise.run(ctx, findings, clarification or None)` + `revise.write(путь_отчёта, res)`; `rewrites` в отчёт.
  Если в `--revise` есть ответы, лучше передавать `findings` «до» (правки по всем дефектам с подставленными ответами).
  Путь к входному файлу — в `ctx.options["input"]` (revise читает исходный MD, чтобы сохранить разметку).
  Mock-ответы этапов: `tests/v2/fixtures/11_official/clarify.json` (можно скопировать в фикстуру official).
