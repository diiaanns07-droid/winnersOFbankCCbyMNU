1. **`62965d6` — веб-демо падает трейсбэком, если порт занят.** Что ломается: второй запуск
   `python -m bcc_review.v2.web --open` (или порт 8014 занят другой программой) — `OSError: [Errno 98] Address already
   in use` по-английски; на Windows хуже: `SO_REUSEADDR` пускает второй сервер на тот же порт молча, запросы уходят то
   в один, то в другой. Воспроизвести: запустить демо дважды. Стало: второй запуск пишет «Веб-демо уже запущено:
   http://127.0.0.1:8014/», открывает его при `--open`, код 0; порт занят чужой программой — сервер поднимается на
   следующем свободном с сообщением; неверный `--host` — «такого адреса нет», код 2; на Windows — исключительный порт.
   Тест: `tests/v2/test_34_web_release.py` (5 тестов про порт).
2. **`aba7f99` — веб не видит ключ из `.env`, который видит CLI.** Что ломается: `.env` из Блокнота (UTF-8 с BOM) —
   Gemini в форме «недоступен», хотя `python -m bcc_review` с тем же `.env` работает; `.env` из PowerShell 5.1
   (`echo GEMINI_API_KEY=… > .env`, UTF-16) — веб-демо падает `UnicodeDecodeError` при старте; запуск не из корня — `.env`
   корня не читается. И «Автовыбор» был подписан «Claude через Claude Code CLI», а `--provider auto` при ключе Gemini
   запускает Gemini. Стало: загрузчик CLI (`doctor.load_dotenv`, тот же порядок поиска), подпись автовыбора —
   по `doctor.resolve_auto`, наличие Claude CLI — по `find_cli` (как у CLI, с Windows-путями npm).
   Воспроизвести: `printf '\xef\xbb\xbfGEMINI_API_KEY=x' > .env; python -m bcc_review.v2.web` — Gemini «недоступен».
   Тест: `tests/v2/test_34_web_release.py` (5 тестов про `.env` и автовыбор).
