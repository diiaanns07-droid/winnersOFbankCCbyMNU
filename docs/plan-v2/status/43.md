## Что сделано

- **`gallery_block(app) -> str`** — блок «Готовые отчёты» для главной (его уже вызывает `_gallery()` №39):
  карточки на бумаге (`.b-surface`) — название, одна строка «модель · дата» и метка «вердикт: нельзя, блокеров 5»
  (цвет по смыслу: `.b-badge crit/major/ok`). Ниже — «Проверить пример:» капсулами `.b-button small` и одна строка,
  каким провайдером пойдёт проверка. Главной (зелёной) кнопки в блоке нет. Стили — маленький `<style>` с классами
  `.g43-*` на токенах `--b-*` внутри блока; внешних ссылок нет.
- **Готовый отчёт = обычное завершённое задание** `00000000-000043-<6 hex>` в `JobStore`: открывается тем же
  экраном `/jobs/<id>`, что своя проверка, без ключа, без сети, без повторного анализа — **290–390 мс** от нажатия до
  показанного отчёта (Playwright, 1440 и 390). Пометка одной строкой: «Готовый отчёт: Claude Sonnet, 27.11.2026 —
  открыт из файла, модель не вызывалась» (у демо — «Готовый отчёт без модели: ответы модели записаны заранее…»).
  Номер задания зависит от содержимого `report.json`: обновился отчёт — новое задание, старое удаляется само.
  Готовые задания хранятся без `job.json` (только `ready.json`), поэтому не попадают в «Последние проверки» ни при
  старте, ни потом (`store.recent` их пропускает); после перезапуска берутся с диска без копирования.
- **`examples/examples.json`**: 4 отчёта — `reports/requirements.*` (официальный ТЗ), `reports/requirements_pdf.*`
  (из PDF), `reports/other_topic_cashback.*` (исходник — `evaluation/dev/corpus/cases/cashback.base/source.md`, как
  в плане №36) — от №36; карточка появится сама, когда файлы будут в ветке; модель/дата/вердикт берутся из
  `report.json`, руками ничего не пишем. Необязательные выгрузки `docx`/`pdf`/`csv` (Jira) подхватываются, если есть.
  Четвёртый — **«Официальный ТЗ · демо»**: `examples/mock/requirements.{json,html,md}`, `--provider mock`,
  сгенерирован инструментом на чистом дереве (команда — `examples/README.md`).
- **Примеры документов одним нажатием** (`POST /examples/check/<id>` → 303 `/jobs/<id>`): официальный ТЗ (MD и PDF),
  кэшбэк (`cashback.base`), чистый `transfer_limit.base` (`evaluation/v2/RESULTS.md`, корпус «базы и перефразы»:
  0 critical, «можно / можно», P1 не нарушен). С ключом — провайдер «Автовыбора»; без ключа — официальный ТЗ через
  `mock`, остальные через `offline` с пометкой «только правила». Проверено в браузере: offline — 3,5 с, PDF через
  mock — 2,5 с до показанного отчёта. Слепой набор и `*.key.json` не используются.
- `GET /examples/<id>` — постоянная ссылка на готовый отчёт (для README/презентации: `http://127.0.0.1:8014/examples/mock`).

## Как проверить

```bash
PYTHONPATH=src python -m pytest tests/v2/test_43_gallery.py -q
```

10 тестов без сети и без ключа: карточки только для существующих файлов (нет json, html или исходника — нет
карточки); `examples.json` ссылается на существующие пути, пути относительные; мок-отчёт сгенерирован, не правлен
(`provider=mock`, `dirty=false`, sha256 входа = официальный); готовое задание открывается < 1 с, переживает
перезапуск и обновляется при смене отчёта; «Последние проверки» без готовых заданий; пример документа проходит
настоящий pipeline (`offline` и `mock`) и открывает отчёт.

Снимки: `docs/plan-v2/wave5/shots/43-home-1440x900.png`, `43-home-390x844.png` (вся страница),
`43-report-1440x900.png`, `43-report-390x844.png`. На снимках одна карточка (демо): отчётов №36 ещё нет.
Сетку из 4 карточек проверил локально на копиях демо-отчёта (в репозиторий не клал): 4 колонки на 1440, 2 до 1100,
одна на телефоне, горизонтальной прокрутки нет.
