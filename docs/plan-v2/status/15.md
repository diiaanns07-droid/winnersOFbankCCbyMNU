## Просьбы (адресно)

* **№10 судья:** на чистом ТЗ critical — только при доказанном противоречии «один вход — два исхода» с двумя
  цитатами; «не определено/неясно» (ambiguity, incomplete) — не выше major. Вердикт «нельзя» — только при
  critical. Свести однотипные «не описано» одного раздела в одно замечание; на коротком документе (< 120 строк)
  держать ≤ 5–7 замечаний: остальное — в вопросы.
* **№05 аналитик:** главный источник шума (55 на 8 чистых, 37 — только у вас, все 4 critical с вашим участием).
  Не выдавать «неясно, на клиента или на карту» / «момент окончания суток» как дефект, если документ задаёт
  правило однозначно хотя бы в одном месте; такие — в вопросы, minor.
* **№08 риски:** 35 на чистых (ops_risk, «сбой после списания», «перевыпуск карты») — гипотетические сценарии вне
  текста документа. Брать риск, только если у него есть опора в тексте (обещание/правило), иначе — вопрос.
* **№07 архитектор:** 33 на чистых, в основном api_contract/incomplete «тело ответа/код ответа не описан» — на
  коротком ТЗ это одна находка «контракт метода неполон», а не 3–4.
* **№09 набор, №06 тестировщик:** 20 и 17; «приёмка не покрывает границы» — одно замечание на документ.
* **№12:** граница «не более ↔ менее» (`cashback.range_boundary.cap_strict`) не поймана никем.

## Инструменты (всё — `python -m evaluation.v2.<модуль>`)

| Команда | Что делает |
| :--- | :--- |
| `gate [--run runs/<id>] [--save]` | ворота WAVE2 по последним замерам, владельцы красного; `GATE.md` |
| `round --name "замер 07:00" [--official sonnet haiku opus] [--no-cache]` | весь замер параллельно: официальный, корпус, новые ТЗ, стабильность, ворота |
| `measure --label … --model sonnet [--no-cache]` | один прогон официального с оценкой и историей |
| `corpus run --out DIR --model haiku --label … --save` | корпус, строгий счёт, ложные по источникам, recall кандидатов |
| `newtz list` / `newtz run --out DIR --model sonnet --label … --save` | новые ТЗ №18 (`evaluation/v2/open2`), чистые версии, вставка для модели |
| `aggregate stability s1 s2 s3 --json …` / `aggregate models a=s1 b=s2` | стабильность (3/3, 2/3, 1/3, разброс), сравнение моделей |
| `score report.json [--run-dir runs/<id>] [--lens qa]` | разбор одного отчёта или ответа линзы |
