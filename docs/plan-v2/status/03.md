## Сделано

* `src/bcc_review/v2/docview.py` — `load(path) -> DocView` поверх `bcc_review.engine.read_document` (MD/TXT/PDF/DOCX),
  HTML — через `readers_html` (в работе). Также `numbered(view, start, end)`, `line(view, n)`, `text_of`, `section_of`,
  `page_of`, `place(view, a, b)` («строки 38–40», для PDF «с. 2, строка 25»), `nonempty`, `summary(view)` (паспорт для
  `report.json`), `from_text(text)` (DocView из строки — для тестов и веб-демо).
* `src/bcc_review/v2/quotes.py` — `verify_quote(view, quote, line_hint=None, near_lines=())` по CONTRACT, раздел 7;
  `verify_candidates(view, candidates, requirements)` → `{"candidates", "rejected", "stats"}`;
  `verify_evidence(view, ev, near)`; `verify_requirements(view, requirements)` (уточняет строки нарезки по цитатам);
  `normalize(s)`.
* Фикстура `tests/v2/fixtures/03_reference_quotes.json` — 85 дословных цитат эталона К1–К5, С1–С20 и мелких
  (`docs/task-analysis.md`, раздел 5) с номерами строк `release/input/requirements.md`. Можно брать №15 для счётчика.
* `src/bcc_review/v2/readers_html.py` — HTML на входе (`html.parser`): заголовки, абзацы, списки (с номерами у `ol`),
  таблицы (« | »), `pre` построчно, `br`; скрипты/стили/`nav` пропускаются; `src_line` — строка HTML-файла; кодировка
  из `meta charset` (cp1251 тоже). `docview.load('x.html')` работает.
* `src/bcc_review/v2/render/exports.py` — экспорт для банка, одна точка вызова
  `exports.export(report, view, input_path, out_base, formats=("jira","docx","pdf"), markdown=None) -> [результат]`:
  * **Jira CSV** `<out>.jira.csv` — строка на дефект: Summary `[D-01] заголовок`, Description (разметка Jira: проблема,
    места с цитатами «…» — раздел, страница, строка; сценарий; последствия; что сделать; формулировка; вопрос с
    вариантами; критерий и стандарт; требования), Issue Type `Task`, Priority critical→Highest, major→High,
    minor→Low, Labels (`bcc-review severity-… criterion-… kind-… blocks-… fix-first`). UTF-8 с BOM, RFC 4180.
  * **DOCX**: вход DOCX → `<out>.annotated.docx` — копия с комментариями Word на местах цитат + сводный комментарий
    (проверенный v1 `exports/word.annotate_docx` через адаптер координат `to_v1_report`); другой вход →
    `<out>.docx` — Word-версия отчёта (из Markdown-отчёта №13, если передан `markdown=`, иначе из `report`).
  * **PDF**: вход PDF → `<out>.annotated.pdf` — копия с выделениями цитат цветом серьёзности и всплывающими
    примечаниями (PyMuPDF `search_for` в рамке блока → `add_highlight_annot`), сводная заметка на с. 1; вход MD/TXT →
    `<out>.pdf` — производная PDF-версия документа с выделениями (v1 `exports/pdf`).
  * Экспорт не роняет прогон: каждый формат → `{"format", "status": written|skipped|failed, "path", "message"}`.
* CLI для отладки: `python -m bcc_review.v2.docview ФАЙЛ [--from N --to M] [--json]` — нумерованный вид;
  `python -m bcc_review.v2.quotes ФАЙЛ "цитата" --line N` и `--candidates ответ.json --requirements segment.json` —
  сверить все цитаты ответа линзы. Сверка снимает префиксы «L038| » и «[с.2] », если модель их скопировала.

## Решения (в рамках контракта)

* **Нумерация PDF/DOCX** — строка на строку текста блока читателя v1 (как `try_prompt.load_lines`), поэтому фикстура
  `tests/v2/fixtures/official_pdf/segment.json` остаётся верной, перегенерировать не нужно.
* **MD/TXT**: строка = строка файла; текст из блоков v1 (снята разметка); ограждения кода, `---`, разделители и пустые
  строки таблиц — пустые строки. Нумерованные пункты сохраняют номер («5. При отклонении…»), маркеры `* `/`- ` сняты.
* `section` — путь заголовков через « › » без заголовка документа (корня): «Часть A. Новый функционал › Требования к
  изменениям › Функциональные требования». Для строки-заголовка раздел включает сам заголовок.
* `src_line` для PDF/DOCX — `None` (строки исходного файла нет); `page` для DOCX — `None`.
* Нормализация цитат дополнительно к контракту: ё → е, пробел внутри числа («4 000» = «4000»), снятие обрамляющих
  кавычек и точек, ведущих `* # | -`; вхождение по границам слов предпочтительнее куска слова («Prod: —» не находит
  «Product»); цитата с «…» внутри ищется по частям в пределах 3 строк (`normalized`).
* `verified=exact` — цитата дословно есть в строке view. В доказательство всегда пишется `quote` = дословный текст
  документа (без префиксов «L038|», обрамляющих кавычек, «…»): `verify` №13 проверяет его подстрокой строк. Для цитаты
  с «…» внутри — сплошной отрезок документа от первой части до последней.
* У строки `Line` есть `kind` (вид блока: `heading|paragraph|list_item|table_header|table_row|code`, пусто у пустой
  строки), `level` (уровень заголовка, иначе 0) и `heading` (bool) — CONTRACT, раздел 9; их читают №04 и №14.
* `verify_candidates`: у оставленного кандидата доказательства `missing` убираются, на кандидате ставятся
  `line_start/line_end/page/section` первого найденного доказательства; дубли доказательств (та же строка и текст)
  схлопываются; кандидат без найденных цитат → `rejected` (весь кандидат + `reason: "цитата не найдена"`).
* `bcc_review/v2/__init__.py` не создаю (файл №01): до каркаса пакет работает как namespace-пакет.
