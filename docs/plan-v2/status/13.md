Ветка: `v2/13-report` (рабочая сессионная ветка `claude/epic-cerf-wp9k86` — тот же коммит).

## Сделано

* `contracts/v2.json` — JSON Schema report.json (CONTRACT 2.6): обязательные поля, перечисления severity/blocks/
  verified/статусов, `critical ⇒ blocks ≠ none`; необязательные `run.stage_stats`, `clarification` (№11), `rewrites`,
  `revised_file`, `title`/`signals`/`not_checked` (офлайн №12), `checklist_source` (№10), `topic`/`evidence` вопросов,
  `finding.status_after_answers`, `rule_conflict`; вердикт `no|conditional|yes|undetermined|none`. Лишние поля разрешены.
* `src/bcc_review/v2/render/jsonout.py` — `finalize(report)` (summary и вердикт считает код), `compute_summary`,
  `rule_verdict` (правило CONTRACT 5; для `provider=offline` — `no` только при блокирующем critical или `rule_conflict`,
  иначе `undetermined`), `validate`, `write(report, path, strict=False)` — схема проверяется при записи.
* `src/bcc_review/v2/render/markdown.py` — `render(report, max_lines=900)` / `write(report, path)`: «Кратко» (вердикт,
  числа, блокеры, «исправить первым», «до/после ответов», навигация), разделы 1–6, приложения А–Е; сжатие при > 900
  строк; рендер не падает на неполных данных (очистка типов, изоляция разделов, фазз-тест); в тексте нет английских
  слов вне `кода` и «кавычек» — проверено счётчиком №15.
* `src/bcc_review/v2/render/console.py` — `summary(report, md_path=, json_path=)`: 4–8 строк в терминал.
* `src/bcc_review/v2/verify.py` — `verify_report(report, source)` и `main(argv)`; код 0 / 4; цитаты на своих строках,
  страница PDF, SHA, счётчики, ссылки D-/R-/Q-, вердикт по правилу, коммит.
* `tests/v2/fixtures/13_report_sample.json` — отчёт по эталону (К1–К5, С1–С20, 7 незначительных, 67 цитат); сборщик
  `13_build_sample.py`, отрисовка `13_report_sample.md`.
* Тесты `tests/v2/test_13_report.py`, `tests/v2/test_13_verify.py` — 44 зелёных (+1 PDF, пропускается без `docview`).
* Текст модели: «L038» → «строка 38» с падежом после предлога; варианты ответа — списком A, B, C.
* Проверено на чужих данных: фикстура №14 `14_report_official.json` — схема OK, 638 строк; офлайн-отчёт №12
  (`rules/offline.build`) на официальном документе — рисуется, 372 строки.

## API для конвейера (№01)

```python
from bcc_review.v2.render import jsonout, markdown, console
jsonout.finalize(report)                      # summary; verdict — если конвейер его не поставил
jsonout.write(report, out.with_suffix(".json"))
markdown.write(report, out)                   # out — путь .md из командной строки
print(console.summary(report, md_path=str(out), json_path=str(out.with_suffix(".json"))))
```

## Просьбы

* **№01**: `python -m bcc_review verify ОТЧЁТ.json ИСХОДНИК` → `bcc_review.v2.verify.main(argv)`, если в JSON
  `"schema": "bcc-review/2"` (иначе — v1). В `run` — `stage_stats{этап: {calls, seconds, candidates}}` (приложение Д).
  Из `judge` класть в отчёт `rejected`, `checklist`, `checklist_source`, `verdict.summary ← verdict_summary`,
  `verdict.fix_first`. Режим `--answers`: `report["clarification"]` = `recheck.apply_answers(...)["clarification"]`,
  `report["findings"]` = `findings_after` (со `status_after_answers`), вердикт — «после».
* **№12 / №01**: в офлайн-отчёте заполнять `run.agent = "BCC Review"`, `run.version`, `run.commit` (сейчас
  «bcc_review», «2», без коммита — схема требует `commit`, verify без него даёт код 4).
* **№10**: `rejected` в вашем формате (`candidate_id`, `reason_code`, `line`) рендер понимает; строку показывает.
* **№11**: `clarification` рисуется как есть: таблица «до/после» на первом экране, ответы — под каждым вопросом
  приложения А, «Что изменили ответы» — там же. Буквы вариантов — A–D. `rewrites`
  `[{"finding_id", "line_start", "line_end", "before", "after"}]` и `revised_file` → приложение Г.
* **№14**: новые поля в отчёте: `clarification`, `finding.status_after_answers`, `signals`, `not_checked`, `title`,
  `checklist_source`; подписи и словари — в `markdown.py` (`READINESS`, `CRITERIA`, `KIND_NAME`, `STAGES`).
* **№15**: в `LATIN_ALLOW` можно не добавлять ничего — шаблон отчёта чистый (имена продуктов в «»).
* **№16**: файлы читаю и пишу с `encoding="utf-8"`; `contracts/v2.json` грузится по пути от пакета — для установки
  не в режиме `-e` нужен `package-data` или копия в пакете (скажите, сделаю копию в `render/`).

## Решения

* Вердикт в `finalize` не перезаписывается, если уже есть; `verify` сверяет его с правилом кода (расхождение — код 4).
* Цитаты нарезки (`requirements[].quote`) `verify` проверяет мягко — предупреждение, не ошибка; цитаты дефектов —
  строго, на указанных строках (`fuzzy` ≥ 0,92 допускается только для помеченных `fuzzy`).
* Номер строки документа для MD/TXT = номер строки файла (`splitlines`), как на GitHub.
* Схема грузится из `contracts/v2.json` (ищется вверх от пакета). Для установки не в режиме `-e` файл нужно положить в
  пакет — решим с №16.
