# №09 — проверка набора требований целиком (consistency)

Ветка: `v2/09-consistency` (рабочая ветка сессии `claude/affectionate-hawking-vnw96d`, каждый push дублируется).

## Сделано

* `src/bcc_review/v2/prompts/consistency.md` — промпт v1: предметы → попарная сверка по сценарию
  (`same_subject` обязателен, догадка о приоритете не даёт `compatible`) → глоссарий → трассировка →
  дефекты набора (цель ↔ требования, обещанное без описания, схемы, полнота, дубли, ранжирование, ID).
* `src/bcc_review/v2/stages/consistency.py` — схема ответа (`SCHEMA`), `run(ctx)`, `postprocess()`:
  * `pair_checks`: `conflict` по одному предмету и двум найденным цитатам в разных строках → critical-кандидат,
    иначе major; `undefined` → major (не больше 4); `same_subject = false` → не сравнивается;
  * `glossary`: `major|minor` → кандидат `terminology`; `none` — без кандидата;
  * кандидаты модели, повторяющие конфликт пары, отбрасываются; critical без сценария → major;
  * `trace`: только известные ID, `verified_by` — только строки приёмки; недостающие требования дополняются;
  * `coverage(trace)`, `coverage_table_md(trace, requirements)` — матрица покрытия для отчёта №13.
* `tests/v2/test_09_consistency.py` — 24 теста на синтетических ответах.

## Как проверить

```bash
PYTHONPATH=src python -m pytest tests/v2/test_09_consistency.py -q
```
