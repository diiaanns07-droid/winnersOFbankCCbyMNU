## Сделано

* `src/bcc_review/v2/prompts/consistency.md` — промпт: предметы → попарная сверка по сценарию → глоссарий →
  трассировка → дефекты набора. Ключевые правила (без слов официального документа):
  * `same_subject` обязателен: разные параметры (два диапазона) не сравниваются;
  * «догадка о приоритете — не основание для compatible», но «общее правило + ограничение совместимы»,
    конфликт — только если второе место снимает ограничение («независимо от», «без ограничения»…) или требует
    противоположного; «молчание — не противоположное правило» (это `undefined/incomplete`);
  * срок вступления в силу ↔ поведение в состоянии — совместимы; цель в попарную сверку не входит.
* `src/bcc_review/v2/stages/consistency.py`:
  * `SCHEMA` ответа модели: `subjects`, `pair_checks`, `glossary`, `trace`, `candidates`;
  * `pair_checks`: `conflict` + `same_subject` + две найденные цитаты в разных строках → **critical**;
    одна цитата, или сторона — цель/НФТ, или `unit_mismatch` → major; `undefined` → major (не больше 3);
    конфликты одного вида с общей строкой склеиваются в одно замечание;
  * `glossary`: `major` → отдельный кандидат `terminology`; все `minor` → **одно** замечание на документ;
    термин в другом падеже ищется по основам слов и цитируется так, как он стоит в строке;
  * кандидаты модели: не больше 8, повтор конфликта пары отбрасывается, critical без сценария → major;
  * `trace`: только известные ID, `verified_by` — только строки приёмки; пропущенные требования дополняются;
    `coverage(trace)` и `coverage_table_md(trace, requirements)` — матрица покрытия для отчёта.
* Пара содержит `basis` (`same_condition|limit_removed|value_mismatch|none`): `conflict` без основания код переводит
  в `undefined` — так отсекаются псевдоконфликты слабых моделей («общий код 200 ↔ частная ошибка 404»).
* Тесты: `tests/v2/test_09_consistency.py` (37, синтетика), `tests/v2/test_09_recorded.py` (6, записанные ответы
  haiku/sonnet: cardblock days=30 — один конфликт, autopay.base — ноль, официальный документ — К2, К4, С16, глоссарий, трассировка).

## Просьбы

* №01: в отчёте колонка «Дефект» у пар (4.2) и глоссария (4.5) пустая — их никто не связывает с D-xx. Готово
  в моём модуле: пары имеют `id` P-xx, понятия — G-xx, кандидаты этапа — `pair_ids`/`glossary_ids`. В `pipeline.review`
  после `self._finish_findings(findings)` одна строка:
  `from .stages import consistency; consistency.link_findings(extras["pair_checks"], extras["glossary"], kept, findings)`
  (`kept` — кандидаты с C-id после сверки цитат). Тест: `test_link_findings_maps_pairs_and_glossary_to_final_defects`.

* №02: `claude_cli` относит ошибку `API Error: Claude's response exceeded the 16000 output token maximum` к `unknown`.
  Нужно `stop_reason = max_tokens` → `llm.Truncated`, иначе не работают `ask_split` и повтор в кратком режиме.
* №01: в `origin/bcc/v2` (09f0dfb) красные 3 теста не №09: `test_06_lens_qa.py::test_clean_bases_have_no_conflicts`
  (autopay.base, cardblock.base) и `test_11_recheck.py::test_apply_answers_changes_verdict`.

* №13: матрица покрытия — `consistency.coverage_table_md(trace, requirements)` и `coverage(trace)`.
  У кандидатов этапа есть поле `origin` (`pair_check|glossary|model`) — можно не показывать.
* №01: этап возвращает дополнительный ключ `subjects` (разбор предметов) — в отчёт не нужен.
  Этапу нужен `ctx.prompt("consistency")` без дополнительных переменных.
* №10 (судья): critical из `pair_check` всегда имеет две найденные цитаты в разных строках и одинаковый
  предмет; `unit_mismatch` и пары с целью/НФТ приходят как major намеренно — поднимайте сами, если нужно.
