Ни одного падения и ни одного ложного «можно». Провайдер отдельно (настоящий HTTP): 429 ждёт ровно Retry-After
из заголовка; 429 дольше 65 с → запасная модель; 503/500/504/обрыв/обрезанный JSON/пусто — повтор на той же модели;
стойкий отказ → следующая модель (503 — 4 попытки, пусто/обрезка — 2, 404/квота — 1); тайм-аут клиента — повтор;
блок, MAX_TOKENS, неверный ключ — сразу наверх одним запросом (не тратим 20 суточных); нет сети — 3 запроса и стоп.
**`--rpm`:** 5 параллельных этапов при окне 2 запроса — на сервер не больше 2 за окно (фактический темп по журналу
сервера). На прогоне по умолчанию окно Flash 5/мин: 9 запросов, шестой ждёт окно (~60 с), 429 нет.

Ход по журналу сервера: нарезка — 0 с; набор и 3 линзы — 7,9 с (окно 5/мин заполнено); линза рисков ждала окно

вторая проверка — 271 с; конец — 289 с. **Критический путь = старт 8 + набор 110 + судья 153 + проверка 17 = 288 с:
провайдер и окно 5/мин времени не добавляют**, дальше время — скорость модели на наборе и судье. Цель ≤ 6 мин
выполняется при скорости haiku. Риск: кто из рецензентов ждёт окно, решает гонка потоков; если выпадет архитектору
(96 с) — путь +38 с (≈ 5 мин 27 с), всё равно ≤ 6 мин. Сравнить время с ERA216 и SoloHive честно нельзя: в
