## Политика нарезки (решения №04)

* Одно требование — один пункт, одна строка таблицы параметров/статусов/критериев или один абзац с обязательством;
  пункт с несколькими обязательствами не дробится (атомарность — линзы).
* Таблица общих параметров метода (назначение, тип, URL, авторизация, CURL, Swagger, автор…) — **одно** требование
  на метод: так у официального документа 40, а не 44 требования, и замечания про GET/URL/Swagger ссылаются на одно R.
* Код ответа — одно требование; если код описан в перечне и в отдельном блоке с примером, требование — на строке
  перечня, блок с примером — в `excluded` («пример тела к коду N»). Пример, который единственное описание
  ответа метода, — требование.
* Термины глоссария — по одному требованию на термин (`kind = other`).
* `source_id`: собственный ID пункта; «<раздел>, п. N»; «<таблица>: <параметр>»; «<таблица>, строка N»;
  «Статус <код>»; для таблицы общих параметров — название раздела; у абзаца без номера — пусто.

## Цифры

* Стабильность, официальный MD, sonnet, 4 прогона: 40/40/40/40 требований, одинаковые диапазоны строк;
  расхождения — только `source_id` одной записи на прогон («Схема» vs пусто, «Общие параметры» vs «Метод …»,
  147 vs 147–148) — правила в промпте уточнены. PDF, 2 прогона: 40/40, тот же набор `source_id`, что у MD.
* Haiku, официальный MD: 40 требований, набор (source_id, строки) совпадает с sonnet 1:1, схема не ломается; 96 с.
* Время одного вызова sonnet: 50 с (официальный), 20–35 с (корпус); ≈ $0,12 за вызов.

## Просьбы

* №01 (mock): фикстура `segment.json` содержит поля `id` и `page`, которых нет в схеме ответа модели
  (`additionalProperties: false`). Если mock-провайдер отдаёт её как ответ модели этапа `segment` и `llm.ask`
  валидирует его — либо не валидировать ответы mock, либо отбрасывать лишние поля перед проверкой.
  Этап сам игнорирует `id`/`page` из ответа и пересчитывает их.
* №01 (`ctx`): этап использует `ctx.view`, `ctx.llm.ask`, `ctx.llm.ask_split` (если есть; `merge` получает
  список ответов), `ctx.prompt("segment")` только ради `system`; предупреждения — `ctx.warn(msg)` или
  `ctx.warnings.append`. Возвращает `requirements`, `excluded` и служебный `coverage`.
* №03 (docview): для распознавания заголовков удобно поле строки `heading: true` (или `level`). Сейчас этап
  узнаёт заголовок по «#» в исходном MD или по совпадению текста с последним элементом `section`; для PDF —
  по короткой строке без точки.
