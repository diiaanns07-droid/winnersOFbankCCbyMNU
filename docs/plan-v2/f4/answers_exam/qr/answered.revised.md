### Цели
Клиент получает перевод от другого клиента банка, показав QR-код на экране телефона, без диктовки номера карты или телефона. Снизить число переводов по ошибочным реквизитам.

### Архитектура решения
Приложение получателя → сервис QR-кодов. Приложение отправителя → сервис QR-кодов → сервис переводов → антифрод. Сервис переводов → сервис уведомлений.

### Дизайн процесса UI
Получатель: Платежи → «Получить по QR» → выбор карты зачисления, необязательное поле «Сумма, ₸» и кнопка «Создать QR». QR-код показывается с таймером обратного отсчёта и кнопкой «Отменить».
Отправитель: Платежи → «Сканировать QR» → экран подтверждения с маскированным именем получателя («Айгерим С.»), суммой, картой списания, надписью «Без комиссии» и кнопкой «Перевести». Если сумма задана в QR-коде, изменить её нельзя.

### Требования к изменениям

#### BPMN схема процесса
Создание QR-кода получателем → сканирование отправителем → проверка QR-кода → подтверждение отправителем → проверка антифродом → списание и зачисление → push получателю и отправителю → завершение.

#### Функциональные требования
* **Ф-1.** Получатель — клиент банка с активной картой KZT. QR-код создаётся без суммы или с суммой от 100 до 500 000 ₸ включительно; сумма — целое число тенге.
* **Ф-2.** QR-код с суммой действует 15 минут с момента создания, QR-код без суммы — до 23:59:59 дня создания по времени Астаны (UTC+5). QR-код с суммой можно оплатить один раз, QR-код без суммы — несколько раз в течение срока действия. [изменено: D-01]
* **Ф-3.** Перед подтверждением отправитель видит маскированное имя получателя, сумму и надпись «Без комиссии». Для QR-кода без суммы отправитель вводит сумму от 100 до 500 000 ₸.
* **Ф-4.** Комиссия за перевод по QR-коду не взимается.
* **Ф-5.** Получатель может отменить неоплаченный QR-код. После отмены или истечения срока действия при сканировании показывается «QR-код недействителен».
* **Ф-6.** После зачисления получатель и отправитель получают push с суммой перевода и маскированным именем второй стороны.

### Требования к данным
QR-код содержит только идентификатор QR-кода и сумму, если она задана. Карту зачисления сервис QR-кодов определяет по идентификатору QR-кода. Хранить идентификатор QR-кода, идентификатор клиента-получателя, карту зачисления, сумму в тенге, время создания, срок действия (для QR-кода с суммой — ttl в минутах, для QR-кода без суммы — 23:59:59 дня создания по времени Астаны), статус (активен, оплачен, отменён, истёк) идентификаторы переводов, идентификатор клиента-отправителя, карту списания, requestId и результат первого запроса; requestId и результат хранятся 48 часов с первого запроса. [изменено: D-05, D-07, D-11]

### Требования к интеграции
Приложения создают QR-код, получают данные QR-кода перед подтверждением и выполняют перевод через дочерний документ «Перевод по QR-коду — REST API». Повторный запрос перевода с тем же `requestId` не создаёт второй перевод.

### Логика работы метода
1. Проверить сессию отправителя.
2. Проверить, что карта списания принадлежит плательщику, активна и открыта в тенге. Иначе вернуть 400 с message «Карта недоступна», операцию не создавать. [изменено: D-12]
3. Найти QR-код по `qrId`. Если QR-код не найден, вернуть 404.
4. Проверить срок действия: для QR-кода с суммой текущее время не позже времени создания QR-кода + ttl минут, для QR-кода без суммы текущее время не позже 23:59:59 дня создания по времени Астаны (UTC+5). Если срок истёк, вернуть 410 с message «Срок действия QR-кода истёк». Если QR-код отменён, вернуть 410 с message «QR-код отменён». [изменено: D-01]
5. Если в QR-коде задана сумма, использовать её, а поле `amount` запроса не учитывать. Если суммы нет, проверить amount: от 100 до 500 000 ₸. Если amount вне диапазона, вернуть 400 с message «Проверьте сумму», операцию не создавать. [изменено: D-12]
6. Проверить, что QR-код с суммой ещё не оплачен. Если он оплачен, вернуть <уточнить: код ответа и message для оплаченного QR-кода>. [изменено: D-09]
7. Передать операцию в антифрод. При окончательном отказе антифрода вернуть <уточнить: код ответа — 422 или 403> с message, деньги не списывать. [изменено: D-13]
8. Выполнить списание и зачисление и вернуть результат. На время обработки QR-код с суммой резервируется (признак резерва, статус остаётся «активен»), параллельный запрос с другим requestId получает тот же ответ, что и для оплаченного QR-кода. QR-код с суммой получает статус «оплачен» после успешного зачисления. При отказе антифрода или сбое списания либо зачисления QR-код остаётся «активен». [изменено: D-06]

### Особые правила
1. QR-код без суммы действует до 23:59:59 дня создания по времени Астаны (UTC+5). [изменено: D-01]
2. Повторный запрос с тем же `requestId` возвращает результат первого запроса.
