# Экзамен ответов владельца

Участник запускает обычную команду проверки требований. На каждый вход приходится один исходный отчёт с вопросами, один полный запуск с ответами и один независимый запуск на полученной редакции. Только для первого шага по двум открытым ТЗ использованы опубликованные отчёты. Их входы проверены командой `verify`.

| ТЗ | Исходник | Вопросы, увиденные владельцем | Ответы владельца |
| --- | --- | --- | --- |
| Уведомления о расходах | [ТЗ](../../../../release/input/requirements.md) | [Отчёт](../../../../evaluation/v2/measurements/zamer_08_30_6d03683_sonnet/report.md) · [JSON](../../../../evaluation/v2/measurements/zamer_08_30_6d03683_sonnet/report.json) | [Ответы](official/answers.md) |
| Перевод через QR | [ТЗ](../../../../evaluation/v2/open2/qr/source.md) | [Отчёт](../../../../evaluation/v2/open2/results/sonnet_0820/qr.md.md) · [JSON](../../../../evaluation/v2/open2/results/sonnet_0820/qr.md.json) | [Ответы](qr/answers.md) |
| Изменение дня платежа по автокредиту | [ТЗ](car-loan/source.md) | [Первый отчёт](car-loan/baseline.md) · [JSON](car-loan/baseline.json) | [Ответы](car-loan/answers.md) |

В первых двух файлах по десять адресных реплик и по одному общему решению. У исходного отчёта по уведомлениям модель `claude-sonnet-5-5`, код `e2f2cba`, девять вызовов. У отчёта QR та же модель, код `2cd7a28`, семь ответов из кэша и два вызова, паспорт отмечает изменения в рабочей копии. Эти отчёты задают формулировки и порядок вариантов, которые видел владелец.

По автокредиту тот же Sonnet на `9bd5954` задал восемь вопросов за десять вызовов без кэша. Владелец дал девять адресных реплик и два общих решения. Всего в экзамене 33 реплики, из них 29 адресных и четыре общих решения. Входы и вопросы открыты команде по мере подготовки. Предварительные ключи остаются у F4 до фиксации результатов.

## Запуск

Команды PowerShell выполняются из рабочей копии кода проверки. Переменная `$exam` указывает на каталог этой ветки F4. Для сравнимой серии используйте один коммит и одну фактическую модель, проверьте их в JSON каждого прогона. В первой серии с ответами выбран код `9bd5954`. Путь к исполняемому файлу Claude должен находиться в PATH.

```powershell
$env:PYTHONUTF8 = '1'
$env:CLAUDE_CLI_FALLBACK_MODEL = 'off'
$env:PYTHONPATH = (Resolve-Path 'src').Path
$exam = (Resolve-Path '../f4-team-20261127/docs/plan-v2/f4/answers_exam').Path
$opt = @('--provider', 'claude_cli', '--model', 'sonnet', '--no-cache', '--no-html')
python -m bcc_review "$exam/car-loan/source.md" out/f4-exam/car-loan/baseline.md @opt
```

Для каждого документа с готовым файлом ответов выполнить оба шага. Здесь приведены команды для QR. Для уведомлений подставьте `release/input/requirements.md` и `official`, для автокредита — `"$exam/car-loan/source.md"` и `car-loan`. Для другого размещения рабочих копий задайте абсолютный путь к каталогу экзамена в `$exam`.

```powershell
python -m bcc_review evaluation/v2/open2/qr/source.md out/f4-exam/qr/answered.md --answers "$exam/qr/answers.md" --revise @opt
python -m bcc_review verify out/f4-exam/qr/answered.json evaluation/v2/open2/qr/source.md
python -m bcc_review out/f4-exam/qr/answered.revised.md out/f4-exam/qr/reread.md @opt
python -m bcc_review verify out/f4-exam/qr/reread.json out/f4-exam/qr/answered.revised.md
```

Сохраните отчёты MD/JSON, исправленный текст и данные этапов пересмотра и правки. По паспорту проверяются фактическая модель, статус и ошибки. Если сервис вернул неполный результат, зафиксируйте причину отдельно и запустите новый прогон под другим именем. До фиксации отчётов участнику передаются только входные файлы.

## Как выставляется счёт

Единица общего счёта — исходная реплика, включая по одной единице на каждую из двух реплик спорящих адресатов и одну на каждое общее решение. Реплика получает один балл, если сохранён её смысл, она отнесена к нужному вопросу и результаты по всем затронутым причинам совпали с предварительным ключом. Номера карточек пересматриваются по смыслу и по ссылкам на исходный текст. У варианта-буквы смысл задаёт список, показанный владельцу. Если нужная тема выпала при повторной генерации, записывается «не привязан». Для решения вне вопросов связь с Q неприменима. Его зачёт требует отражения в исправленном ТЗ.

Отдельно считаются привязки, исходы по уникальным причинам, конфликты между адресатами (один эпизод на пару), новые противоречия с другим пунктом, вердикты по двум направлениям и соответствие исправленной редакции решениям. Для зачёта конфликта между адресатами нужны обе реплики, отметка `conflicting_answers` и открытый дефект. Для нового противоречия проверяются обе стороны и финальная карточка после судьи. Попадание только в кандидаты указывается отдельно. Юридические нормы, догадки о предпочтениях клиента и подсказки из чужих эталонов при оценке не используются.

При чтении исправленного текста сверяются исходные строки, обе стороны конфликта, сохранность оговорок, пометки об изменении и вопросы владельцу. Проверяется каждое новое число, обещание и условие, в том числе в приложениях к редакции. В повторном отчёте отличаем новую ложную тревогу от настоящей ошибки, внесённой правкой. Полнота и качество редакции показываются отдельно от балла за реплику, кроме общего решения, которое можно наблюдать только в тексте.

Для сопоставления с внешним счётом дополнительно приводится результат только по адресным репликам. Знаменатели, документы, сложность и способ зачёта у команд различаются. Незавершённый прогон обозначается как отсутствующее измерение.
