#### <a id="d-01"></a>🟠 D-01. Нет метода чтения договора: день, редакция, график и проценты «до»

- Действия клиента, п. 3, строка 67: «Приложение показывает действующий день и предлагает выбрать новое число»
- Действия клиента, п. 5, строка 69: «5. Клиент видит обе даты каждого взноса и суммы процентов до и после изменения»
- М-1, строка 83: «принимает целое поле day и текущую редакцию baseRevision»
- М-1, строка 86: «В ответе 200 возвращаются previewId, baseRevision, expiresAt и installments со строками по Г-4»
- О-2, строка 167: «владелец читает актуальный график через этот экран сразу после подтверждения»

**Проблема.** Приложение должно показать действующий день (строка 67) и проценты «до» (строка 69) и передать `baseRevision` (строка 83). Ответ М-1 даёт только новый график (строка 86), метод чтения экрана договора (О-2, строка 167) не описан.  
**Сценарий.** Клиент открывает карточку договора, выбирает 18-е: `baseRevision`, текущий день и старые проценты взять неоткуда. Сравнение «до и после» не собрать, М-1 не вызвать.  
**Последствия.** Расчёт нельзя вызвать, график после подтверждения не показать; реализация и тесты блокируются.  
**Как исправить.** Описать GET договора: текущий день, редакция, строки графика, поля и ошибки.

#### <a id="d-02"></a>🟠 D-02. Исход подтверждения при просрочке от 1 000 ₸ оставлен заглушкой

**<a id="q-01"></a>Q-01** Метод чтения договора для экрана · можно ответить позже · кому: Архитектор · к [D-01](#d-01)  
Приложению нужно показать действующий день платежа, текущую редакцию и график до расчёта и после подтверждения. Какой метод это отдаёт?  
Где: Действия клиента, п. 3, строка 67: «Приложение показывает действующий день и предлагает выбрать новое число.»; М-1, строка 83: «принимает целое поле day и текущую редакцию baseRevision»; О-2, строка 167: «владелец читает актуальный график через этот экран сразу после подтверждения»

- **A** Отдельный метод чтения договора по образцу описанных методов: возвращает действующий день, текущую редакцию и строки графика (договорная дата, дата списания, основной долг, проценты)
- **B** Действующий день и текущую редакцию отдаёт существующий экран договора вне этого документа; требования ссылаются на его контракт, график читается тем же методом
- **C** Действующий день и редакция возвращаются в ответе расчёта, график — отдельным методом чтения графика

Зачем: Без метода приложение не узнает `baseRevision`, и расчёт нельзя вызвать. Команды приложения и сервера реализуют контракт по-разному.

- **B** Приложение берёт проценты до изменения из метода чтения текущего графика

**<a id="q-03"></a>Q-03** Код отказа проигравшему подтверждению · можно ответить позже · кому: Аналитик · к [D-03](#d-03)  
Какой код вернуть второму подтверждению по тому же предложению с новым ключом, если первое уже сменило день? Порядок проверок даёт отказ по лимиту, а правило гонки — смену редакции.  
Где: М-2, строка 101: «Только первое успешное подтверждение заменяет редакцию, остальные получают…»; М-2, строка 94: «интервал Д-3, право по Д-4, срок предложения, актуальность baseRevision»

- **A** `REVISION_CHANGED`: актуальность редакции проверяется раньше лимита смен, порядок проверок меняется
- **B** `CHANGE_LIMIT`: порядок проверок сохраняется, правило гонки уточняется как относящееся только к подтверждениям, не прошедшим лимит
- **C** `REVISION_CHANGED` только для подтверждений, одновременных с успешным; позже зафиксированной смены возвращается `CHANGE_LIMIT`

Зачем: Один и тот же вход даёт два кода, тест приёмки гонки нельзя написать.

**<a id="q-04"></a>Q-04** Единица и тип денежных полей · можно ответить позже · кому: Архитектор · к [D-05](#d-05), [D-06](#d-06)  
В каких единицах и типе сервис передаёт суммы (просрочка, основной долг, проценты) и как сравнивать просрочку с порогом 1 000 ₸?  
Где: Д-5, строка 42: «Кредитный учёт сообщает сумму просрочки в тиынах и время её определения»; М-2, строка 95: «Если просрочка, впервые возникшая после расчёта предложения, меньше 1 000 ₸, предложение…»; Термины, строка 29: «Денежные поля ответа сервиса передаются в единице и типе <уточнить: тиыны (целое число)…»

- **A** Все денежные поля — целое число тиынов; порог 1 000 ₸ = 100000 тиынов, сравнение в тиынах
- **B** Все денежные поля — десятичное число тенге с двумя знаками; просрочку из учёта пересчитывают в тенге до сравнения с порогом
- **C** Денежные поля ответа — строка тенге с двумя знаками; внутри учёта тиыны, порог 100000 тиынов

Зачем: Без выбора просрочка 99 999 или 100 000 тиынов даст разный исход, а приложение покажет суммы в 100 раз неверно.

## <a id="pe"></a>Приложение Е. Методика

Статическое ревью текста до разработки: программа не запускается. Документ нумеруется построчно; проверяющие роли (аналитик, тестировщик, архитектор, риски, набор целиком) предлагают кандидатов с дословными цитатами; программа находит каждую цитату в документе и сама определяет строку; судья объединяет дубли, отклоняет ложные и калибрует серьёзность; вердикт считает программа.

**Шкала серьёзности**

- 🔴 **Критичный** — два места документа дают несовместимый результат для одного входа; ключевое правило нельзя однозначно реализовать или проверить; нет информации, без которой основную функцию не реализовать.
- 🟠 **Существенный** — неоднозначность или неполнота, ведущая к неверной реализации или спору при приёмке; непокрытая ветка (ошибки, повторы, отмены, границы); риск ИБ; расхождение типов, единиц, терминов.
- 🟡 **Незначительный** — оформление, незаполненный шаблон, версия и согласования, отсутствие ID и приоритетов, стиль.

**Вердикт.** Критичный дефект, блокирующий разработку, — разработку начинать нельзя; то же для тестирования. Иначе при трёх и более существенных дефектах по направлению — «можно с условиями»: начинать части, не затронутые дефектами, и исправлять их параллельно. Иначе — «можно». Частичный прогон не даёт «можно»: в лучшем случае «с условиями».

**Сверка цитат.** Сравнение без учёта регистра, вида кавычек и тире, лишних пробелов и разметки; цитата ищется у указанной строки, затем во всём документе, ближе к требованию. Нечёткое совпадение (не ниже 92 %) допускается только рядом с указанной строкой.
