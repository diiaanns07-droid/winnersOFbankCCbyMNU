# Предварительный эталон ответов по уведомлениям

Вопросы и номера D взяты из исходного отчёта [Sonnet](../../../../evaluation/v2/measurements/zamer_08_30_6d03683_sonnet/report.json). Ссылки на строки относятся к [официальному ТЗ](../../../../release/input/requirements.md). Если номера в новом отчёте изменились, соответствие устанавливается по вопросу, условию и последствиям. Обозначения O01–O11 соответствуют порядку реплик в файле ответов, включая общее решение.

| Реплика и тип | Вопрос и причина в первом отчёте | Ожидаемый исход | Что проверить в исправленном ТЗ |
| --- | --- | --- | --- |
| O01, прямой ответ | Q-01, D-01, отнесение к месяцу | resolved | В Ф-2, стр. 38, выбрать дату проведения по Алматы. Пример на стр. 64 оставляет февраль. Месяц возврата совпадает с месяцем учёта исходной покупки. Не выбирать событие процессинга за владельца. |
| O02, конфликт адресатов | Q-02, D-02, повторный push | open, conflicting_answers вместе с O03 | Стр. 39–40 оставить на согласование. Для одной карты после уже доставленного push и повышения порога одна реплика запрещает второй push. Недостаточно написать о двух получателях уведомления. |
| O03, конфликт адресатов | Q-02, D-02 | open, conflicting_answers вместе с O02 | Те же карта, месяц, переход и доставка. Вторая реплика требует послать второй push. Не выбирать ни один из вариантов и не вводить исключение для одного канала. |
| O04, нет ответа | Q-03, D-03, авторизация или клиринг | open | В стр. 23, 38, 43, 46 не закреплять событие, сохранить запрос уточнения. Дата бухгалтерского учёта из O01 сама по себе не задаёт тип входящего сообщения. |
| O05, буква | Q-04, D-04, отклонение суммы | resolved | «A» в показанном отчёте означает 400, тело с message «Проверьте сумму», прежняя настройка сохраняется. Убрать пример 200/ERROR со стр. 169–172, синхронизировать 121, 163, 178–181. Не унифицировать по этой реплике все другие ошибки API. |
| O06, частичный | Q-05, D-05, обещанное чтение | changed, major | В контрактах после стр. 103 появляется GET /alerts/current с cardId, amount и enabled. Для суммы на экране (29) и её чтения (52) оставить уточнение. Не дописывать источник расходов, currency или числовой пример остатка. |
| O07, числа | Q-06, D-07, тиыны и порог | resolved | На стр. 37, 49, 63 согласовать целочисленное сравнение с порогом ×100. Для 1 234 499 и 1 234 500 результаты разные. Не округлять расходы и не менять допустимые пороги. |
| O08, по смыслу | Написано Q-17, целевой Q-07, D-12, сумма уже достигла нового порога | resolved | Уточнить отдельную ветвь Ф-4 на стр. 40. Первый push сразу при сохранении, если ещё допустим. Эта реплика не разрешает спор адресатов о новом пересечении после уже доставленного push. |
| O09, новое противоречие | Q-08, D-13, сумма сообщения | resolved для исходной причины, требуется новая карточка | Стр. 43 задаёт месячный итог в тенге с двумя знаками. Вторая сторона новой коллизии — Ф-2, стр. 38, «Переводы и снятие наличных исключаются», и приёмка, стр. 65, «Счётчик показывает 19 900 ₸». Для одного исходящего перевода 500 ₸ дан итог 20 400 ₸. Не менять срок хранения событий процессинга и не придумывать способ реализации архива. |

При полном пересмотре ожидается «нельзя» для разработки и для тестирования. До ответов оба вердикта такие же. Основания после ответов — разные решения владельцев по Ф-3/Ф-4 и оставленный открытым выбор события процессинга. В независимом чтении редакции эти же причины продолжают действовать, если редактор честно отразил ответы.
