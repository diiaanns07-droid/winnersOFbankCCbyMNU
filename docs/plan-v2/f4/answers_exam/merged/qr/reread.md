### 3.2. Критичные и существенные дефекты

#### <a id="d-01"></a>🟠 D-01. Код и текст ответа для оплаченного QR-кода не заданы

- критерий приёмки №6, строка 74: «Показан ответ: <уточнить: текст для уже оплаченного QR-кода>»
- Логика работы метода, п. 6, строка 132: «Проверить, что QR-код с суммой ещё не оплачен»
- Часть B › Статусы, строка 179: «Ответ в случае, если QR-код с суммой уже оплачен; текст сообщения: <уточнить: текст ответа для оплаченного QR-кода>»

**Проблема.** Код и текст ответа для уже оплаченного QR (строка 74, строка 179) и параллельного запроса (строка 132) — заглушки «<уточнить…>»; критерий приёмки №6 не имеет проверяемого результата.  
**Сценарий.** QR на 7 000 ₸ оплачен, его сканируют повторно: код и текст не определены, тест не написать.  
**Последствия.** Тестировщик не может обосновать ожидаемый результат требованиями, а разработчик реализует своё толкование: при приёмке возникнет спор, чья трактовка верна.  
**Как исправить.** Дописать в требования правило, из которого следует «Показан ответ: <уточнить: текст для уже оплаченного QR-кода>», или убрать этот исход из критерия приёмки №6.  
**Было → стало (места «<уточнить>» заполнит ответ владельца).** Строка 74: «Показан ответ: <уточнить: текст для уже оплаченного QR-кода>» → «Показан ответ «<уточнить: текст>», метод возвращает <уточнить: код>, перевод не создаётся.»  
**Вопрос владельцу.** Какой код и текст возвращает метод перевода при попытке оплатить уже оплаченный QR-код с суммой (в том числе при параллельном запросе)? → [Q-01](#q-01) (варианты ответа)

#### <a id="d-02"></a>🟠 D-02. Можно ли отменить многоразовый QR-код после первой оплаты

- Ф-2, строка 41: «после каждой оплаты он остаётся активным до отмены или истечения срока»
- Ф-5, строка 44: «Получатель может отменить неоплаченный QR-код»
- Часть A › Требования к данным, строка 55: «статус (активен, оплачен, отменён, истёк)»
- Часть B › Отмена QR-кода [добавлено: D-03], строка 249: «Description | Отмена неоплаченного QR-кода получателем \[добавлено: D-03\]»

**Проблема.** Ф-2 (строка 41) оставляет QR без суммы активным «до отмены», а Ф-5 (строка 44) и метод отмены (строка 249) разрешают отменять только «неоплаченный». Для QR без суммы после оплаты исход отмены не задан.  
**Сценарий.** QR без суммы оплачен на 5 000 ₸, получатель жмёт «Отменить»: по толкованию A отмена отклоняется, по B QR отменён и дальнейшие сканирования недействительны.  
**Последствия.** Разработчики и тестировщики по-разному решат, можно ли получателю закрыть многоразовый QR-код после первой оплаты.  
**Как исправить.** Явно описать для QR-кода без суммы, меняется ли статус после оплаты и разрешена ли отмена после неё.  
**Было → стало.** Строка 44: «Получатель может отменить неоплаченный QR-код» → «Получатель может отменить QR-код с суммой, который ещё не оплачен, и QR-код без суммы в любой момент до истечения срока, в том числе после оплат; статус QR-кода без суммы после оплаты остаётся «активен».»  
**Вопрос владельцу.** Можно ли отменить QR-код без суммы после того, как по нему уже были переводы: да или нет? → [Q-02](#q-02) (варианты ответа)

**<a id="q-01"></a>Q-01** Ответ для уже оплаченного QR · можно ответить позже · кому: Архитектор · к [D-01](#d-01)

- **B** Код 410 с сообщением «QR-код уже оплачен»
- **C** Код 400 с сообщением «QR-код уже оплачен»

Зачем: Код и текст не заданы, критерий приёмки нельзя написать, а команды выберут разные коды.

**<a id="q-02"></a>Q-02** Отмена QR без суммы после оплат · можно ответить позже · кому: Владелец продукта · к [D-02](#d-02)  
QR-код без суммы после первой оплаты остаётся активным, а отменять можно только неоплаченный QR-код. Можно ли получателю отменить QR-код без суммы, по которому уже были переводы?  
Где: Ф-2, строка 41: «после каждой оплаты он остаётся активным до отмены или истечения срока»; Ф-5, строка 44: «Получатель может отменить неоплаченный QR-код»

- **A** Да: QR-код без суммы можно отменить в любой момент до конца срока, пока он в статусе «активен»; прошлые переводы не затрагиваются; для QR-кода с суммой после оплаты отмена возвращает отказ
- **B** Нет: после первой успешной оплаты QR-код без суммы отменить нельзя, он действует до конца календарного дня
- **C** Да, но только если с последней оплаты прошло не менее 1 минуты

Зачем: Без ответа неясно, какой ответ даёт метод отмены и какие тесты писать для QR-кода без суммы после оплаты.

## <a id="pe"></a>Приложение Е. Методика

Статическое ревью текста до разработки: программа не запускается. Документ нумеруется построчно; проверяющие роли (аналитик, тестировщик, архитектор, риски, набор целиком) предлагают кандидатов с дословными цитатами; программа находит каждую цитату в документе и сама определяет строку; судья объединяет дубли, отклоняет ложные и калибрует серьёзность; вердикт считает программа.

**Шкала серьёзности**

- 🔴 **Критичный** — два места документа дают несовместимый результат для одного входа; ключевое правило нельзя однозначно реализовать или проверить; нет информации, без которой основную функцию не реализовать.
- 🟠 **Существенный** — неоднозначность или неполнота, ведущая к неверной реализации или спору при приёмке; непокрытая ветка (ошибки, повторы, отмены, границы); риск ИБ; расхождение типов, единиц, терминов.
- 🟡 **Незначительный** — оформление, незаполненный шаблон, версия и согласования, отсутствие ID и приоритетов, стиль.

**Вердикт.** Критичный дефект, блокирующий разработку, — разработку начинать нельзя; то же для тестирования. Иначе при трёх и более существенных дефектах по направлению — «можно с условиями»: начинать части, не затронутые дефектами, и исправлять их параллельно. Иначе — «можно». Частичный прогон не даёт «можно»: в лучшем случае «с условиями».

**Сверка цитат.** Сравнение без учёта регистра, вида кавычек и тире, лишних пробелов и разметки; цитата ищется у указанной строки, затем во всём документе, ближе к требованию. Нечёткое совпадение (не ниже 92 %) допускается только рядом с указанной строкой.
