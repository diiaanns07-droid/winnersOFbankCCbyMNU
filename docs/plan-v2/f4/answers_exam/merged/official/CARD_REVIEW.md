# Официальное ТЗ до ответов владельца

Проверены 27 исходных карточек одного запуска `claude-sonnet-5-5` на интеграции `2eac95cb`. Взяты поля `findings_before` полного паспорта пересмотра. Они описывают первоначальное ТЗ, до применения ответов. Вопросы понятности здесь относятся к текстовым полям карточек в JSON. Для вёрстки отчёта жюри нужен отдельный просмотр его Markdown. [Паспорт запуска](answered.json) · [Исходное ТЗ с номерами строк](https://github.com/diiaanns07-droid/winnersOFbankCCbyMNU/blob/2eac95cb/release/input/requirements.md) · [Проверка выпуска](../../../final_check.md).

F4 подтвердил причины полностью у 14 карточек и частично у 12. Одну карточку предложено снять. Из 16 исходных major десять сохраняют эту оценку, пять отнесены к minor и одна снята. У пяти critical есть основания для блокировки разработки и приёмки. Например, для одного события на границе месяца ожидаемая сумма зависит от того, читает ли команда Ф-2 или критерий приёмки. Поэтому оба вердикта «нельзя» обоснованы даже при снятии D-20 и исправлении ошибок в шести карточках, переданных №01 до 19:00. Частичное подтверждение означает, что основание есть, но пример, часть вывода или готовая правка выходят за исходный текст. [Список для №01](../../../final_check.md) · [Критерий оценки критичности F4](../../../trust_after.md).

В колонке цитат по порядку указаны количества буквальных совпадений, совпадений после нормализации оформления, приблизительных совпадений и отсутствующих цитат. По всему документу это 54 / 22 / 0 / 0. У числа есть узкое значение. Например, у D-25 цитата подлинная, но её текст прямо задаёт обе границы измерения, которые карточка объявляет отсутствующими. [Доказательства по каждой карточке](answered.json).

Семь отметок следуют порядку WAVE3. Первая оценивает ясность и длину заголовка, вторая — номер исходного требования или шага вместе со строкой, третья — краткое описание проблемы, четвёртая — конкретный вход и два правдоподобных исхода, пятая — участника и последствие, шестая — применимую правку или вопрос с выбором, седьмая — понятную читателю лексику и конкретность. ✓ означает выполнение, × — замечание, · — сценарий с двумя исходами не применялся к этому виду замечания. Служебный номер `R-…` в JSON сам по себе не заменяет номер из ТЗ. У многих строк оригинала собственного номера нет. Пригодный вопрос владельцу может получить зачёт по шестому пункту, даже если предложенный рядом готовый текст требует исправления. [Рубрика WAVE3](https://github.com/diiaanns07-droid/winnersOFbankCCbyMNU/blob/c547df6/docs/plan-v2/WAVE3.md).
