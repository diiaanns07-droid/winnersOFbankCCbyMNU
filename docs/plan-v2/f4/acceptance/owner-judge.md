# Ответ владельца как второй источник при пересмотре

**На сохранённых кандидатах судья принял 0/3 после исправления только фильтра дублей и 3/3 после отдельной передачи ответов владельца.** На трёх отрицательных контролях ложных конфликтов 0/3. Фактическая модель во всех девяти запусках этапа — `claude-sonnet-5-5`. По одному запуску судьи на документ в каждом варианте, без кеша и без переключения модели. Автоматическая перепроверка внутри этапа дала по два физических вызова на положительных входах с двумя источниками; на остальных — по одному. [Девять результатов со счётчиками](owner-judge-results.json) · [Входы, зафиксированные до вызова](owner-judge-inputs.json).

| Документ | Содержание одной и той же коллизии | Только фильтр | Фильтр + два источника | Ответ согласуется с ТЗ |
| --- | --- | --- | --- | --- |
| Уведомления | Ответ включает перевод в счётчик, Ф-2 и приёмка исключают его | Отклонён | Принят, D-28 | Отклонён |
| QR | Ответ добавляет комиссию 20 ₸, Ф-4 запрещает комиссию | Отклонён | Принят | Отклонён |
| Автокредит | Для 3-го числа ответ требует 200, Д-2 разрешает 5–25 и требует 422 вне диапазона | Отклонён | Принят, D-11 | Отклонён |

Для положительных входов использованы те же пять архивных кандидатов с теми же цитатами и ответами. В зачёт вошли три заранее указанные причины. Во всех трёх принятых карточках F4 проверил содержание ответа, ссылки на ответ и место исходного ТЗ. На отрицательном контроле исходное обвинение кандидата сохранено. Заменён только ответ владельца: он прямо соглашается с нормой документа. Так проверяется, читает ли судья второй источник самостоятельно. [Все три контроля](owner-judge-controls.json) · [Положительные решения](owner-judge-reports/two-sources/) · [Решения на контролях](owner-judge-reports/agreeing-control/).

В исходном режиме системный текст описывает замечания внутри одного ТЗ. Хотя пересмотр помещал ответ в текст кандидата, судья требовал найти его в самом ТЗ. Новая правка передаёт реальные ответы отдельным блоком данных с номерами, а в системном задании включает режим двух источников только для кандидатов пересмотра. Чтобы подтвердить конфликт, судья должен сопоставить ответ с продолжающим действовать пунктом ТЗ. Новое пожелание само по себе не образует противоречия. Обычные карточки первого прохода используют прежний режим. [Правка и две регрессии](owner-judge-sources.patch) · [Девять прогонов по сохранённым кандидатам](owner_judge.py).

Правку испытали в отдельной рабочей копии `3e7133c2` с [исправлением фильтра](owner-conflicts.patch). В группе тестов судьи и пересмотра прошли 136 проверок. Обе правки применимы к интеграции `d013c123`; результаты первоначального сквозного экзамена на `2eac95cb` по-прежнему составляют 17/33. Влияние на другие продукты и модели этим опытом не измерено. [Сквозной экзамен](../answers_exam/merged/RESULTS.md).

Для повтора в отдельной копии исходной версии примените правку фильтра. Выполните первую команду для трёх документов, затем примените правку судьи и повторите те же вызовы. Путь `$f4` указывает на каталог аудита.

```powershell
foreach ($doc in 'car-loan','official','qr') {
    python "$f4/acceptance/owner_judge.py" --repo . --out out/f4-judge-filter --document $doc
}
git apply "$f4/acceptance/owner-judge-sources.patch"
foreach ($doc in 'car-loan','official','qr') {
    python "$f4/acceptance/owner_judge.py" --repo . --out out/f4-judge-two-sources --document $doc
    python "$f4/acceptance/owner_judge.py" --repo . --out out/f4-judge-control --inputs "$f4/acceptance/owner-judge-controls.json" --document $doc
}
```
