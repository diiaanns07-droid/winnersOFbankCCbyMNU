# Одни и те же дефекты в MD, PDF и DOCX

На коде релизной ветки `3e7133c2` через обычный CLI прошли 96 проверок без модели. Это 32 родственных варианта из четырёх семейств банковских ТЗ, каждый в трёх форматах. В каждом формате строгий оценщик сопоставил 27 из 28 внесённых причин при нуле лишних карточек. Во всех 32 тройках совпали число карточек, множество найденных причин и оба вердикта. Пропуск в каждом формате один и тот же: договорённость о последних четырёх цифрах при блокировке карты. [Данные по входам](formats-result.json) · [Исходный корпус и разметка](https://github.com/diiaanns07-droid/winnersOFbankCCbyMNU/tree/3e7133c2/evaluation/dev/corpus).

Среди 32 вариантов — четыре чистых исходника, четыре перефраза без смены смысла, 20 одиночных мутаций и четыре пары внесённых дефектов. Выход `verify` подтверждён для всех 96 отчётов, суммарно проверены 153 цитаты. Правила не выставили замечаний ни на одном из восьми чистых текстов, но и не дали разрешение на разработку или тестирование: ответ обоих полей — `undetermined`. Пустой служебный вход генератора исключён до подсчёта. Проход не измеряет качество модели и не заменяет финальный слепой экзамен. [Скрипт опыта](formats.py) · [Проверка живого судьи](../trust_after.md).

## Повторить

Нужны чистая копия кода `3e7133c2` и Python 3.12 с зависимостями агента. Для генерации представлений нужны также `reportlab`, `python-docx`, `pdfplumber` и три шрифта DejaVu. На Windows пакет Matplotlib содержит шрифты, пригодные без системной установки. В примере `$f4` указывает на каталог проверок F4 в отдельной копии аудиторской ветки. Команды выполняются из корня проверяемой версии.

```powershell
python -m pip install -r requirements.txt -e .
python -m pip install reportlab pdfplumber matplotlib
$fonts = python -c "from pathlib import Path; import matplotlib; print(Path(matplotlib.get_data_path()) / 'fonts' / 'ttf')"
python "$f4/acceptance/formats.py" --repo . --out out/f4-formats --font-dir "$fonts"
```

Скрипт использует установленный в проверяемой версии оценщик. Для каждой зачтённой причины он проверяет тип и текстовые опоры, для противоречия нужны обе стороны. Подробные файлы `md.metrics.json`, `pdf.metrics.json` и `docx.metrics.json` перечисляют зачтённые причины и пропуски. Таблица `result.json` показывает также возможный случай, когда в двух форматах число карточек одинаково, а найденные причины различаются. [Правила сопоставления](https://github.com/diiaanns07-droid/winnersOFbankCCbyMNU/blob/3e7133c2/evaluation/harness/score.py).
