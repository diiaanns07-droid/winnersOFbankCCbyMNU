## Что подтвердилось при чтении критических карточек

- **Капитализация, D-01 — minor.** Шаг 3 проверяет активность карты до сохранения. Для заблокированной карты прямо указан 400. Повтор уже выбранного способа даёт 200 после прохождения проверок. Можно уточнить область правила повтора; альтернативный успех на недопустимом входе не обязателен. [Карточка](capital_v2.md) · [Исходник, стр. 124, 129, 168](https://github.com/diiaanns07-droid/winnersOFbankCCbyMNU/blob/d013c123/evaluation/v2/clean/capital_v2/source.md#L124).
- **Льготный период, D-01 — отклонить.** Ф-1 обещает «до 55 календарных дней». Карточка отсчитывает для каждой покупки ровно 55 дней и получает 6 апреля для покупки 10 февраля. Расчётное окно определяется выпиской и заканчивается 25 марта. Такой вход не доказывает противоречия. [Карточка](grace_v2.md) · [Исходник, стр. 36–38, 40](https://github.com/diiaanns07-droid/winnersOFbankCCbyMNU/blob/d013c123/evaluation/v2/clean/grace_v2/source.md#L36).
- **Страхование, D-01 — отклонить.** Полное досрочное погашение прекращает страхование и запускает частичный возврат. После прекращения договор уже нельзя отменить с полным возвратом — в методе прямо указан 409. Карточка применяет общее правило охлаждения к уже прекращённому полису. [Карточка](insurance_v2.md) · [Исходник, стр. 40–41, 224](https://github.com/diiaanns07-droid/winnersOFbankCCbyMNU/blob/d013c123/evaluation/v2/clean/insurance_v2/source.md#L40).
- **Досрочное погашение, D-01 — minor.** Для первого запроса с недостаточным остатком задан подтверждённый отказ без списания. Ответ 200 в правиле повтора зависит от самостоятельной последующей проверки факта проведения в АБС. Карточка переносит результат этой проверки на первоначальный запрос. Имеет смысл уточнить, когда возможна сверка проведённой операции после подтверждённого отказа; второго обязательного исхода для того же запроса не показано. [Карточка](repay.md) · [Исходник, стр. 74, 80–81, 135, 139–140, 158](https://github.com/diiaanns07-droid/winnersOFbankCCbyMNU/blob/d013c123/evaluation/v2/clean/repay/source.md#L74).
- **Выписка, D-01 — minor.** Строка 54 задаёт для таблицы текущее время 10 марта, 12:00. В строке 79 дату 15 марта указали только для окончания хранения файла. Для самой выдачи ссылки стоит только время 12:00. При выдаче 10 марта в 12:14 до срока файла ещё пять дней. В следующей строке для выдачи в последний день дата повторена прямо. Уточнение даты сделало бы пример яснее, но запрещать выпуск на таком основании нельзя. [Карточка](statement.md) · [Исходник, стр. 36, 54, 79–80, 198](https://github.com/diiaanns07-droid/winnersOFbankCCbyMNU/blob/d013c123/evaluation/v2/clean/statement/source.md#L36).

Вне авторского ключа оказались 5 critical, 31 major и 82 minor. F4 вручную сверил все отмеченные critical. Индивидуальной экспертной разметки оставшихся 113 карточек в этом опыте нет. Корпус публичный и входит в историю разработки. Четыре требования производны от исправленных редакций open2. Поэтому эти два корпуса нельзя складывать как независимые наблюдения. ## Повторить

Восемь полных CLI-запусков прошли на чистой версии `d013c123`. В каждом паспорте одна фактическая модель `claude-haiku-5-5`, по одному запуску на документ, без кеша и резервной модели. Сверка проверяет хеш исходника, пустой ключ, версию кода, паспорт и цитаты. В чистой копии указанной версии задайте абсолютный путь `$f4` к каталогу аудита.

```powershell
$env:PYTHONUTF8 = '1'
$env:CLAUDE_CLI_FALLBACK_MODEL = 'off'
$out = 'out/f4-clean20'
New-Item -ItemType Directory -Force $out | Out-Null
Get-ChildItem evaluation/v2/clean -Directory | Where-Object { Test-Path (Join-Path $_.FullName source.md) } | ForEach-Object {
    python -m bcc_review (Join-Path $_.FullName source.md) "$out/$($_.Name).md" --provider claude_cli --model haiku --no-cache --no-html
}
python "$f4/acceptance/clean20_score.py" --repo . --reports $out
```

Для проверки опубликованных отчётов достаточно последней команды с `--reports "$f4/acceptance/clean20"`. [Проверяющий скрипт](../clean20_score.py).
