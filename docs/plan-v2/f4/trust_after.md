# Можно ли доверять вердикту после правок судьи

**Решение для №01 к заморозке.** Оставить выбранную сборку без дополнительной калибровки F4. В собственном контроле сборки `c6aa9b5` из четырёх исправленных ТЗ одно получило ложное «нельзя». На четырёх дефектных парах все 16 блокирующих причин найдены, но только 13 получили critical. В опыте №01 дополнительная калибровка сохранила пять официальных блокеров, а число найденных существенных причин уменьшилось на одну на каждой из двух моделей. Сырые результаты отдельного варианта с калибровкой на исправленных ТЗ к этому решению не поступили. ### Повтор измерения

Команды запускаются из рабочей копии нужной версии. Переменная `$f4` указывает на каталог материалов аудитора из ветки `codex/f4-precision-audit`. Для официальных баллов именно этого сравнения возьмите оценщик из `743ff39`. Путь к кешу оценщика должен указывать на новый файл, чтобы ранее принятые решения арбитра не участвовали. [Код оценщика](https://github.com/diiaanns07-droid/winnersOFbankCCbyMNU/blob/743ff39/evaluation/v2/score.py).

```powershell
$env:PYTHONUTF8 = '1'
$env:PYTHONPATH = (Resolve-Path src).Path
$env:CLAUDE_CLI_FALLBACK_MODEL = 'off'
$f4 = (Resolve-Path '../f4-team-20261127/docs/plan-v2/f4').Path
Expand-Archive "$f4/trust_reports/reviewer-inputs.zip" out/f4-inputs -Force
$opt = @('--provider','claude_cli','--model','haiku','--no-cache','--no-html')
foreach ($case in 'capital','grace','insurance','qr') {
    foreach ($variant in 'clean','defect') {
        $dataset = if ($variant -eq 'clean') { "${case}_clean" } else { $case }
        $inputId = if ($variant -eq 'clean') { $case } else { "$case-defect" }
        python -m bcc_review stage judge --doc "evaluation/v2/open2/$dataset/source.md" --from "out/f4-inputs/$inputId" --out "out/f4-repeat/$inputId.md" @opt
        if ($LASTEXITCODE -ne 0) { throw $inputId }
    }
}
# Из рабочей копии 743ff39, укажите путь к полученному каталогу отчётов.
$runsF4 = (Resolve-Path 'out/f4-repeat').Path
$cacheF4 = Join-Path $env:TEMP ("open2-" + [guid]::NewGuid() + ".jsonl")
foreach ($case in 'capital','grace','insurance','qr') {
    python -m evaluation.v2.score "$runsF4/$case-defect.json" --gold "evaluation/v2/open2/$case/gold.yaml" --arbiter off --cache $cacheF4 --out "$runsF4/$case-defect.score.json"
}
```

## Промежуточный вывод, переданный до замера

**Промежуточное решение для №01.** Отложить включение именно добавки F4 до сравнения на исправленных ТЗ. В опубликованной проверке №01 на официальном входе целый судья с калибровкой сохранил пять из пяти блокеров на обеих моделях. При добавлении калибровки число найденных существенных причин снизилось на одну на каждой модели. Независимый результат по ложным запретам на исправленных ТЗ для этой комбинации пока не получен. [Сравнение №01 на фиксированных выходах линз](https://github.com/diiaanns07-droid/winnersOFbankCCbyMNU/blob/9bd5954/docs/plan-v2/status/01.md#L48-L67) · [План отдельного замера](https://github.com/diiaanns07-droid/winnersOFbankCCbyMNU/blob/9bd5954/docs/plan-v2/INTEGRATION.md#L8-L28).

## Что показало утро

Единица в колонках вердикта — отчёт по одному документу и одной модели. «Без основания в карточках» означает, что ни один из предъявленных блокеров в этом отчёте не выдержал проверки F4. Это позволяет отличить качество обоснования от фактической готовности документа. [Шкала и исходная разметка F4](calibration.md).

| Исправленные ТЗ open2, редакция 1 | Отчётов | Объявлено critical | Подтверждено как critical | Завышено или ложно | «Нельзя» хотя бы в одном направлении | Из них без основания в карточках этого отчёта |
| --- | ---: | ---: | ---: | ---: | ---: | ---: |
| Haiku | 4 | 7 | 2 | 5 | 3 | 2 |
| Sonnet | 4 | 2 | 0 | 2 | 2 | 2 |
| Обе модели | 8 | 9 | 2 | 7 | 5 | 4 |

По этой серии каждое «нельзя» было выставлено и для разработки, и для тестирования. Для одних и тех же байтов QR у Haiku нашлись два настоящих блокера. Sonnet также запретил старт, но его критичная карточка оказалась ложной. Поэтому из пяти запретов четыре лишены основания в собственном отчёте, а три приходятся на документы, где F4 не подтвердил блокер ни по одному из двух отчётов. Два других документа здесь — льготный период и проценты по счёту. Для major по обеим моделям F4 сохранил 31 из 108, понизил 54 до minor и отклонил 23. ## Что опубликовано после изменения судьи

| Один набор кандидатов, официальный вход | Критичными до → с калибровкой F4 | Существенные причины до → с F4 | Дубли до → с F4 |
| --- | --- | --- | --- |
| Sonnet, целый судья №10 + F2 | 5/5 → 5/5 | 20/20 → 19/20 | 2 → 2 |
| Haiku, целый судья №10 + F2 | 5/5 → 5/5 | 18/20 → 17/20 | 3 → 4 |

Это счёт №01. Вариант с разбиением судьи на две части дал отдельный результат — на Haiku один из пяти блокеров получил major. Для проверки самой калибровки релевантны две строки целого судьи. Без сырых результатов попарный список потерянных и пониженных причин на новых документах восстановить из этих сумм нельзя. [Замер №01](https://github.com/diiaanns07-droid/winnersOFbankCCbyMNU/blob/9bd5954/docs/plan-v2/status/01.md#L48-L67).

Ближайший доступный контроль на четырёх исправленных open2 относится к **правкам №10**. При одних выходах линз Haiku сообщил до правок 2 critical и 37 major, два «нельзя», после — 0 critical, 4 major и ноль «нельзя». На пяти дефектных входах счёт эталонных блокеров изменился с 19/20 до 20/20, присвоенный critical — с 14 до 18. Пятый вход включает отдельный вариант страхования. Без независимой проверки последних четырёх major этот замер говорит об изменении вердиктов, а не о правильности каждой карточки. [Исходные числа и протокол №10](https://github.com/diiaanns07-droid/winnersOFbankCCbyMNU/blob/9ed5b42/docs/plan-v2/status/10.md#L12-L37).

Для решения о добавке F4 запрошены отчёты №01/№19 с паспортами, финальными карточками, исходниками и контролем на тех же кандидатах. Для blind3 публикуются только групповые результаты после разрешённой фиксации отчётов. На этом этапе сравнение «7 ложных critical утром → 0 после калибровки F4» не подтверждено.
