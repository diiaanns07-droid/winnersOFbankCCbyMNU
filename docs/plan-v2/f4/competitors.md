## ERA216

1. При проверке нарезки в одной строке соседствуют исходная фраза, её пересказ, ID и место. У нас исходную цитату каждого требования нужно искать в JSON. Особенно ощутимый проигрыш для строки без номера в самом ТЗ. [ERA216, стр. 28–33](https://github.com/ERA216/Hac/blob/3bfe28f962e812e5beecf4fa57a01eb546e472ab/reports/report.md?plain=1#L28) · [BCC, стр. 59–63](https://github.com/diiaanns07-droid/winnersOFbankCCbyMNU/blob/bd71bb9a193e41ea05c252598ee872ebd544040e/evaluation/v2/measurements/zamer_08_30_6d03683_haiku/report.md?plain=1#L59).
2. Матрица ERA216 называет нарушенные критерии словами и показывает место требования. В нашей строке восемь сокращений и цветные значки. Для бумажного или узкого экрана жюри удобнее оставить в строке только применимые критерии с полными названиями. [ERA216, стр. 74–82](https://github.com/ERA216/Hac/blob/3bfe28f962e812e5beecf4fa57a01eb546e472ab/reports/report.md?plain=1#L74) · [BCC, стр. 127–134](https://github.com/diiaanns07-droid/winnersOFbankCCbyMNU/blob/bd71bb9a193e41ea05c252598ee872ebd544040e/evaluation/v2/measurements/zamer_08_30_6d03683_haiku/report.md?plain=1#L127).
3. В карточке отсутствующего метода чтения ERA216 предлагает дополнить API отдельной операцией. В нашей таблице правок агент предлагает заменить действующий параметр сохранения описанием чтения. Если аналитик перенесёт правку дословно, потеряет часть контракта. [ERA216, стр. 127–129](https://github.com/ERA216/Hac/blob/3bfe28f962e812e5beecf4fa57a01eb546e472ab/reports/report.md?plain=1#L127) · [BCC, стр. 226–227](https://github.com/diiaanns07-droid/winnersOFbankCCbyMNU/blob/bd71bb9a193e41ea05c252598ee872ebd544040e/evaluation/v2/measurements/zamer_08_30_6d03683_haiku/report.md?plain=1#L226).

## SoloHive

1. Уже на первом экране видны два вердикта до и после ответов. Из 55 находок остаются 23, закрыты все шесть объявленных блокеров. Есть связь «ответ → закрытый ID → новая редакция → новый критерий приёмки». Наш опубликованный файл заканчивает этот путь списком вопросов и предложениями правок. Преимущество относится к показанному сценарию. Повторное независимое ревью исправленного входа и происхождение ответов этим сравнением не проверялись. [SoloHive, сводка](https://github.com/khusrav11/solohive/blob/479ff57c1962a31c5c64294c9ffddcef05eb8b2e/reports/report.md?plain=1#L13) · [SoloHive, пересмотр](https://github.com/khusrav11/solohive/blob/479ff57c1962a31c5c64294c9ffddcef05eb8b2e/reports/report.md?plain=1#L1969) · [BCC, вопросы](https://github.com/diiaanns07-droid/winnersOFbankCCbyMNU/blob/bd71bb9a193e41ea05c252598ee872ebd544040e/evaluation/v2/measurements/zamer_08_30_6d03683_haiku/report.md?plain=1#L608).
2. В таблице блокеров для PDF указаны и строка, и страница. Жюри может сразу открыть лист оригинала. Наш выбранный прогон на MD даёт строки. Для пути жюри стоит показать такой же результат на PDF. SoloHive также предъявляет холодный прогон Gemini за 212,3 с. Наш Haiku на другом входном формате занял на 139,5 с больше. В нашей отдельной серии Sonnet диапазон 195,6–233,4 с, поэтому общего проигрыша по скорости из этих файлов не следует. [SoloHive, места блокеров](https://github.com/khusrav11/solohive/blob/479ff57c1962a31c5c64294c9ffddcef05eb8b2e/reports/report.md?plain=1#L22) · [SoloHive, замер](https://github.com/khusrav11/solohive/blob/479ff57c1962a31c5c64294c9ffddcef05eb8b2e/reports/report.md?plain=1#L49) · [BCC, паспорт](https://github.com/diiaanns07-droid/winnersOFbankCCbyMNU/blob/bd71bb9a193e41ea05c252598ee872ebd544040e/evaluation/v2/measurements/zamer_08_30_6d03683_haiku/report.md?plain=1#L43) · [Серия Sonnet](https://github.com/diiaanns07-droid/winnersOFbankCCbyMNU/blob/bd71bb9a193e41ea05c252598ee872ebd544040e/evaluation/v2/RESULTS.md?plain=1#L40).

## azekowka

1. На тех же байтах исходника можно выборочно проверить нарезку прямо в MD. Например, в строке ТР-02 показана прямая цитата о конкретном участке архитектуры. У нас этому соответствует обобщённая карточка R-02, доказательство вынесено в JSON. Перенести короткий исходный фрагмент в таблицу — конкретное улучшение проверяемости. Само различие 53 против 40 требований не измеряет полноту. [azekowka, стр. 73–78](https://github.com/azekowka/ai-requirements-validator-task/blob/c704a9e2dffe59390c7c104a517aedfa10ae4ce8/reports/requirements-report.md?plain=1#L73) · [BCC, стр. 59–64](https://github.com/diiaanns07-droid/winnersOFbankCCbyMNU/blob/bd71bb9a193e41ea05c252598ee872ebd544040e/evaluation/v2/measurements/zamer_08_30_6d03683_haiku/report.md?plain=1#L59).
2. Журнал снятых замечаний даёт ID кандидата и номер оставшейся карточки, например О-01 → Д-86. У нас в приложении есть мотивировка отклонения, но в трёх опубликованных строках вместо ID стоит прочерк и нет ссылки на оставшуюся карточку. Для F2 это важно при проверке, действительно ли снят дубль. [azekowka, стр. 2363–2372](https://github.com/azekowka/ai-requirements-validator-task/blob/c704a9e2dffe59390c7c104a517aedfa10ae4ce8/reports/requirements-report.md?plain=1#L2363) · [BCC, стр. 786–794](https://github.com/diiaanns07-droid/winnersOFbankCCbyMNU/blob/bd71bb9a193e41ea05c252598ee872ebd544040e/evaluation/v2/measurements/zamer_08_30_6d03683_haiku/report.md?plain=1#L786).
