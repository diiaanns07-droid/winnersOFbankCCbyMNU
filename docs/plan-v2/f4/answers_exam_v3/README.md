| Класс | Сколько | Типы |
| --- | ---: | --- |
| **Противоречивые** | 8 | два адресата с разными значениями (2 пары = 4 реплики), ответ против общего решения (2 реплики одной пары), ответ против другого места ТЗ, которое он не меняет (2) |

## Что засчитывается (строго по ключу, скриптом)

`python docs/plan-v2/f4/answers_exam_v3/score.py <каталог прогона> [--key …/key-fresh.json]` — без модели и без
ручных поправок. Реплика получает балл, только если выполнены **все** условия её ключа:

- противоречие адресатов или ответа с решением → дефект **открыт**, и `answer_conflict` называет обе стороны;
- ответ против другого места ТЗ → в отчёте после ответов **новый дефект** с цитатой этого места;
- неоднозначный ответ → агент **переспросил** (`needs_confirmation` или предупреждение «подтвердите/уточните») и
  **ничего им не закрыл**; для устаревшего номера с точной темой допустима и верная привязка по теме;
- обычный ответ → нужный дефект снят именно этой репликой, а число / правка видны в исправленной редакции
  (`revised_contains` / `revised_not_contains`); отложенное — в `postponed`, дефект открыт; вставка-указание не
  снимает чужих дефектов.

## Порог (зафиксирован до прогона)

- **≥ 27/30** и **≥ 7/8 противоречивых** (не ниже доли 5/6 из задания);
- при повторном чтении исправленной редакции — **0 новых ложных critical** (каждый critical повторного чтения
  разбирается в RESULTS: настоящий дефект, внесённый правкой, или открытый конфликт владельцев — не ложный).

## Запуск (sonnet, без кэша)

```bash
export PYTHONPATH=src PYTHONUTF8=1 CLAUDE_CLI_FALLBACK_MODEL=off
E=docs/plan-v2/f4/answers_exam_v3
for c in capital grace insurance; do
  python $E/run_exam.py $c $E/$c/answers.md $E/runs/<серия>/$c --provider claude_cli --model sonnet --no-cache --no-html
  python -m bcc_review verify $E/runs/<серия>/$c/answered.json $E/$c/source.md
  python -m bcc_review $E/runs/<серия>/$c/answered.revised.md $E/runs/<серия>/$c/reread.md --provider claude_cli --model sonnet --no-cache --no-html
done
python $E/score.py $E/runs/<серия>
```

`run_exam.py` — тот же `pipeline.review`, что у `python -m bcc_review <ТЗ> <отчёт> --answers … --revise`, но с
готовыми этапами исходного отчёта (`reuse=`, как у команды `stage`): владелец отвечает на вопросы **того** отчёта,
который видел, поэтому номера Q и D не перегенерируются. Живьём идут пересмотр, суд над новыми кандидатами и
редакция.
