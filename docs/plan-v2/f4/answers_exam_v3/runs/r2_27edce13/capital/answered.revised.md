### Цели
Клиент сам выбирает, прибавлять проценты по вкладу к остатку или получать их на карту, и видит, сколько процентов начислено за текущий месяц. Снизить число обращений в контакт-центр о способе выплаты процентов.

### Архитектура решения
Мобильное приложение → API сбережений → депозитный модуль. Депозитный модуль → сервис уведомлений → push-уведомление клиенту.

### Дизайн процесса UI
Накопления → накопительный счёт → «Проценты». На экране: ставка, проценты за текущий месяц, переключатель «Капитализация / На карту», выбор карты для выплаты (виден при выборе «На карту»), кнопка «Сохранить». После сохранения под переключателем показывается дата, с которой действует новый способ. [изменено: D-01]

### Требования к изменениям

#### BPMN схема процесса
Ежедневное начисление процентов → последний день месяца → определение способа выплаты → капитализация или перечисление на карту → push клиенту → завершение.

#### Функциональные требования
* **Ф-1.** Владелец накопительного счёта в тенге выбирает способ выплаты процентов: капитализация (проценты прибавляются к остатку счёта) или перечисление на свою карту KZT. По умолчанию — капитализация.
* **Ф-2.** Проценты начисляются ежедневно на остаток счёта на конец дня по ставке 14 % годовых, база — фактическое число дней в году. Проценты, начисленные за месяц, выплачиваются в последний календарный день месяца.
* **Ф-3.** Новый способ выплаты применяется с даты выбора; проценты за весь месяц, в котором выбран способ, выплачиваются новым способом. [изменено: D-02]
* **Ф-4.** Неснижаемый остаток — 1 000 ₸ и задаётся в справочнике продуктов. Если остаток счёта на конец дня меньше неснижаемого остатка, проценты за этот день не начисляются; если остаток равен 1 000 ₸, проценты за этот день начисляются. [изменено: D-04]
* **Ф-5.** После выплаты клиент получает push с суммой процентов и способом выплаты.
* Ф-7. Система отправляет push о выплате процентов не позже 10:00 по времени Астаны в день выплаты. [добавлено: Решение-1]
* **Ф-6.** При закрытии счёта проценты за неполный месяц выплачиваются в день закрытия: при способе «Капитализация» — вместе с остатком счёта, при способе «На карту» — <уточнить: на карту или вместе с остатком счёта>. [изменено: D-08]

### Логика работы метода
1. Проверить сессию клиента.
2. Проверить, что накопительный счёт принадлежит клиенту, открыт и ведётся в тенге; для счёта не в тенге метод возвращает <уточнить: код и текст ответа>. [изменено: D-09]
3. Если `mode` = `CARD`, проверить, что карта `cardId` принадлежит клиенту, активна и открыта в тенге.
4. Сохранить способ выплаты с датой начала действия — дата выбора. [изменено: D-02]
5. Вернуть действующий способ выплаты, дату начала его действия, ставку и проценты за текущий месяц. [изменено: D-02]

### Особые правила
1. Повторная установка уже выбранного способа не считается ошибкой: возвращается 200 с текущими условиями.
2. Если клиент несколько раз сменил способ в течение месяца, с даты последнего выбора действует последний выбранный способ. [изменено: D-02]
3. Для способа `CAPITALIZATION` поле `cardId` не передаётся; переданное значение не сохраняется.
