# Blind3 · порядок прогона и зачёта

В [папке входов](../../../evaluation/v2/blind3/) лежат шесть файлов Markdown. Для каждого нужен отдельный запуск агента, без доступа к соседним файлам и их отчётам. Идентификатор прогона — имя входного файла. Для сравнения моделей каждую проверяют на всех шести документах с одной версией кода и настроек.

**Для F1 или F3.** На машине с настроенным провайдером передайте каждому запуску отдельный вход. Например, из корня рабочей версии v2 в PowerShell:

```powershell
$reportDir = 'out/blind3'
New-Item -ItemType Directory -Force -Path $reportDir | Out-Null
foreach ($specFile in Get-ChildItem -File -Path 'evaluation/v2/blind3/tz-*.md') {
    $reportPath = Join-Path $reportDir $specFile.Name
    python -m bcc_review $specFile.FullName $reportPath --no-cache
    if ($LASTEXITCODE -ne 0) { Write-Warning "Неполный прогон: $($specFile.Name)" }
}
```

Вернуть шесть пар MD/JSON с ID входа и моделью. При отсутствии JSON достаточно MD с паспортом, временем, вердиктами и полным перечнем замечаний. Для повторной модели использовать отдельный выходной каталог. Ошибку или частичный запуск сохранить под своим ID.

**Что зафиксировано до запуска.** Положительные редакции дважды проверены. Сначала сверены ссылки, поля, примеры JSON и структура таблиц. Затем независимо от перечня внесённых дефектов просчитаны примеры, границы и переходы состояний. SHA-256 закрытого эталона с секретной случайной солью — `edbf2f90d82347a53e91f353566741ef5f4b1a62efab3f4936fa207914657944`. Набор пригоден для слепой оценки при первом независимом прогоне на зафиксированной конфигурации.

## Как F4 выставит результат

- Единица сопоставления — одна исходная причина в одном документе. Совпадение требует корректного текстового основания и того же наблюдаемого последствия. Для пропуска подходит место, где нужный результат обещан. Семантическое совпадение засчитывается при любом присвоенном уровне, ошибку уровня считаем отдельно.
- Каждой карточке и каждой эталонной причине можно дать максимум один зачёт. При нескольких подходящих связях выбираем максимальное число однозначно доказанных пар. Повтор одной причины во второй карточке — лишняя находка. Объединённая карточка получает один зачёт. Вопросы, тест-кейсы и отклонённые кандидаты в число находок не входят.
- **Recall** = совпавшие причины / все внесённые причины. **Precision** = совпавшие карточки / все финальные карточки на шести ТЗ, включая чистые. Публикуем числители и знаменатели суммарно и по группам. Каждой карточке назначается одна группа по основной причине. При пустом знаменателе ставим «не определено». Чистые документы отдельно имеют нулевой знаменатель recall.
- **Ложные critical** считаем двумя непересекающимися группами — без подтверждённой причины (включая лишний дубль) и с настоящей причиной меньшей тяжести. Отдельно указываем сумму и число critical на чистых. Подтверждённую новую причину вне эталона отмечаем отдельно от ложного утверждения. В строгом precision она остаётся вне зачёта, в счетчике ложных critical оценивается по фактической тяжести.
- **Готовность чистых** — число «можно / с условиями / нельзя» из трёх отдельно для разработки и тестирования, плюс документы хотя бы с одним «нельзя». При неполной серии указываем покрытие и отсутствующие паспорта. Итоговую сопоставимую оценку выдаём после шести полных отчётов. По частичным возможен отдельный предварительный срез.
- В открытом результате будут только группы причин, агрегаты критичности и вердикты. Сопоставления по документам и конкретные ответы хранятся у F4. До получения отчётов показатели не измерены.
