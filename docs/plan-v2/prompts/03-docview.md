## Твоя роль: №03 — документ с номерами строк, сверка цитат, затем экспорт. Ветка: `v2/03-docview`

Доказательность — главный козырь: каждая цитата в отчёте найдена программой, номер строки посчитан кодом, а не моделью. В v1 8–10 отчётов из 24 не прошли свой же `verify`: цитата привязывалась к другому вхождению той же фразы.

**Твои файлы:** `src/bcc_review/v2/{docview,quotes,readers_html}.py`, `src/bcc_review/v2/render/exports.py`, `tests/v2/test_03_*`.

**Задачи:**
1. **До 02:30** — `docview.load(path)` поверх v1 `bcc_review.engine.read_document(path)` (читатели MD/TXT/PDF/DOCX уже протестированы): `Line` и `DocView` по CONTRACT, раздел 2.1. Для MD/TXT одна строка view = одна строка файла (номера совпадают с GitHub), видимый текст без markdown-разметки, ячейки таблиц через « | ». Для PDF/DOCX — по строке на блок или визуальную строку, со страницей и разделом. `numbered(view)` → «L038| …», для PDF «L045| [с.3] …». Заголовок документа, sha256, предупреждения читателя.
2. **До 03:00** — `quotes.verify_quote` по CONTRACT, раздел 7: нормализация, ближайшее к подсказке вхождение, склейка до 3 строк, нечёткое ≥ 0,92 только рядом с подсказкой. Плюс пакетная проверка кандидатов: проставляет `verified` и точные `line_start/line_end/page/section`, отбрасывает ненайденные.
3. Тесты: все цитаты эталона из `docs/task-analysis.md`, раздел 5, находятся на своих строках в `release/input/requirements.md`; тот же текст из `release/input/requirements.pdf` даёт те же разделы и разумные страницы; фраза, повторённая в «Целях» и в таблице API, привязывается к ближайшей к подсказке; базы корпуса `evaluation/dev/corpus/cases/*.base` (md, pdf, docx) читаются без потерь (сравни число непустых строк и наличие ключевых фраз).
4. `readers_html.py`: HTML на входе (п. 1 ТЗ: «остальные форматы в плюс») через стандартный `html.parser` — заголовки, абзацы, списки, таблицы → строки view.
5. **После 05:00** — экспорт для банка в `render/exports.py`: (а) Jira CSV — строка на дефект (Summary, Description с цитатами и местом, Priority по серьёзности, Labels); (б) DOCX — если вход DOCX, копия исходного файла с комментариями Word на местах цитат; если вход MD — Word-версия отчёта; (в) PDF — если вход PDF, копия исходного файла с выделениями цитат и примечаниями (PyMuPDF `add_highlight_annot` по поиску цитаты на странице). Можно переиспользовать v1 `exports/word.py`, `exports/pdf.py`, `exports/jira.py` через преобразование результата v2 — выбери быстрый путь. Подключение через `--export html,docx,pdf,jira` (точку вызова согласуй с №01).

**Готово, когда:** 100 % цитат эталона находятся на верных строках в MD и PDF; тест на повтор фразы зелёный; экспорт открывается (проверь чтением результата через python-docx и PyMuPDF).
