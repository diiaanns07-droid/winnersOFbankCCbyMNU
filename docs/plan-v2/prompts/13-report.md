**Твои файлы:** `src/bcc_review/v2/render/{markdown,jsonout,console}.py`, `src/bcc_review/v2/verify.py`, `contracts/v2.json`, `tests/v2/test_13_*`, `tests/v2/fixtures/13_report_sample.json`.

**Структура** (обязательные разделы п. 6 ТЗ — по порядку 1–6):
* Заголовок и строка «Сформирован агентом … (коммит …) без ручных правок; все N цитат сверены программой».
* **Кратко** (первый экран): вердикт по разработке и тестированию значками; числа (требований, дефектов по серьёзности, вопросов); таблица блокеров (дефект — где — почему блокирует); «Исправить первым» — 3–7 пунктов; если были ответы — таблица «до/после».
* 1. Паспорт прогона: документ, файл, формат, SHA-256, дата и время (UTC+5), фактическая модель, провайдер, версия и коммит, вызовы, токены, время, статус и статусы этапов — человеческими словами, без путей модулей.
* 2. Нарезка: ID в отчёте — ID в документе — вид — краткая формулировка — место (раздел, строка, страница); «Не вошло в нарезку» с причинами.
* 3. Проверка каждого требования: компактная матрица (требование × нарушенные критерии, значок итога, ссылки на дефекты); карточки critical и major полностью (критерий со ссылкой на стандарт, места с цитатами, проблема, сценарий, последствия, что исправить, «было → стало», вопрос), minor — одной таблицей.
* 4. Проверка набора: таблица критериев набора (согласованность, полнота, понятность, валидируемость, ранжирование, модифицируемость, прослеживаемость) с итогом и ссылками; противоречия по сценариям; сверка критериев приёмки («исполнение»); матрица покрытия требований критериями приёмки; глоссарий разночтений.
* 5. Сводка: требований, нарушений, без замечаний; критичные по видам — противоречивые, непроверяемые, неполные (как в ТЗ); нарушения по критериям.
* 6. Итог: можно ли начинать разработку и тестирование, обоснование, что исправить в первую очередь (со ссылками на дефекты).
* Приложения: А — вопросы владельцу с вариантами; Б — черновик тест-кейсов; В — чек-лист «Ревью требований» банка, заполненный агентом; Г — «было → стало»; Д — как работал агент (этапы, вызовы, время, отклонённые кандидаты с причинами); Е — методика (критерии, стандарты, шкала).

Текст: только русский; ID документа рядом с ID отчёта (R-04 / Ф-2); место — «Часть A › Функциональные требования, строка 38» (+ «стр. 2» для PDF); в карточке цитаты до ~160 символов с «…», полные — в JSON; якоря-ссылки на дефекты и требования; таблицы читаются на GitHub; ≤ 900 строк на официальном документе. `console.py` — короткая сводка в терминал после прогона.
