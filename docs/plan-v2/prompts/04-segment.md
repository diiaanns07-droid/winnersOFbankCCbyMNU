## Твоя роль: №04 — нарезка требований. Ветка: `v2/04-segment`

От нарезки зависят все линзы. ТЗ требует таблицу «ID в отчёте — ID в документе — краткая формулировка»; если номеров нет, агент присваивает свои и сохраняет цитату. Для ориентира: у ERA216 37 требований, у SoloHive 40, у azekowka 53 (каждая ячейка API-таблицы — шум).

**Твои файлы:** `src/bcc_review/v2/stages/segment.py`, `src/bcc_review/v2/prompts/segment.md`, `tests/v2/test_04_*`, `tests/v2/fixtures/<кейс>/segment.json`.

**Задачи:**
1. Промпт и схема ответа (CONTRACT, раздел 2.2). `source_id` сохраняет исходную нумерацию («Ф-1»; «Логика работы метода, п. 1»; «Критерии приёмки, строка 2»; «Query-параметр <имя>»; «Статус 400»); у абзаца без номера `source_id` пустой — ID присвоит код. Политика, общая для любых ТЗ: одно требование — это один пункт, одна строка таблицы параметров/статусов/критериев или один абзац с обязательством. Пункт с несколькими обязательствами не дробить (атомарность проверят линзы). Не включать метаданные, шаблон чек-листа ревью, блок согласующих, пустые разделы, строки «не используется», примеры (пример ответа относится к своему статусу) — перечислить их в `excluded` с причиной.
2. Код: ID `R-01…` по порядку документа; проверка цитат через `quotes` (№03; пока его нет — простой поиск подстроки); **проверка покрытия**: каждая непустая строка — внутри требования, в `excluded` или заголовок; иначе второй короткий вызов по непокрытым строкам (так v1 терял пропущенные блоки).
3. Длинные документы: части по разделам верхнего уровня (до ~250 строк), при обрезке — деление (`ask_split`), склейка и перенумерация.
4. **До 03:00 — фикстуры для всех линз**: `tests/v2/fixtures/official/segment.json` (MD) и `official_pdf/segment.json`, плюс 4 базы корпуса (`autopay.base`, `cardblock.base`, `cashback.base`, `transfer_limit.base`). Прогон на `sonnet`, проверь глазами. Это самый срочный пункт: остальные ждут.
5. Стабильность: 3 прогона официального документа → число требований ±2 и тот же набор `source_id`; на Haiku схема не ломается.

**Готово, когда:** в официальном документе есть Ф-1…Ф-4, цель, UI, BPMN, sequence, НФТ, данные, интеграция, 3 строки приёмки, 5 шагов логики, 3 особых правила, параметры запроса и ответа, статусы; чек-лист и согласующие — в `excluded`; непокрытых строк 0; 30–40 требований; MD и PDF дают сопоставимый список.
