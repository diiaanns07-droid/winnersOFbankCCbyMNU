## 3. Решение: лёгкое ядро v2 в том же пакете

`python -m bcc_review ВХОД ОТЧЁТ.md` → новое ядро `src/bcc_review/v2/`. Старый движок остаётся за флагом
`--engine v1`.

**Из v1 переиспользуем:** читатели MD/TXT/PDF/DOCX (`readers/*`, протестированы), адаптеры Gemini и Anthropic
(интерфейс `invoke(model, messages, schema, timeout_s)`), экспорт DOCX/PDF/Jira, корпус `evaluation/dev` и
счётчик `evaluation/harness`.
**С основного пути убираем:** оценку «каждое требование × каждый критерий» (`individual`, 26 тыс. токенов
на пакет), шумные правила как готовые замечания, контракт v1 с якорями по смещениям, отчёт v1.

```text
файл ─► docview: строки «L038| …», страница, раздел                          (код, №03)
     ─► rules: сигналы высокой точности                                      (код, №12)
     ─► segment: требования R-01…, исключённые фрагменты                     (LLM ×1, №04)
     ─► параллельно: линзы analyst · qa · architect · risk + consistency     (LLM ×5, №05–09)
     ─► quotes: каждая цитата ищется в документе, строка считается кодом     (код, №03)
     ─► judge: кластеры, отклонения с причиной, критичность, приоритет,
               чек-лист банка, текст вердикта                                 (LLM ×1, №10)
     ─► clarify: вопросы с вариантами ответа                                  (LLM ×1, №11)
     ─► verdict по правилу кода → отчёт MD/JSON/HTML/DOCX/PDF/Jira            (код, №13/14/03)
```

Около 8 вызовов. Цель: Gemini Flash ≤ 6 мин, Opus через CLI ≤ 15 мин, статус `complete`.

**План Б.** В 12:00 №01 и №15 сравнивают v2 и v1 по воротам качества. Если v2 не проходит, а v1 на Opus
по-прежнему находит К1–К5, выпускаем v1 (`--engine v1`) с отчётом №13 и судьёй №10 поверх находок v1;
решение записывается в `docs/plan-v2/INTEGRATION.md`.

## 7. Правила работы

1. **Ветки.** Старт сразу: `git switch -c v2/NN-имя origin/claude/gallant-gauss-vbjqc8`; когда в `bcc/v2` появится каркас — `git merge origin/bcc/v2`.
   Если среда сессии требует ветку `claude/…`, работайте в ней и дополнительно пушьте тот же коммит:
   `git push origin HEAD:v2/NN-имя` — это разрешено владельцем репозитория.
2. **Синхронизация каждые ~60 минут:** `git fetch origin && git merge origin/bcc/v2`, тесты, push.
3. **Статус:** только свой файл `docs/plan-v2/status/NN.md`: сделано (SHA), как проверить, метрики,
   просьбы к другим, следующий шаг. №01 читает статусы всех веток `v2/*` перед каждым слиянием.
4. **Слияния** делает только №01: в начале каждого часа, `--no-ff`, после зелёных `tests/v2` и mock-прогона.
5. **Тесты:** `tests/v2/test_NN_*.py` (уникальные имена файлов), запуск `python -m pytest tests/v2 -q`;
   без сети — провайдер `mock`.
6. **Бюджет живых вызовов.** `claude -p` тратит лимит той же подписки, на которой работают все 16 сессий.
   Итерации — одним этапом на сохранённых входах (`python -m bcc_review.v2 stage …`), модель для итераций
   `sonnet`, проверка устойчивости на слабой модели — `haiku` (ближе к Gemini Flash),
   Opus — контрольные прогоны. Полный прогон — не чаще раза в 20 минут на сессию.
7. **Запреты.** Не править отчёты руками. Не коммитить ключи и `.env`. Не копировать код конкурентов (лицензий
   нет). Не вставлять в промпты слова официального документа (push, saveLimit, тиын, порог, Алматы, Ф-1…):
   агент должен работать на любом ТЗ, это проверяет тест №15. Весь текст для пользователя — по-русски.
