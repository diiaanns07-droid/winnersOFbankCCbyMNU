# Что критично в логике BCC Review

Сборка 08d3af5. Основная проблема — достоверность решения по незнакомому банковскому ТЗ.

## Что показали прогоны

| Проверка | Измеренный результат |
| --- | --- |
| Правила, 32 непустых ТЗ | 0/28 эталонных дефектов, 179 замечаний, 44 ложные тревоги на 8/8 чистых ТЗ |
| Штатный адаптер Claude, одно ТЗ | 10 из 10 запросов отклонены из-за поля cache, 0 ответов для анализа |
| Claude после локальной правки, 4 частичных отчёта | 1/2 дефектов, 34 лишних по разметке, F1 5,4% |
| Gemini 3.5 Flash-Lite с явным выбором модели | 11 ТЗ с принятыми ответами, 1/5 дефектов, F1 2,9% |
| Блокирующий вердикт на чистом ТЗ | 2 из 8 получили запрет начинать разработку и тестирование |

Для Claude три из четырёх диагностических прогонов задел общий ограничитель расходов. Эти четыре отчёта показывают последствия локальной правки на небольшой выборке. Попадание — конфликт единиц тенге/тиын с двумя опорами.

## Три исправления с наибольшей отдачей

1. **Довести ответ модели до отчёта.** Убрать служебное поле из запроса Claude и делить обрезанный пакет. На чистом автопополнении четыре пакета достигли лимита 16 000 токенов, 57 требований остались без индивидуальной оценки. У azekowka уже реализовано деление и есть тест на такое поведение. [Тест конкурента](https://github.com/azekowka/ai-requirements-validator-task/blob/c704a9e2dffe59390c7c104a517aedfa10ae4ce8/tests/test_pipeline.py#L79)
2. **Сравнивать одно и то же поле по обе стороны конфликта.** Порог баланса и сумма пополнения независимы. Для одного параметра `days` срок 30 суток одновременно разрешён и вызывает HTTP 400. На этом примере Gemini принял восемь ответов, а межтребованийная проверка вернула ноль кандидатов. Проверять оба примера парой.
3. **Привязать вывод к нужному пункту.** В восьми отчётах проверка нашла цитату из другого вхождения слова. Ещё три верно замеченных пропуска метода чтения потеряли зачёт из-за короткой опоры. Контроль — те же восемь отчётов проходят verify, а три пропуска получают зачёт тем же счётчиком.

Сохранить стоит чтение ТЗ и генерацию граничных тестов: для суммы 1 000–1 000 000 ₸ четыре проверенных примера дали верный результат. Готовность к разработке пока должен подтверждать аналитик.
