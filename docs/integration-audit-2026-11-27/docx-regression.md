# Почему проверка официального DOCX стала красной

**На объединённом коде `831d82cf` mock находит 13/20 существенных причин. Порог теста — 14.** Все пять блокирующих причин найдены, все 104 цитаты подтверждены, итоговый JSON полный. Число найденных причин и совпадение цитат измеряют разные свойства отчёта. [Тест и пороги](../../tests/v2/test_31_regress.py)

| Проверенный коммит | Блокирующие причины | Существенные причины | Замечаний | Цитат без совпадения |
|---|---:|---:|---:|---:|

| Начальная база `d629aa0a` | 5/5 | 15/20 | 31 | 0 |

| Код итоговой сборки `831d82cf` | 5/5 | 13/20 | 29 | 0 |

Каждый отчёт создан полным CLI с `--provider mock --no-cache`. Каждый JSON оценён дважды — счётчиком и кэшем из собственного коммита и одной итоговой версией счётчика и кэша. Для приведённых строк результаты совпали.

Между `0b910505` и `825c2b8d` изменилась одна используемая во время выполнения запись — `tests/v2/fixtures/official/judge.json`. Остальные изменения этого слияния — тесты и статус. Автор перезаписал решение судьи по кандидатам официального Markdown. Выбор папки mock выделяет собственную запись для PDF, а DOCX берёт ту же запись, что и Markdown. Номера кандидатов в записанном решении относятся к конкретному набору входов судьи. [Разница между коммитами](https://github.com/diiaanns07-droid/winnersOFbankCCbyMNU/compare/0b910505...825c2b8d) · [Выбор фикстуры](https://github.com/diiaanns07-droid/winnersOFbankCCbyMNU/blob/831d82cf8ff9d53a91d2c8004c3dc2d269beeb3c/src/bcc_review/v2/pipeline.py#L197) · [Заметка автора](../plan-v2/status/23.md)

Из зачёта на DOCX выпали поведение после возврата, открытый перечень исключений и неполное описание спецификации. Вместе с этим добавилась одна зачтённая причина по интерфейсу. Итоговая разница — две. Владельцам №23 и №31 нужен записанный ответ судьи на кандидаты **DOCX**, после чего можно заново проверить оба формата. Порог 14 сохранён. Этот опыт измеряет повтор записанного ответа; качество новой живой модели на DOCX здесь не измерялось.

Для воспроизведения из корня объединённой ветки достаточно команды `python -m pytest "tests/v2/test_31_regress.py::test_mock_official_floor[docx]" -q`.
