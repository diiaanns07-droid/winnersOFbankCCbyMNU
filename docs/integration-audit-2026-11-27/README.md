## Что теперь работает вместе

- **Чтение и экспорт.** Добавлены случаи сложного PDF и DOCX, обработка разметки и таблиц, выгрузки для CI, автономный HTML и веб-демо. В Markdown восстановлены итог по каждому требованию и связь дублей с итоговой карточкой.
- **Проверка требований.** Вошли независимые проверки аналитика и тестировщика, проверка согласованности, новые правила и сведение находок судьи. На чистом документе и при общем повторном запуске аналитик учитывает уже выбранное число проходов.
- **Ответы владельца.** Пересмотр, проверка числовых значений, защита чужих требований при редактировании и учёт отвергнутых правок теперь попадают в один цикл. Сохраняются и причины, по которым предложенная правка не вошла.
- **Воспроизведение.** Объединены повтор прогона по сохранённым этапам, сравнение нескольких запусков, ограничение стоимости и отчёты независимой оценки. [Что именно пришло из каждой ветки](contributions.md)

## Где ветки расходились

1. **Аналитик мог повторять одну работу на двух уровнях.** Одна ветка запускала несколько проходов по описи, другая делала два просмотра по разделам. Согласовали выбор режима и добавили проверки числа вызовов. На симуляторе бесплатного тарифа три проверки успешно завершаются как при 10 вызовах в стандартном режиме, так и при девяти с явно заданным одиночным проходом. Это симуляция квоты.
2. **Паспорт отчёта содержал невыполнимую команду.** Рендерер научился принимать пути, но основной CLI их не передавал. Теперь команда `verify` получает относительные пути, с которыми запущен агент. Для абсолютных путей Windows и POSIX в отчёт попадает только имя файла. Добавлена проверка через фактическую запись Markdown.
3. **Отчёт и судья по-разному связывали дубли и требования.** Объединены ссылки по явному ID и пометки о предположении по строке. Сохранены отдельно группировка пожеланий по требованию и присоединение вторичного расхождения с целью документа. Убраны шесть одинаковых определений тестов под одними именами.
4. **Выпуск v1 запускал v2.** Исторические команды тестов и упаковки вызывали CLI без указания движка. Исправлены затронутые вызовы. Семь проверок выпуска прошли и на исходной ветке p18, и после исправления, а более широкий контроль старых команд дал 80/80.
5. **Два журнала измерений переписывали один период.** Сохранены отдельные прогоны обеих веток и последний пересчёт 27 общих строк. Это влияет на сравнение исторических показателей дублей. [Решения по всем 26 конфликтным файлам с учётом повторений](conflicts.md)
