# №04 «Нарезка и реестр требований» — передача

Модуль: `src/bcc_review/analysis/inventory.py`, тесты: `tests/p04/`.
База: `bcc/integration` @ `2821989` (кандидат релиза `f91d3b6`, `release/`; контракт v1 @ `431f76d`). Движок подхватывает
модуль из слота команды: `run.modules.build_inventory = team:bcc_review.analysis.inventory:build_inventory`.

```python
from bcc_review.analysis.inventory import build_inventory
inv = build_inventory(document, ask=None)   # ask(stage, payload, schema) -> dict | None
```

## Что возвращается

| Ключ | Содержимое |
| :--- | :--- |
| `requirements` | атомы: `id` (`R-007` или `R-007.2`), `group` (общий ID исходного пункта), `source_id` (номер из документа или `null`), `source_ref` («Особые правила › 1», «Критерии приемки › строка 2»), `kind`, `text` (пересказ), `block_ids`, `hints`, `evidence`, `section`, `origin` (`rules`, `llm`, `llm_retry`, `rules_fallback`), `review_status: not_reviewed`. Проходит `validate(r, "Requirement")` |
| `fact_hints` | `subject, field, direction (request/response/business), type, value, unit, range{min,max,min_inclusive,max_inclusive}, condition, required, size, values, db_field, hints, evidence, req_ids, origin`; неизвестное = `null` |
| `excluded` | группы `{category, reason, block_ids, cross_check, sections}`; форма `Report.excluded` |
| `unprocessed_block_ids` | явный остаток (предупреждение о нём выдаёт движок, модуль его не дублирует) |
| `warnings` | `{code, message, stage: "inventory", block_ids}` (контрактный `Warning`); `str(w)` даёт «код: сообщение», как и ждёт `engine.py` |
| `block_coverage` | судьба каждого блока (`blocks[]`), уровень `complete/partial`, доля учтённых, вызовы, `evidence_audit` в форме `Run.evidence_audit`, объяснение на русском |

Инвариант: каждый блок попадает ровно в одно из трёх: требование, одна группа исключения, остаток.

## Обязательство и не обязательство

| Что | Судьба | Почему |
| :--- | :--- | :--- |
| Пункт с номером, абзац раздела требований, предложение с «должен/shall» | требование (`functional/nonfunctional/data/integration/ui/contract`) | проверяемое утверждение |
| Строка критерия приёмки, сценарий «Дано/Когда/Тогда» | требование `acceptance` | нужно сквозной сверке (исполнение критерия по правилам) |
| Строка параметра API | один `contract` на параметр, атрибуты — в `fact_hints` | не делать требование из каждой ячейки |
| Метод, URL, авторизация, код ответа | `contract` | обязательство контракта |
| Контроллер, проект, автор, «URL type» | `metadata` | описывает, а не обязывает |
| Цель | `goal` (`cross_check`) | источник трассировки |
| Пример ответа, curl | `example` (`cross_check`) | опора для сверки контракта |
| Архитектура, BPMN, sequence | без модели — остаток, с моделью — `design` или `integration`, если шаг задаёт передачу данных | правила не решают смысл схемы |
| Чек-лист ревью («Да / Нет»), блок согласования (ФИО, подпись) | `review_checklist`, `approval` — жёстко, модели не отдаются | подпись никогда не становится требованием |
| Заголовок, шапка таблицы, разделитель | `structure` | структура |

## Атомарность и ID

* Без модели: деление до предложения (Ф-2 → 4 атома). С моделью: до обязательства (Ф-1 → кто задаёт, целое, нижняя граница, верхняя граница, по умолчанию).
* `source_id` принимается, только если он виден в тексте опоры, в ярлыке строки или в заголовке раздела. Иначе сбрасывается и восстанавливается из текста.
* Пункт = (раздел, номер, блок с номером). Одинаковое «1.» в разных разделах даёт разные группы. Повтор номера в одном разделе — предупреждение `duplicate_source_id`.
* ID зависят только от позиции опор в документе, а не от порядка ответа модели. Вывод совпадает побайтно при любом `PYTHONHASHSEED`.

## Вызов модели

* `ask("inventory", {task: PROMPT, input: {document, window, blocks:[id, section, kind, label, process]}, context}, RESPONSE_SCHEMA)`.
* Короткий документ — одно окно, `context.mode = full` (части A и B вместе), в том числе в повторе. Большой — окна по `window_chars` с перекрытием `overlap_blocks`, `context.mode = blocks`.
* Схема ответа: `items[] {source_id, kind, text, evidence[]}`, `excluded[]`, `facts[]`, `done`. У объектов `additionalProperties: false`, `required` полный. Это проверяет тест.
* Код проверяет: неизвестный блок (ищет цитату в окне и переносит, иначе отклоняет), цитату (дословно, затем с нормализацией пробелов, кавычек, тире и разметки; результат заменяется фрагментом источника), пустую цитату, выдуманный номер, дубль, конфликт «исключён, но цитируется», обрезанный ответ (`done != true`), сбой и `BudgetExhausted`.
* Непокрытые блоки предъявляются модели один раз и только они (`window.mode = retry`). Остаток закрывают правила (`origin: rules_fallback`) или он показывается явно.
* `build_payload(document)` и `python -m bcc_review.analysis.inventory DOC.json --payload` дают самодостаточный payload для ручного прогона промпта.

## Второй проход: реестр на границе двух фрагментов

Вход — `fixtures/card_turnover.md`: К-1 дословно одинаков в «1. Дебетовые карты» и «2. Корпоративные карты»,
только дебетовый раздел следующей строкой («Исключение: возвраты в оборот не включаются.») исключает возвраты;
таблица согласования со строкой-шапкой и пустой подписью. Модель — `WindowContentAdapter` за опубликованным
`runtime.asker.Asker` (`ContextBuilder`, `Budget`): отвечает только по тому, что Asker передал, и меняет порядок выдачи.

* **Дефект прежнего кода (`067f965`).** Модель верно называет строку исключения пунктом «К-1», но проверка номера его
  сбрасывала (номера нет в самом блоке) и подставляла номер заголовка «1». Исключение уходило в отдельную группу и
  теряло связь с дебетовым правилом — одинаково в большом и малом окне. Без модели строка уходила в остаток.
* **Правка.** Блок без своего номера сразу за пронумерованным абзацем того же раздела — продолжение пункта: номер
  принимается из ответа модели, подставляется при `null` и используется правилами. Только прямое соседство,
  без цепочек; код, таблицы и заголовки номер не наследуют. Плюс номер списка из `loc.list.number` (№01 выносит «1.»
  из текста) и точное сообщение о `BudgetExhausted`.
* **Итог.** Большое окно (1 вызов, `context.mode = full`) и малое (3 окна, стык между К-1 и исключением, перекрытие 1)
  дают `R-001.1` К-1 дебет, `R-001.2` исключение (группа `R-001`), `R-002` К-1 корпоративный; повторы из перекрытия
  связаны по координатам (`context_linked = 4`), лишних пунктов нет.
* **Усечение и бюджет** (окна те же, ответ 2 усечён, `max_calls = 2`): модуль обращается к `ask` 3 раза, адаптер — 2,
  повтора нет. Требования: К-1 дебет (`llm`), исключение и К-1 корпоративный (`rules_fallback`, исключение — в группе
  дебетового К-1); исключено: заголовки, вводный абзац, шапка и пустая подпись (`approval`, с причиной); остаток —
  схема.
* **Для №06** — `fixtures/same_number_two_sections.inventory.json`: два одноимённых К-1 и исключение. Ключ пункта —
  (раздел, `source_id`), а не `source_id` и не текст: движок в `normalize_requirements` отбрасывает `group` и `source_ref`.

## Четвёртый проход: критерий приёмки → правило

Вход — `fixtures/acceptance_links.md` (PDF собирается в тесте), путь движка `engine.read_document` → `build_inventory`.

ID блоков одинаковы в MD и PDF; реестры совпадают (9 пар, `compare_registries`).

* **Дефект `fb5007d` (путь с моделью).** Модель кладёт в `source_id` номер, на который критерий ссылается:
  `ДК-2` для АК-1, `ДК-3` для АК-4. Проверка номера принимала любой номер, видимый в тексте блока, поэтому АК-4
  регистрировался как `source_id = "ДК-3"`, `source_ref = "3. Критерии приемки › ДК-3"`. Отсутствующий пункт появлялся
  в реестре, номер АК-4 терялся. Дальше: в `cross.py` критерий получал метку «ДК-3», а в известные номера
  `RULE-ACCEPTANCE-TRACE` попадал ДК-3. АК-1 отклонялся как «опирается только на блоки другого пункта», шёл повтор
  (2 вызова вместо 1), критерий возвращался откатом `rules_fallback`.
* **Правка.** Номер, упомянутый в тексте блока со своим другим номером, — ссылка. В строке таблицы номер задаёт
  колонка ID. В прозе номер в начале предложения с «.» или «:» — номер слитого пункта, он принимается как раньше.
  Ссылка не включает перенос опоры в блок того пункта и отказ «чужой пункт». `source_id` берётся из собственного
  номера блока, предупреждение — `source_id_reference`. Промпт и путь без модели не менялись.
* **Итог.** С ошибочным ответом модели реестр совпадает с реестром при верном ответе: АК-1…АК-4, `origin = llm`,
  1 вызов, ДК-3 нигде не зарегистрирован. Через `run_review` движок отдаёт №05/№06 `R-005…R-008` с `source_id`
  АК-1…АК-4.
* **Для №05 и №06** — `fixtures/acceptance_links.inventory.json`: реестр, `expected_links` (критерий, блок, цитата,
  исход, цели `{source_id, req_id}`, отсутствующие номера) и `not_a_criterion`. Тест держит файл актуальным.
