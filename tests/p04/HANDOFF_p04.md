Модуль: `src/bcc_review/analysis/inventory.py`, тесты: `tests/p04/`.
База: `bcc/integration` @ `3e6b569` (контракт v1 @ `431f76d`).

```python
from bcc_review.analysis.inventory import build_inventory
inv = build_inventory(document, ask=None)   # ask(stage, payload, schema) -> dict | None
```

## Что возвращается

| Ключ | Содержимое |
| :--- | :--- |
| `requirements` | атомы: `id` (`R-007` или `R-007.2`), `group` (общий ID исходного пункта), `source_id` (номер из документа или `null`), `source_ref` («Особые правила › 1», «Критерии приемки › строка 2»), `kind`, `text` (пересказ), `block_ids`, `hints`, `evidence`, `section`, `origin` (`rules`, `llm`, `llm_retry`, `rules_fallback`), `review_status: not_reviewed`. Проходит `validate(r, "Requirement")` |
| `fact_hints` | `subject, field, direction (request/response/business), type, value, unit, range{min,max,min_inclusive,max_inclusive}, condition, required, size, values, db_field, hints, evidence, req_ids, origin`; неизвестное = `null` |
| `excluded` | группы `{category, reason, block_ids, cross_check, sections}`; форма `Report.excluded` |
| `unprocessed_block_ids` | явный остаток |
| `warnings` | `{code, message, stage: "inventory", block_ids}` (контрактный `Warning`) |
| `block_coverage` | судьба каждого блока (`blocks[]`), уровень `complete/partial`, доля учтённых, вызовы, `evidence_audit` в форме `Run.evidence_audit`, объяснение на русском |

Инвариант: каждый блок попадает ровно в одно из трёх: требование, одна группа исключения, остаток.

## Обязательство и не обязательство

| Что | Судьба | Почему |
| :--- | :--- | :--- |
| Пункт с номером, абзац раздела требований, предложение с «должен/shall» | требование (`functional/nonfunctional/data/integration/ui/contract`) | проверяемое утверждение |
| Строка критерия приёмки, сценарий «Дано/Когда/Тогда» | требование `acceptance` | нужно сквозной сверке (исполнение критерия по правилам) |
| Строка параметра API | один `contract` на параметр, атрибуты — в `fact_hints` | не делать требование из каждой ячейки |
| Метод, URL, авторизация, код ответа | `contract` | обязательство контракта |
| Контроллер, проект, автор, «URL type» | `metadata` | описывает, а не обязывает |
| Цель | `goal` (`cross_check`) | источник трассировки |
| Пример ответа, curl | `example` (`cross_check`) | опора для сверки контракта |
| Архитектура, BPMN, sequence | без модели — остаток, с моделью — `design` или `integration`, если шаг задаёт передачу данных | правила не решают смысл схемы |
| Чек-лист ревью («Да / Нет»), блок согласования (ФИО, подпись) | `review_checklist`, `approval` — жёстко, модели не отдаются | подпись никогда не становится требованием |
| Заголовок, шапка таблицы, разделитель | `structure` | структура |

## Атомарность и ID

* Без модели: деление до предложения (Ф-2 → 4 атома). С моделью: до обязательства (Ф-1 → кто задаёт, целое, нижняя граница, верхняя граница, по умолчанию).
* `source_id` принимается, только если он виден в тексте опоры, в ярлыке строки или в заголовке раздела. Иначе сбрасывается и восстанавливается из текста.
* Пункт = (раздел, номер, блок с номером). Одинаковое «1.» в разных разделах даёт разные группы. Повтор номера в одном разделе — предупреждение `duplicate_source_id`.
* ID зависят только от позиции опор в документе, а не от порядка ответа модели. Вывод совпадает побайтно при любом `PYTHONHASHSEED`.

## Вызов модели

* `ask("inventory", {task: PROMPT, input: {document, window, blocks:[id, section, kind, label, process]}, context}, RESPONSE_SCHEMA)`.
* Короткий документ — одно окно, `context.mode = full` (части A и B вместе), в том числе в повторе. Большой — окна по `window_chars` с перекрытием `overlap_blocks`, `context.mode = blocks`.
* Схема ответа: `items[] {source_id, kind, text, evidence[]}`, `excluded[]`, `facts[]`, `done`. У объектов `additionalProperties: false`, `required` полный. Это проверяет тест.
* Код проверяет: неизвестный блок (ищет цитату в окне и переносит, иначе отклоняет), цитату (дословно, затем с нормализацией пробелов, кавычек, тире и разметки; результат заменяется фрагментом источника), пустую цитату, выдуманный номер, дубль, конфликт «исключён, но цитируется», обрезанный ответ (`done != true`), сбой и `BudgetExhausted`.
* Непокрытые блоки предъявляются модели один раз и только они (`window.mode = retry`). Остаток закрывают правила (`origin: rules_fallback`) или он показывается явно.
* `build_payload(document)` и `python -m bcc_review.analysis.inventory DOC.json --payload` дают самодостаточный payload для ручного прогона промпта.

* **№01/02/03:** номер пункта оставляйте в `block.text` («1. …», «Ф-1. …») или в `loc.marker`. Без него `source_id` теряется. Снятие `**` и `|` из текста не мешает — это проверено тестом.
* **№05:** фильтруйте по `kind`. `acceptance` и `contract` удобнее проверять отдельными критериями.
* **№06:** `fact_hints` уже связаны с требованиями (`req_ids`). Тип `amount` в запросе integer, в ответе string, `db_field` общий; тиын и тенге — в `unit`. Описания 401, 403, 500 стоят под заголовком «200. Successful — Created», это видно в `source_ref`.
* **№07:** `hints` уже дословны, `evidence` посчитан; `context` — строка, где цитата встречается один раз.
