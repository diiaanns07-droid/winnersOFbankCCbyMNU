# №13 · Автономный HTML-отчёт

`write_html(report, output_path) -> Path` собирает из канонического Report один `.html`.
Файл открывается с диска без сети и сервера. CSP `default-src 'none'` и хеши встроенных стилей и
кода запрещают любые запросы и чужие скрипты.

Код: `src/bcc_review/exports/html.py`, `src/bcc_review/exports/html_assets/{report.css,report.js}`.
Тесты и фикстуры: `tests/p13/`.

```bash
python -m pytest tests/contract tests/p13 -q
```

```bash
PYTHONPATH=src python -m bcc_review.exports.html tests/p13/fixtures/synthetic_report.json /tmp/report.html
```

```bash
python tests/p13/make_samples.py
```

Браузерная часть (`test_html_browser.py`) запускает `browser/check_report.cjs` через Node Playwright.
Если нет `node` или пакета `playwright`, она пропускается. Python-пакет playwright не нужен.

## Что видит аналитик

1. **Итог.** Вердикт отдельно для разработки и для тестирования, «Что сделать первым», решения и сводка.
   При неполном прогоне показан баннер, у вердикта пометка «предварительно».
2. **Ревью.** Слева исходный документ: каждый блок с ID, строками или страницей и числом замечаний.
   Справа карточки замечаний с фильтрами по серьёзности, критерию, статусу и тексту.
   - Конфликт: вход, исходы A и B, по кликабельной цитате с контекстом у каждой стороны.
   - Остальные замечания: основание, последствие, источник, уточняющий вопрос, как исправить.
   - Клик по цитате переходит к точному вхождению. В шапке документа есть «Предыдущая / Следующая
     цитата» и «Вернуться к замечанию». Escape и кнопка «Назад» браузера возвращают фокус на ту же
     цитату, выбор замечания сохраняется.
   - Клик по подсветке в документе выбирает замечание. Если фрагмент общий, открывается список.
     Клавиатурный путь — кнопка «N замечаний» у блока.
   - Узкое окно (< 1000 px): переключатель «Замечания / Документ», без горизонтальной прокрутки
     страницы. Длинные таблицы прокручиваются внутри блока.
3. Разделы `#requirements`, `#questions` (черновики ответов), `#checklist`, `#coverage`,
   `#diff`, `#test-cases`, `#facts`, `#run` (паспорт, аудит опор, самопроверка подсветки).

Серьёзность передаётся не только цветом: ▲/◆/● и текст «Критичное / Существенное / Незначительное»,
у подсветки сплошная, пунктирная или точечная линия, у сторон конфликта метки A/B.

## Якоря (для №15 и Markdown)

| Объект | Якорь | Функция |
| :--- | :--- | :--- |
| замечание | `#finding-<slug(id)>` | `finding_anchor(id)` |
| блок документа | `#block-<slug(id)>` | `block_anchor(id)` |
| вопрос | `#question-<slug(id)>` | `question_anchor(id)` |
| требование | `#req-<slug(id)>` | `requirement_anchor(id)` |

`slug` оставляет `A–Z a–z 0–9 . -` как есть, любой другой символ (включая `_`) кодирует как `_<hex>_`.
`F-001` → `finding-F-001`, `b0012` → `block-b0012`, `Ф-1` → `_424_-1`. Отображение однозначное. Ссылку
`report.html#finding-F-001` можно давать из Markdown и веб-интерфейса. Открытие по такой ссылке
выбирает замечание и прокручивает документ к его опоре, `#block-…` прокручивает к блоку.

## Координаты и подсветка

* Контракт хранит позиции в кодовых точках Unicode, JS индексирует строки в UTF-16. Текст режется на
  сегменты в Python, где индексы совпадают с контрактом, поэтому браузеру пересчитывать нечего.
  Каждый сегмент несёт `data-ev` (все покрывающие опоры) и `data-cp="start:end"`.
* Опора подсвечивается, только если `block.text[start:end] == quote`. Иначе в карточке появляется
  «⚠ Опора не подтверждена: причина» со ссылкой на блок.
* Перекрытия: сегмент хранит все опоры, `data-n` равно числу замечаний. Одинаковые цитаты в разных
  блоках и повторы внутри блока различаются по `block_id` и `start`, поиска по тексту нет.
* `\r` выводится как `&#13;`: иначе HTML-парсер превратит CRLF в LF. U+0000 и одиночные суррогаты
  заменяются на U+FFFD (1:1), об этом есть предупреждение в паспорте.
* Самопроверка в браузере: склеенный текст сегментов и `Array.from(blockText).slice(s, e)` должны
  совпасть с `quote` у всех опор. Результат выводится в `#dom-check`.
* `window.bccReview.cpToUtf16(text, cp)` — помощник для №15, если подсветку строит живое приложение.

Сравнение на маленьком примере (`🔔 👨‍👩‍👧 Порог\r\n<b>50 000 ₸</b> …`, цитата в кодовых точках 15–30):
наивный `text.slice(15, 30)` в JS дал `"ог\r\n<b>50 000 ₸"` (неверно); перевод в UTF-16 — верно;
нарезка в Python — верно, и весь текст блока совпал. Сырой `\r` парсер нормализует, `&#13;` — нет.

## Что принимается на вход

Report контракта v1 (`contracts/v1.json`, коммит `431f76d`): `dict`, pydantic-модель
(`model_dump`), объект с `to_dict()`, dataclass или путь к JSON. Поля читаются мягко: недостающие
разделы показывают пустое состояние, а не падение. Что используется:

* `block.loc`: `line_start/line_end` и `map` дают точную строку цитаты: строка вычисляется по
  `map` и числу `\n` до `start`. `page` даёт разделители «Страница N» и `стр. N`, `path` и `part`
  выводятся для DOCX. С `write_html(..., pdf_href="x.pdf")` у блоков появляется ссылка
  `x.pdf#page=N` на артефакт №14.
* `kind` блока: `table_header` и `table_row` выводятся моноширинным шрифтом с прокруткой внутри
  блока. Блоки из `excluded[]` помечены «исключён из проверки», блоки из
  `document.warnings[].block_ids` — кодом предупреждения чтения.
* `finding`: `witness` (вход, исходы A/B, две кликабельные цитаты), `cause`, `anchor_status`,
  `meaning_status`/`meaning_reason`, `impact`, `blocked_decision`, `blocks[]` (метки «блокирует
  разработку/тестирование» и фильтр), `recommendation`, `hints` (показаны как подсказки без
  координат), `inspected_block_ids`, `merged_from`, `source`/`stage`, `notes`.
* `verdict.development/testing` — `Readiness{status, reasons, finding_ids}`, `first_actions`
  сортируются по `order`, `basis` идёт под плитками.
* `diff`: три статуса старых замечаний — `resolved` «Исправлено», `persisting` «Осталось»,
  `unassessed` «Не оценено» — и отдельный список `introduced` «Новые замечания». `old_ids`
  выводятся текстом (это ID прошлого отчёта), `new_ids` — ссылками, `evidence` — кликабельными
  цитатами.
* `checklist` (`available/checked`: yes/no/na/unknown → Да/Нет/Не требуется/Не определено),
  `coverage[]`, `checks[]`, `facts[]`, `test_cases[]`: таблицы. Поля `*_id(s)` становятся ссылками,
  опоры внутри подсвечиваются.
* `run`: `calls{physical, cache_hits, failed, retries}`, `tokens`, `budget`, `stages[]`,
  `incomplete_stages`, `status_reasons`, `modules`, `evidence_audit` — в паспорте. При
  `status != complete` наверху появляется баннер, у вердикта пометка «предварительно».
  `rejected[]` выводится раскрывающимся списком.
* Подписи критериев: встроенные русские для кодов контракта (`unambiguous` → «Однозначность»,
  `set_consistent` → «Согласованность набора» и т. д.), затем `src/bcc_review/criteria.toml` №05
  (ключи `name_ru|name|title|label` с кириллицей), затем `report.criteria`.

## Ответы: черновик в браузере и `--answers` (для №08)

* Черновик хранится в `localStorage` под ключом `bcc-review/answers/v1/<document.id>`
  (`{format: "bcc-review-answers-draft/1", document_sha256, saved_at, answers}`). Другая версия
  документа с другим хешем черновик не видит.
* Черновик не меняет документ, вердикт и статусы. Об этом сказано у вопросов и в статусе
  восстановления. Ответы, уже учтённые прогоном (`decisions[]` с `source_sha256` текущего
  документа), показаны отдельно с пометкой «учтён при этом прогоне». Предложенные `edits`
  помечены «в исходный документ не внесены». Decision с чужим `source_sha256` выделен как «ответ дан
  к другой версии документа» и открытым вопросом не считается закрытым.
* `options` вопроса — кнопки, которые вставляют вариант в черновик.
* Без хранилища (приватный режим, запрет сайта) выводится предупреждение, а ответы всё равно
  выгружаются в `.md` (Blob) или копируются из поля «Показать Markdown».
* Формат файла (`answers_markdown`/`parse_answers_markdown` в `html.py`, JS строит тот же текст
  байт в байт, это проверяет `test_exported_answers_match_python_format`):

```markdown
---
format: bcc-review-answers/1
source_sha256: <64 hex = document.id>
document_title: …
report_run_id: …
report_agent_version: …
exported_at: 2026-11-26T12:00:00.000Z
---

# Ответы на уточняющие вопросы

## Q-01

> текст вопроса (prompt)

Варианты: Да, после изменения порога | Нет, не более одного push в месяц

Замечания: F-001

### Ответ

текст ответа (строки, начинающиеся с # или \, экранируются ведущим \)
```

Соответствие для `parse_answers(path, document) -> list[Decision]` №08: `question_id` берётся из
заголовка `## <id>`, `source_sha256` — из шапки, `answer` — из текста после `### Ответ`, `edits`
остаются пустыми. Пустой ответ означает «нет ответа». Если `source_sha256` не совпадает с хешем
входного файла, ответы относятся к другой редакции: №08 стоит предупредить, а не применять молча.
Пустой черновик при выгрузке заменяется ответом, уже учтённым прогоном, поэтому повторный запуск
его не теряет.
