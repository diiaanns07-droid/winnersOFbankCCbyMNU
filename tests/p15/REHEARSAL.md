# Репетиция показа веб-демо (для №18)

Цель — за 3 минуты показать жюри путь аналитика на настоящем движке и уметь переключиться
на сохранённый прогон, если сеть или ключ подведут.

## Демо пути аналитика: команда и последовательность (проверено на bcc/integration 2821989)

Вход — публичный кейс `release/input/requirements.md` (= `tests/p15/fixtures/case_ab.md`, SHA-256
`e7dae55e…`). Ответы модели воспроизводятся из записанного сценария
`tests/p15/fixtures/mock_case_recorded.json` (ответы транспорта №06, `tests/p15/record_mock_case.py`);
живая модель не вызывается, ключ не нужен. Режим показан в шапке и в вердикте.

```bash
python -m bcc_review.web --provider mock --mock-script tests/p15/fixtures/mock_case_recorded.json --export html,pdf --demo-answers tests/p15/fixtures/demo_answers.md
```

1. <http://127.0.0.1:8015/> → «Загрузить ТЗ» → `release/input/requirements.md`. Видны этапы движка;
   обновите страницу (F5) посреди прогона — статус и пройденные этапы сохраняются.
2. После `готово частично partial` (в сценарии нет ответов этапа `individual`, это честно указано)
   откройте вопрос **Q-01** → ссылка **F-002**: две цитаты, строка 38 (Ф-2) и строка 64 (критерий №2).
3. У Q-01 нажмите «Подставить демонстрационный ответ»: заполнятся ответ и «Новая формулировка»;
   над полем видно предложение, которое движок заменит. → «Подтвердить новую редакцию и перепроверить».
4. Редакция 2: блок «Изменённые пункты» — было «В расходы входят проведённые покупки.» → стало
   «…; месяц покупки определяется по дате её совершения (Asia/Almaty, UTC+5).», пункт Ф-2 целиком.
5. «Файлы запуска»: `report.md`, `report.html` (№13), `report.annotated.pdf` (№14), файл редакции
   `case_ab.rev-….md` — его SHA-256 равен версии документа редакции 2.
6. Откройте прежнюю ссылку на редакцию 1: сверху пометка «не актуальная» и ссылка на редакцию 2;
   статус, вопросы и `questions.md` — версии 1.

Автоматически, с кадрами и видео:

```bash
python tests/p15/demo_run.py --out out/p15-demo
```

## 1. Репетиция полного пути без ключа (настоящий движок, mock-провайдер)

```bash
python -m bcc_review.web --provider mock --mock-script tests/p15/fixtures/mock_case_web.json --demo-answers tests/p15/fixtures/demo_answers.md --data-dir .bcc_web_rehearsal
```

Загрузить `tests/p15/fixtures/case_ab.md`. Ожидается: `готово частично partial` (в ветке
пока нет модуля правил и №05), вердикт «нельзя начинать», вопрос Q-001 о Ф-3/Ф-4,
«Подставить демонстрационный ответ» заполняет ответ и правку текста. После
«Подтвердить…» в редакции 2 видны этап «учёт ответов: применено правок: 1», файл
`case_ab.rev-….md` в «Файлах запуска», блок «Решения, учтённые движком (1)» и сравнение.
Отчёт помечен «mock: синтетические ответы модели»: жюри его как живой анализ не показывать.

## 2. Живой прогон и сохранение запасного варианта

```bash
python -m bcc_review.web --provider gemini --demo-answers tests/p15/fixtures/demo_answers.md
```

1. <http://127.0.0.1:8015/> → «Загрузить ТЗ» → `tests/p15/fixtures/case_ab.md` (или PDF-версия от организаторов).
2. В шапке должна быть строка `Движок: bcc_review:run_review` и «ключ … найден». Если там
   «ключ не найден», прогон будет `rules_only`, и страница честно напишет «Отчёт неполный».
3. Дождаться `готово complete`. Записать измеренную длительность из блока «Статус»: только её
   можно называть жюри («обычно N минут»).
4. Ответить на вопрос о Ф-3/Ф-4 кнопкой «Подставить демонстрационный ответ» (видна подпись
   «не решение банка»; вместе с ответом заполняется «Правка текста ТЗ») или выбрать вариант движка
   и вписать правку → «Подтвердить новую редакцию и перепроверить». Без правки документ не меняется,
   и замечание останется.
5. Дождаться второй редакции и проверить блоки «Сравнение с редакцией 1» и «Что ещё требует внимания».
6. Сохранить обе редакции для резервного показа (run_id — из адресной строки второй редакции):

```bash
python -m bcc_review.web pack <run_id редакции 2> --out demo_bundle
```

## 3. Сценарий показа (3 минуты)

| Время | Действие | Что сказать / что видно |
| :--- | :--- | :--- |
| 0:00 | главная: одна кнопка «Загрузить ТЗ» | вход — тот же файл, что у CLI |
| 0:10 | загрузка PDF/MD | этапы движка появляются по мере работы; страницу можно перезагрузить |
| 0:40 | вердикт | «Разработка: нельзя начинать», «Тестирование: нельзя начинать», первые действия со ссылками |
| 1:00 | критичное замечание о конфликте | два фрагмента А и Б с подсветкой, строка и раздел, сценарий-свидетель |
| 1:30 | ответ на вопрос | происхождение ответа подписано; повторный клик не запускает второй анализ |
| 2:00 | редакция 2 | устранено N, осталось M, «Что ещё требует внимания» |
| 2:30 | «Открыть сравнение», «Файлы запуска» | report.md / report.json / report.html (№13) — реальные файлы этого run_id |

## 4. Если что-то пошло не так

* Нет сети или провайдер упал: страница покажет причину и кнопку «Проверить только по правилам».
  Режим и неполнота отчёта будут видны.
* Показ без сети: остановить сервер и запустить его с сохранённым прогоном. Страницы
  `/demo/…` помечены датой и моделью прогона, новых анализов в этом режиме нет.

```bash
python -m bcc_review.web --demo demo_bundle
```

* UI без движка (только репетиция интерфейса): все отчёты помечены mock.

```bash
python -m bcc_review.web --engine dev --demo-answers tests/p15/fixtures/demo_answers.md
```


Путь на настоящем движке с mock-провайдером, без браузера:

```bash
python -m pytest tests/p15/test_contract_junction.py
```

Проходит в Chromium: загрузка → вердикт → два фрагмента → демо-ответ и вариант решения →
двойной клик «Подтвердить» (ровно один дочерний запуск) → сравнение → скачивание
report.md и questions.md → перезагрузка страницы во время прогона → «нет ключа» → проверка
по правилам. Скриншоты шагов — в `out/p15/`.
