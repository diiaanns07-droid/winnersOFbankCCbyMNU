# №02 · Чтение PDF и координаты текста — передача

Точка входа по `contracts/HANDOFF.md`: `bcc_review.readers.pdf:read_pdf(path) -> Document`
(dict контракта v1, проходит `validate(doc, "Document")`). Зависимость — `pymupdf>=1.24`
(экстра `pdf` в `pyproject.toml`), только CPU. Проверено на PyMuPDF **1.26.5** и **2.2**.

```bash
pip install -e ".[pdf,dev]"
python -m pytest tests/contract tests/p02 -q
python -m bcc_review.readers.pdf tests/p02/fixtures/p02_scan_mixed.pdf --diagnose --ocr off
```

## Почему PyMuPDF

`python tests/p02/compare_libs.py` на фикстуре (кириллица, ₸, перенос, таблица, две колонки):

| Библиотека | Кириллица и ₸ (9 из 9) | Колонки по порядку | Таблица | Рамка слова «составляет» |
| :--- | :--- | :--- | :--- | :--- |
| pypdf (читалка zerde) | да | да | нет API | нет координат |
| pdfplumber / pdfminer | да | **нет**, строки колонок перемешаны | да | 175.94, 169.22, 238.25, 179.72 |
| pypdfium2 (просмотр RAG) | да | да | нет API | 176.40, 171.31, 237.77, 177.33 (по глифу, уже строки); перенос даёт `U+FFFE` |
| **PyMuPDF** | да | порядок задаёт читалка | да | 175.94, 169.22, 238.26, 179.72 |

От zerde взяты детектор «латинской каши» вместо кириллицы и OCR как запасной путь. В RAG-просмотре
цитату ищут на странице заново через `text.search(query)`. Здесь от этого отказались: координаты
идут из тех же символов, что и `block.text`, поэтому цитату угадывать не нужно.
PyMuPDF отдаёт координаты неповёрнутой страницы, `add_highlight_annot` принимает те же числа
(проверено на 1.26.5 и 2.2, в том числе со смещённым CropBox). Лицензия PyMuPDF — AGPL или коммерческая.
Если это неприемлемо, запасной вариант — pypdfium2: там нужно пересчитывать ось y и не хватает таблиц.

## Карта Page/fragment для №07 и №14

```text
block = {id: "b0017", kind, section, text, loc}
loc.page          номер страницы с 1
loc.fragments[]   {start, end, rect:[x0,y0,x1,y1], line, dir?, quad?, hyphen?}
                  block.text[start:end] — слово или знак препинания; rect — пункты неповёрнутой
                  страницы PyMuPDF (начало — левый верхний угол CropBox, y вниз); line — визуальная строка
loc.bbox          охват всех фрагментов
loc.rotation      /Rotate страницы, если не 0
loc.table         у table_header/table_row: {id, part, row, header_row, header[], columns[]?, header_source,
                  header_restored, cells:[{col, colspan, start, end, rect}], repeated_header?,
                  link?, adjacent_to?, maybe_continues?}; columns = header, движок кладёт его в loc.columns
                  (cells[].rect — рамка find_tables, внешний край бывает обрезан по тексту; подсветка — по fragments)
loc.level         уровень заголовка; loc.ocr — текст из OCR; loc.furniture — колонтитул (kind "other")
loc.continues / loc.continued_from — абзац продолжается в следующем блоке (колонка или страница)
```

Перевод `Evidence{block_id,start,end}` в прямоугольники:

```python
from bcc_review.readers.pdf import read_pdf, locate_span
doc = read_pdf("spec.pdf")
block = next(b for b in doc["blocks"] if b["id"] == ev["block_id"])
where = locate_span(block, ev["start"], ev["end"])
# {"block_id", "page", "rects": [[x0,y0,x1,y1], ...], "quads"?, "precision": exact|approx|page, "warning"}
page = pymupdf.open("spec.pdf")[where["page"] - 1]
for r in where["rects"]:
    page.add_highlight_annot(pymupdf.Rect(r))     # без пересчёта, на повёрнутой странице тоже
```

* Для каждой визуальной строки возвращается один прямоугольник: соседние слова строки объединяются вместе с пробелом между ними.
  `exact` означает, что границы опоры совпали с границами фрагментов (по словам и знакам препинания).
  `approx` — опора режет слово, и часть слова отмерена пропорционально числу букв.
* `locate(document, evidence)` из №07 отдаёт рамки тех же фрагментов по отдельности, без объединения по строкам. Оба
  варианта совместимы (стык проверен, см. ниже).
* Перенос «согла-/сования»: в тексте стоит «согласования», рамка «согла» захватывает дефис, «сования» лежит на
  следующей строке. Составное слово («push-/уведомление», `--/data`) склеивается с дефисом и без пробела.
* В тексте пробелы и NBSP приведены к одному пробелу, лигатуры разложены (ﬁ → fi), `и + ̆` склеено в «й».

**Пример с повёрнутой страницей** (`fixtures/p02_rotated_text.pdf`: /Rotate 90, текст написан поперёк
MediaBox, читатель видит обычную книжную страницу):

```json
{"block": {"id": "b0002", "text": "Порог уведомления составляет 90 000 ₸ на повёрнутой странице."},
 "fragment": {"start": 32, "end": 35, "rect": [91.24, 322.94, 101.74, 342.98], "line": 0, "dir": [0.0, -1.0]},
 "locate_span('90 000 ₸')": {"page": 1, "rects": [[91.24, 312.93, 101.74, 359.67]], "precision": "exact"},
 "для показа: Rect * page.rotation_matrix": [235.61, 91.24, 282.35, 101.74]}
```

В неповёрнутой системе рамка вытянута по вертикали, после `rotation_matrix` — горизонтальная. Подсветка через
`add_highlight_annot(rect)` после повторного открытия накрывает слова `90`, `000`, `₸` (тест
`test_text_across_mediabox_on_rotated_page`). Для страницы, повёрнутой без изменения содержимого
(`p02_rotated90.pdf`), координаты совпадают с неповёрнутым оригиналом.

**Когда известна только страница** (нет фрагментов: например, внешний reader или OCR без рамок):

```json
{"block_id": "b0007", "page": 3, "rects": [], "precision": "page",
 "warning": {"code": "locate_page_only", "stage": "read_pdf", "severity": "warning", "page": 3, "block_id": "b0007",
             "message": "Цитата «Порог уведомления составляет» из блока b0007 привязана только к странице 3: координаты слов недоступны, подсветка показывает страницу целиком."}}
```

## Полнота извлечения (для Max) и диагностика (для №18)

`Document.extraction` — поле сверх обязательных; схема Document разрешает дополнительные поля:

```text
{reader, engine, pages, content_pages, completeness: 0..1, pages_status: {"2": "scan", ...},
 pages_unread, pages_ocr, pages_blank, tables: [{id, pages, parts, header_restored, links?, adjacent_to?,
 maybe_continues?}], method}
```

`completeness` — среднее по непустым страницам. Текстовая страница даёт 1, скан, нечитаемый шрифт и текст
кривыми — 0. У смешанной страницы это площадь текста / (площадь текста + площадь изображений без текста).
Предупреждения: `{code, message, stage: "read_pdf", severity, page?}` плюс поля по смыслу; `page` (целое ≥ 1, как
требует контракт с 6be9e97) есть только у предупреждений конкретной страницы.

| Ситуация | code (контракт) | Чем кончается |
| :--- | :--- | :--- |
| страница — скан, OCR нет | `ocr_required` | блоков страницы нет, полнота < 1 |
| страница из одних кривых | `unreadable_page` | то же |
| шрифт без ToUnicode | `decode_error` (error) | «каша» не попадает в блоки |
| отдельные глифы без кодировки (например, ₸) | `decode_error` (warning) | текст с `�` и номер страницы |
| картинка без текста ≥ 15% площади | `partial_read` с номером страницы | оценка полноты страницы |
| итог при полноте < 1 | `partial_read` без `page`, с `pages` и `completeness` | прогон `partial`, готовность не `ready` |
| полностью скан или пустой PDF | то же, блоков 0, полнота 0 | `Document`, а не исключение |
| OCR применён | `page_ocr` (warning) | `loc.ocr = true`, сверка цитат |
| не PDF / повреждён / пароль | исключение `PdfReadError(code)` | `diagnostic` готов к показу |
| прочее | `empty_page`, `pdf_encrypted_owner`, `pdf_repaired`, `page_text_over_image`, `table_unreliable`, `table_rotated_text`, `layout_grid_unreliable`, `table_continuation_unmatched`, `table_continuation_uncertain`, `table_header_unmapped` | не меняет полноту |

`diagnose_pdf(path)` никогда не бросает исключений. Он возвращает
`{ok, code: complete|partial|no_text|not_pdf|damaged|encrypted, message, pages, extraction, warnings}`.
Пример для `p02_scan_mixed.pdf --ocr off` (код выхода 5):

> Текст извлечён не полностью: оценка полноты 65%; не прочитаны страницы 2, 4. Выводы о готовности по ним
> невозможны. Страница 2: нет текстового слоя, страница — изображение (скан); текст страницы не извлечён и не
> проверялся. OCR отключён параметром. Страница 4: 18% площади — изображение без текстового слоя; его
> содержимое не проверялось.

OCR работает только как дополнение: `read_pdf(..., ocr="auto")` включает его, если PyMuPDF видит tessdata rus/eng
(на Debian/Ubuntu: `apt-get install tesseract-ocr-rus tesseract-ocr-eng`). `ocr="off"` отключает OCR. Базовый путь
OCR не требует.

## Таблицы

Таблицы с линейками (`find_tables`) переходят в блоки `table_header`/`table_row` с текстом `ячейка | ячейка`. Связь
со строкой и колонкой принимается, только если каждый символ однозначно попал в одну ячейку и не пересекает её линию.
Иначе сохраняются исходные блоки и выдаётся `table_unreliable`. Выровненный текст без линеек остаётся блоками в
построчном порядке с `layout_grid_unreliable`. Объединённые ячейки шапки разворачиваются в имена колонок:
`["Сценарий", "Сумма, ₸ / до", "Сумма, ₸ / после"]`.

**Многостраничные таблицы.** Кандидат в продолжение — таблица первой на странице, если прошлая страница кончается
таблицей с тем же числом колонок и теми же внутренними границами (±3 pt). Одной сетки мало: две разные таблицы бывают
одной ширины. Поэтому решает видимое оформление первой строки и шапки прошлой части (`_continuation`):

| Первая строка на новой странице | `link` | Итог |
| :--- | :--- | :--- |
| повторяет шапку прошлой части | `repeated_header` | тот же `id`, `part + 1`, `repeated_header`, нумерация `row` сквозная |
| жирная (как шапка), текст другой | `new_header` | новая таблица со своей шапкой, `adjacent_to` — соседняя |
| обычная, а шапка прошлой части выделена | `header_carried` | тот же `id`, шапка с прошлой части (`header_source: "page N"`) |
| оформлением не различить (шапка не выделена) | `uncertain` | новая таблица без `header`/`columns`, `maybe_continues`, предупреждение `table_continuation_uncertain` с `pages`; значения, страница и координаты сохраняются |

Восстановлено ли соответствие, видно по `header_restored` у каждой строки и в `extraction.tables[]`. На фикстуре и
кейсе все настоящие продолжения восстановлены: T2 (стр. 3–4, повтор), T3 (стр. 4–5, без повтора), чек-лист кейса
(стр. 3–4), таблица ответа (стр. 5–6).

**Пара для №14** (проверяется повторным чтением, без рендера): `b0020`, `[23, 31)`, стр. 2,
`[405.0, 66.02, 451.75, 76.52]` → `page.get_text("words", clip=rect)` = `['50', '000', '₸']`; эталон генератора
`[405.0, 66.02, 451.76, 76.52]`. Повторное чтение лучше вести по центрам слов: в командной копии (шрифт CharisSIL)
рамки глифов выше шага строк, соседние строки перекрываются примерно на 3,5 pt, и `clip` захватывает слово строкой выше.

**Без надёжных координат.** `locate_span` по разделителю ячеек ` | ` или по блоку без `fragments` (скан, чужой reader)
даёт `precision: "page"`, `rects: []` и предупреждение `locate_page_only` с `page` и `block_id`. Опора, режущая слово
(«0 00»), даёт `precision: "approx"` без предупреждения: часть слова отмерена пропорционально числу букв.

| :--- | :--- | :--- | :--- |
| строка 13 на стр. 2 | три абзаца «13», «Покупка техники», «50 000 ₸», без таблицы | T1, строка 13 | T1, строка 13 (обе версии) |

* PyMuPDF 2.x не находит таблицу из одной строки. Читалка сама собирает сетку из видимых линеек (`_ruled_grids`:
  полосы между горизонталями одной длины, закрытые вертикалями, не меньше двух колонок, вне таблиц `find_tables`);
  дальше она проходит прежнюю проверку символов и решение о продолжении. У таких строк `loc.table.source = "ruled_lines"`.
* PyMuPDF помечает шапку «внешней», если над таблицей жирный заголовок, а во второй строке есть жирный текст
  (жирные ключи) и нет заливки. Если первая строка таблицы жирная, а данные — нет, шапкой считается она.

## Порядок чтения

Порядок строится в системе основного направления строк страницы. Обычная страница и страница, повёрнутая через
/Rotate, читаются как оригинал; текст поперёк MediaBox поворачивается так, как его видит читатель. Дальше работает
рекурсивный XY-разрез. Колонки читаются слева направо. Горизонтальный разрез внутри колонок запрещён, но разрешён
перед заголовком. Колонтитулы (повтор в верхних/нижних 9% страницы, номера «N/M», «Стр. N») становятся блоками
`kind: "other"` с `loc.furniture: true`, а `section` у них пустой. Строки склеиваются в абзац, только если

## Открытые вопросы и следующий получатель

* **Max**: (1) учитывать `extraction.completeness` в `run.status`. Коды из `PARTIAL_READ_CODES` уже стоят.
  (2) Решить, делать ли прогон `partial` при `page_ocr`. Сейчас OCR не снижает полноту, а только предупреждает.
  (3) Экстра `pdf = ["pymupdf>=1.24"]`: PyMuPDF 2.x тянет `onnxruntime`, `networkx`, `pymupdf-layout`.
  Для лёгкой установки на CPU предлагаю `pymupdf>=1.24,<2`, и на 1.26.5 всё проходит. Решение за владельцем `pyproject.toml`.
* **№07**: блоки, разорванные колонкой или страницей, связаны `loc.continues`/`continued_from`. Цитату через границу можно
  собрать из двух опор. Для подсветки по строкам можно вызывать `locate_span`.
* **№14**: `locate_span` и `add_highlight_annot(rect)` работают без пересчёта, на повёрнутых страницах тоже.
  `quads` есть только у наклонного текста.
* **№18**: `diagnose_pdf` / `python -m bcc_review.readers.pdf FILE --diagnose` выдают сообщение на русском
  и коды выхода 0 / 5 (partial) / 1 (нет текста или файл не открыть).
* **Max (второй проход)**: в `bcc/integration@6a6c503` влит `pdf.py` из 288d727 — у него склейка разных таблиц
  одной сетки и `Warning.page = null`, из-за которого там падают 5 тестов `tests/p02`. Нужно перелить эту ветку.
  `extraction.tables[].links/maybe_continues` и предупреждение `table_continuation_uncertain` можно показывать в отчёте.
* Известные ограничения: неоднозначный стык (шапка не выделена ни жирным, ни повтором) не склеивается и не получает
  имён колонок — это сознательная осторожность; заливка шапки как признак пока не используется. Заголовок, стоящий прямо под одной колонкой, не отличить от продолжения колонки, если он
  не крупнее текста. Таблица без линеек остаётся блоками. Повёрнутый текст внутри таблицы не превращается в ячейки
  (`table_rotated_text`).
