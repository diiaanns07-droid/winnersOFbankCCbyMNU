## Часть A. Бизнес-требования

### Общие сведения

Время указывается по UTC+5.

| Поле | Значение |
| :--- | :--- |
| **Наименование** | Бронирование переговорных |
| **Задача** | [ROOM-7](https://tracker.example.test/ROOM-7) |

### Функциональные требования

* **R-1.** Сотрудник бронирует комнату на 1–20 мест
  не дольше чем на 4 часа.
* **R-2.** Бронь снимается, если никто не отметился за 15 минут.
  1. Напоминание приходит за 5 минут.
* **R-3.** Повторная бронь той же комнаты заменяет действующую.

### Критерии приемки

| Исходные условия | Действие | Ожидаемый результат |

| 500 минут в журнале за день | Отменить бронь | Журнал 500 минут |
|  Бронь на  4 часа  |Продлить на 1 час|   Отказ: больше 4 часов |

## Часть B. REST API

### Общие сведения

Время указывается по UTC+5.

| Поле | Значение |
| :--- | :--- |
| **REST type** | POST |
| **Swagger** | — |
| **Фильтр** | `status` \| `owner` |

### Логика работы метода

1. Проверить сессию.
2. Проверить комнату и число мест.
3. Сохранить бронь и вернуть её номер.

### Параметры запроса

#### Query-параметры

| Parameter | Format | Mandatory | Logic | Description |
| :--- | :--- | :--- | :--- | :--- |
| `roomId` | string | Да | 1–32 символа | Комната |
| `seats` | integer | Да | 1–20 | Число мест |

### Ответ

| Parameter | Format | Logic | Description |
| :--- | :--- | :--- | :--- |
| `bookingId` | string | При успехе | Номер брони |
| `seats` | string | При успехе | Число мест |

#### 200. Успех

```json
{"bookingId": "b-1", "seats": "12", "filter": "status|owner"}
```
