## Часть A. Новый функционал

### Цели
Клиент сам получает выписку по счёту за выбранный период в PDF, не обращаясь в отделение.

### Архитектура решения
Мобильное приложение → сервис выписок → АБС. Сервис выписок → хранилище файлов.

### Пользовательский интерфейс
Главная → Счета → счёт → «Выписка». На экране поля «Дата с» и «Дата по», кнопка «Сформировать» и список выписок, заказанных за последние 30 календарных дней, со статусом каждой. Для выписки в статусе «Готова» показана кнопка «Скачать».

### Функциональные требования
* **Ф-1.** Клиент заказывает выписку по своему текущему счёту за период от 1 до 366 календарных дней включительно; дата окончания периода — не позже текущей даты по времени Астаны (UTC+5).
* **Ф-2.** В выписку входят операции, проведённые по счёту в АБС с 00:00:00 даты начала до 23:59:59 даты окончания по времени Астаны (UTC+5).
* **Ф-3.** Выписка формируется асинхронно. Статусы заказа: «Формируется» → «Готова» или «Ошибка». Переход в «Готова» происходит, когда файл сохранён в хранилище файлов.
* **Ф-4.** Готовый файл хранится 30 рабочих дней с момента перехода в статус «Готова»; после этого заказ удаляется из списка.
* **Ф-5.** Клиент может заказать не больше 10 выписок за календарные сутки по времени Астаны (UTC+5).
* **Ф-6.** Суммы в выписке указываются в валюте счёта с двумя знаками после запятой.

### Нефункциональные требования
* **НФ-1.** Выписка за период до 31 дня формируется не дольше 60 с для 95 % заказов; за период до 366 дней — не дольше 5 минут для 95 % заказов.
* **НФ-2.** Ссылка на скачивание действует 10 минут с момента выдачи и доступна только владельцу счёта.

### Требования к данным
Хранить идентификатор заказа, идентификатор счёта, даты начала и окончания периода, статус, время заказа и время перехода в «Готова» по UTC+5, идентификатор файла в хранилище.

### Интеграция
Приложение заказывает выписку, отменяет заказ, получает список заказов и ссылку на файл через дочерний документ «Выписка по счёту — REST API». Сервис выписок получает операции из АБС за период и сохраняет файл в хранилище файлов.

### Критерии приемки
| Дано | Действие | Ожидаемый результат |
| :--- | :--- | :--- |
| Счёт клиента, заказов сегодня нет | Заказать выписку с 01.10.2026 по 31.10.2026 | Заказ в статусе «Формируется», через 60 с — «Готова» |
| Счёт клиента | Заказать выписку за 367 дней | Ошибка «Период — не больше 366 дней» |
| 10 заказов сегодня | Заказать ещё одну выписку | Ошибка «Не больше 10 выписок в сутки» |
| Выписка «Готова» | Нажать «Скачать» | Открывается PDF выписки |

## Часть B. Выписка по счёту — REST API

### Метод 1. Заказ выписки

| Поле | Значение |
| :--- | :--- |
| **REST type** | POST |
| **Request URL** | `https://api.bank.local/accounts/{accountId}/statements` |
| **Content-Type** | application/json |

#### Параметры запроса
| Параметр | Тип | Обязательный | Описание |
| :--- | :--- | :--- | :--- |
| `accountId` | string | Да | Идентификатор счёта (в пути) |
| `dateFrom` | string | Да | Дата начала, формат ДД.ММ.ГГГГ |
| `dateTo` | string | Да | Дата окончания, формат ГГГГ-ММ-ДД |

#### Логика работы метода
1. Проверить сессию клиента; если сессии нет, вернуть 401.
2. Проверить, что счёт принадлежит клиенту; если нет, вернуть 404.
3. Проверить период по Ф-1; если период неверный, вернуть 400.
4. Проверить число заказов за сутки по Ф-5; если заказов 9 или больше, вернуть 429.
5. Создать заказ в статусе «Формируется» и вернуть 202 с идентификатором заказа.

#### Статусы ответа
* 202. Заказ создан, выписка формируется.
* 400. Неверный период.
* 401. Нет действующей сессии клиента.
* 404. Счёт не найден или принадлежит другому клиенту.
* 429. Превышено число заказов за сутки.

### Метод 2. Список заказов

| Поле | Значение |
| :--- | :--- |
| **REST type** | GET |
| **Request URL** | `https://api.bank.local/accounts/{accountId}/statements` |

#### Логика работы метода
1. Проверить сессию клиента; если сессии нет, вернуть 401.
2. Проверить, что счёт принадлежит клиенту; если нет, вернуть 404.
3. Вернуть 200 и заказы за последние 30 календарных дней: идентификатор, период, статус, время заказа.

#### Статусы ответа
* 200. Список заказов.
* 401. Нет действующей сессии клиента.
* 404. Счёт не найден или принадлежит другому клиенту.

### Метод 3. Ссылка на файл выписки

| Поле | Значение |
| :--- | :--- |
| **REST type** | GET |
| **Request URL** | `https://api.bank.local/statements/{statementId}/link` |

#### Логика работы метода
1. Проверить сессию клиента; если сессии нет, вернуть 401.
2. Проверить, что заказ принадлежит клиенту; если нет, вернуть 404.
3. Если заказ не в статусе «Готова», вернуть 200 с `result` = `ERROR`.
4. Вернуть 200 и ссылку на файл, действующую 10 минут.

#### Статусы ответа
* 200. Ссылка на файл.
* 401. Нет действующей сессии клиента.
* 404. Заказ не найден или принадлежит другому клиенту.
* 409. Выписка ещё не готова или сформировалась с ошибкой.
