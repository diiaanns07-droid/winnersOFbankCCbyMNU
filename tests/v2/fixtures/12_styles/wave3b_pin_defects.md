## Часть A. Новый функционал

### Цели
Клиент меняет PIN-код карты в приложении, не обращаясь в отделение. Сократить число визитов в отделения по вопросам PIN-кода.

### Архитектура решения
Мобильное приложение → сервис карт → карточный процессинг. Сервис карт → сервис уведомлений.

### Пользовательский интерфейс
Главная → Карты → карта → «Сменить PIN-код». На экране два поля ввода по 4 цифры («Новый PIN-код» и «Повторите PIN-код») и кнопка «Сменить». Пока значения полей не совпадают, кнопка «Сменить» неактивна. После успешной смены показывается сообщение «PIN-код изменён».

### Функциональные требования
* **Ф-1.** Сменить PIN-код можно для карты в статусе «Активна», которая принадлежит клиенту.
* **Ф-2.** Новый PIN-код состоит из 4 цифр. Не допускаются простые комбинации: четыре одинаковые цифры, последовательности и т. д.
* **Ф-3.** Перед сменой клиент подтверждает операцию одноразовым кодом из SMS. Код действует 5 минут с момента отправки; на ввод даётся 3 попытки. После третьей неверной попытки смена PIN-кода для этой карты недоступна 24 часа с момента третьей попытки.
* **Ф-4.** Новый PIN-код действует со следующей операции по карте после ответа процессинга об успешной смене.
* **Ф-5.** После успешной смены клиент получает push «PIN-код карты •• NNNN изменён», где NNNN — последние четыре цифры номера карты.
* **Ф-6.** Сменить PIN-код одной карты можно не чаще 3 раз за календарные сутки по времени Астаны (UTC+5).

### Нефункциональные требования
* **НФ-1.** Метод смены PIN-кода отвечает не дольше 3 с для 95 % запросов при нагрузке до 50 запросов в секунду.
* **НФ-2.** PIN-код передаётся от приложения до процессинга только в зашифрованном PIN-блоке; в журналах, базах и ответах сервисов PIN-код и PIN-блок не сохраняются.
* **НФ-3.** Push о смене передаётся в сервис уведомлений мгновенно и без задержек.

### Требования к данным
Хранить идентификатор карты, последние четыре цифры номера карты, время смены по UTC+5, число смен за текущие сутки, число неверных вводов SMS-кода и время третьей неверной попытки.

### Интеграция
Приложение меняет PIN-код через дочерний документ «Смена PIN-кода — REST API». Сервис карт передаёт PIN-блок в процессинг и после ответа процессинга передаёт push в сервис уведомлений.

### Критерии приемки
| Дано | Действие | Ожидаемый результат |
| :--- | :--- | :--- |
| Активная карта клиента, смен сегодня нет | Ввести 4829 дважды и верный SMS-код | PIN-код изменён, push «PIN-код карты •• 5521 изменён» |
| Активная карта клиента | Ввести 1111 | Кнопка «Сменить» неактивна, подсказка «PIN-код слишком простой» |
| Три смены сегодня | Начать четвёртую смену | Ошибка «Сменить PIN-код можно не чаще 3 раз в сутки» |
| Две неверные попытки SMS-кода | Ввести неверный код третий раз | Смена недоступна 24 часа |

## Часть B. Смена PIN-кода — REST API

### Метод 1. Смена PIN-кода

| Поле | Значение |
| :--- | :--- |
| **REST type** | GET |
| **Request URL** | `https://api.bank.local/cards/{cardId}/pin` |
| **Controller** | CardPinController |
| **Content-Type** | application/json |

### Параметры запроса
| Параметр | Тип | Обязательный | Описание |
| :--- | :--- | :--- | :--- |
| `cardId` | string | Да | Идентификатор карты (в пути запроса) |
| `pinBlock` | string | Да | Зашифрованный PIN-блок нового PIN-кода |
| `otp` | string | Да | Одноразовый код из SMS, 6 цифр |
| `requestId` | string | Да | Ключ идемпотентности, UUID |
| `lockPeriod` | integer | Нет | Срок блокировки смены после трёх неверных попыток, в минутах |

### Логика работы метода
1. Проверить сессию клиента; если сессии нет, вернуть 401.
2. Проверить, что карта принадлежит клиенту; если нет, вернуть 404.
3. Проверить, что карта в статусе «Активна»; если нет, вернуть 423.
4. Проверить число смен за текущие сутки по времени Астаны (UTC+5); если смен уже 3, вернуть 429.
5. Проверить SMS-код; при неверном коде вернуть 400 и увеличить число неверных вводов. После третьей неверной попытки вернуть 429 на любые запросы смены по этой карте в течение 24 часов.
6. Передать PIN-блок в процессинг. При ответе процессинга об успехе вернуть 200; при сбое процессинга вернуть 502.

### Особые правила
1. Повторный запрос с тем же `requestId` возвращает результат первого запроса.

### Статусы ответа
* 200. PIN-код изменён.
* 400. Неверный SMS-код или неверный формат параметров.
* 401. Нет действующей сессии клиента.
* 404. Карта не найдена или принадлежит другому клиенту.
* 409. Карта не в статусе «Активна».
* 429. Превышено число смен за сутки или число попыток ввода SMS-кода.
* 502. Процессинг не ответил или вернул ошибку.

### Ответ
| Поле | Тип | Описание |
| :--- | :--- | :--- |
| `status` | string | `DONE` при коде 200 |
| `changedAt` | string | Время смены по UTC+5 в формате ISO 8601 |

Пример ответа 200:
```json
{"status": "DONE", "changedAt": "2026-11-20T14:03:11+05:00"}
```
