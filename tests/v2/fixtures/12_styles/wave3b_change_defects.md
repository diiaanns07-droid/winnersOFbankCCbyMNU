# Доработка: лимит снятия наличных по карте

| Поле | Значение |
| :--- | :--- |
| **Наименование** | Изменение лимита снятия наличных по дебетовой карте |
| **Продукт** | Дебетовые карты |
| **Тип работы** | Доработка существующего функционала |
| **Влияние на ИС** | Мобильный банк, сервис лимитов, карточный процессинг |
| **Версия документа** | 1.0 от 21.11.2026 |

## Часть A. Доработка

### Цели
Клиент сам меняет суточный лимит снятия наличных в приложении в пределах, установленных банком.

### Что меняется

| Параметр | Было | Стало |
| :--- | :--- | :--- |
| Суточный лимит снятия по умолчанию | 200 000 ₸ | 300 000 ₸ |
| Максимальный суточный лимит, который клиент может задать | 500 000 ₸ | 1 000 000 ₸ |
| Срок действия временного лимита | 3 календарных дня | 7 календарных дней |
| Код ответа при превышении максимального лимита | 400 | 422 |
| Изменение лимита | только в отделении | в приложении и в отделении |

Старые значения из колонки «Было» перестают действовать с даты выпуска доработки; лимиты, заданные клиентами до
неё, сохраняются, если они не больше нового максимума.

### Функциональные требования
* **Ф-1.** Клиент задаёт суточный лимит снятия наличных целым числом тенге от 0 ₸ до 1 000 000 ₸ включительно.
* **Ф-2.** Клиент может задать временный лимит на срок 7 календарных дней; по окончании срока действует постоянный
  лимит.
* **Ф-3.** Новый лимит действует с момента ответа сервиса лимитов об успешном сохранении.
* **Ф-4.** Сутки для лимита считаются с 00:00 до 23:59:59 по времени Астаны (UTC+5).

### Нефункциональные требования
* **НФ-1.** Метод сохранения лимита отвечает не дольше 1 с для 95 % запросов при нагрузке до 100 запросов в секунду.

### Критерии приемки
| Дано | Действие | Ожидаемый результат |
| :--- | :--- | :--- |
| Лимит 300 000 ₸ | Задать 1 000 000 ₸ | Ошибка 422 «Лимит больше максимального» |
| Лимит 300 000 ₸ | Задать 1 000 001 ₸ | Ошибка 422 «Лимит больше максимального» |
| Временный лимит задан 1 декабря | Наступило 8 декабря | Действует постоянный лимит |

## Часть B. REST API

### Метод 1. Сохранение лимита

| Поле | Значение |
| :--- | :--- |
| **REST type** | PUT |
| **Request URL** | `https://api.bank.local/cards/{cardId}/cash-limit` |
| **Content-Type** | application/json |

#### Параметры запроса
| Параметр | Тип | Обязательный | Описание |
| :--- | :--- | :--- | :--- |
| `amount` | integer | Да | Суточный лимит в тенге, от 0 до 1 000 000 |
| `temporary` | boolean | Нет | Временный лимит на 3 календарных дня |

#### Логика работы метода
1. Проверить сессию клиента; если сессии нет, вернуть 401.
2. Проверить, что карта принадлежит клиенту; если нет, вернуть 404.
3. Проверить сумму: от 0 до 1 000 000 ₸ включительно; если сумма больше 1 000 000 ₸, вернуть 400.
4. Сохранить лимит и вернуть 200.

#### Статусы ответа
* 200. Лимит сохранён.
* 401. Нет действующей сессии клиента.
* 404. Карта не найдена или принадлежит другому клиенту.
* 422. Лимит больше максимального.
