# Ответы-ловушки для проверки пересмотра (официальный документ)

> Каждый ответ помечен, чего мы ждём от пересмотра. Пометки — в строках «>», агент их не читает.
> ПРЯМОЙ — ответ прямо снимает дефект (ожидаем «закрыт»).
> ЧАСТИЧНЫЙ — ответ закрывает одну ветку из двух (ожидаем «изменён» или «открыт», но не «закрыт»).
> РАСПЛЫВЧАТЫЙ / НЕ ПО ТЕМЕ — ответ правила не задаёт (ожидаем «открыт»).
> КОНФЛИКТ — ответ сам противоречит другому месту документа, которое вопрос не затрагивал (ожидаем новый конфликт).

> ПРЯМОЙ (месяц покупки)
Q-01 [месяц покупки дата совершения или проведения]: Месяц определяется по дате и времени совершения покупки по времени Алматы (UTC+5). Покупка 31 января в 23:58, проведённая 1 февраля в 00:03, относится к январю; в критерии приёмки №2 ожидаемый результат — январский счётчик вырос на 4 000 ₸, февральский не изменился.
> КОНФЛИКТ (второй push после смены порога): ответ противоречит общему решению 2 (не больше одного push в месяц)
Q-02 [второй push в месяце после смены порога]: После смены порога push по новому порогу возможен в том же месяце; всего не больше двух push на карту в месяц.
> ЧАСТИЧНЫЙ (код ответа при ошибке суммы): только сумма меньше нижней границы
Q-03 [код ответа при сумме вне диапазона]: Если сумма меньше 1 000 ₸, метод возвращает HTTP 400 с телом {"result":"ERROR","message":"Проверьте сумму"}.
> РАСПЛЫВЧАТЫЙ (чтение настроек)
Q-04 [операция чтения настроек и суммы за месяц]: Сделайте, как принято в других сервисах банка.
> НЕ ПО ТЕМЕ (событие процессинга)
Q-05 [событие процессинга запускающее учёт]: Тексты сообщений об ошибках согласует служба поддержки клиентов.

## Решения

> ПРЯМОЙ (общее решение): чужая и отсутствующая карта
- Для чужой и для отсутствующей карты метод возвращает 404 с телом {"message":"Карта не найдена"}; код 403 этим методом не используется.

> КОНФЛИКТ (общее решение): противоречит ответу на Q-02
- Клиент получает не больше одного push в календарный месяц по каждой карте при любых изменениях настроек.
