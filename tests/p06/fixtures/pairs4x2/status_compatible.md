# Платёжное поручение с датой валютирования

Учебный документ №06: дата валютирования.

## Часть A. Бизнес-требования

### Общие сведения

| Поле | Значение |
| :--- | :--- |
| **Наименование задачи** | Отложенный платёж юрлица |
| **Продукт** | Интернет-банк для бизнеса |
| **Версия документа** | 1.0 от 18.11.2026 |

### Функциональные требования
* **ДВ-1.** Клиент-юрлицо создаёт платёжное поручение и указывает дату валютирования.
* **ДВ-2.** Дата валютирования не может быть раньше текущего операционного дня и позже чем через 30 календарных дней.
* **ДВ-3.** Если дата валютирования приходится на выходной день, платёж исполняется в ближайший рабочий день.
* **ДВ-4.** Клиент может перенести дату валютирования неисполненного платежа.

### Требования к интеграции
Интернет-банк создаёт поручение методом createPayment и переносит дату методом reschedulePayment. Методы описаны в части B.

### Критерии приёмки

| Исходные условия | Действие | Ожидаемый результат |
| :--- | :--- | :--- |
| Текущий операционный день 20.11.2026 | Клиент создаёт платёж с датой валютирования 25.11.2026 | Платёж сохранён, исполнение 25.11.2026 |
| Текущий операционный день 20.11.2026 | Клиент создаёт платёж с датой валютирования 30.12.2026 | Платёж не создан |

## Часть B. REST API

### Метод createPayment

| Поле | Значение |
| :--- | :--- |
| **REST type** | POST |
| **Request URL** | `/payments` |
| **Authorization** | Bearer, сессия сотрудника клиента |

#### Тело запроса

| Parameter | Format | Mandatory | Logic | Description |
| :--- | :--- | :--- | :--- | :--- |
| `account` | string | Да | IBAN клиента | Счёт списания |
| `amount` | integer | Да | от 1 до 100 000 000 включительно | Сумма платежа в тенге |
| `valueDate` | string | Да | ГГГГ-ММ-ДД | Дата валютирования |

#### Логика метода
1. Проверить сессию и права на счёт.
2. Проверить дату валютирования по ДВ-2.
3. Сохранить платёж и вернуть 200.

### Метод reschedulePayment

| Поле | Значение |
| :--- | :--- |
| **REST type** | POST |
| **Request URL** | `/payments/{paymentId}/reschedule` |
| **Authorization** | Bearer, сессия сотрудника клиента |

#### Логика метода
1. Найти неисполненный платёж по `paymentId`.
2. Если новая дата валютирования раньше текущего операционного дня, вернуть 422.
3. Сохранить новую дату валютирования и вернуть 200.

### Статусы

| Код | Когда возвращается | Тело ответа |
| :--- | :--- | :--- |
| 200 | Запрос выполнен | `{"paymentId":"p-1","status":"scheduled"}` |
| 400 | createPayment: дата валютирования раньше текущего операционного дня или позже чем через 30 дней | `{"message":"Проверьте дату валютирования"}` |
| 401 | Нет действующей сессии | `{"message":"Требуется вход"}` |
| 404 | Платёж не найден | `{"message":"Не найдено"}` |
