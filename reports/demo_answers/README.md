# Цепочка уточнения на чужом ТЗ: вопросы → ответы владельца → исправленное ТЗ → повторная проверка

Документ — «Перевод по QR-коду» (`evaluation/v2/open2/qr/source.md`, 202 строки): новое ТЗ открытого набора
№18 в шаблоне банка, агент его при настройке не видел. Все отчёты и редакции сформированы агентом командой
`python -m bcc_review …` и руками не правились; ответы владельца (`answers*.md`) написаны человеком в роли
владельца продукта. Модель — `claude-sonnet-5-5` через `claude -p`, агент — коммит `7856f63` (в паспорте
пометка «рабочая копия с изменениями»: незакоммиченными были только статус-файл и сами эти отчёты; правка
`fffa4c2` вопросов этих прогонов не меняет — повтор из кэша даёт те же отчёты).

## Команда одной строкой

Отчёт с вопросами, пересмотр по ответам владельца, исправленное ТЗ и его повторная проверка:

```bash
python -m bcc_review evaluation/v2/open2/qr/source.md reports/demo_answers/qr/qr.md --provider claude_cli --model sonnet --answers reports/demo_answers/qr/answers.md --revise && python -m bcc_review reports/demo_answers/qr/qr.revised.md reports/demo_answers/qr/qr.revised.review.md --provider claude_cli --model sonnet
```

Второй круг — ответы на вопросы повторной проверки:

```bash
python -m bcc_review reports/demo_answers/qr/qr.revised.md reports/demo_answers/qr/qr.round2.md --provider claude_cli --model sonnet --answers reports/demo_answers/qr/answers.round2.md --revise && python -m bcc_review reports/demo_answers/qr/qr.round2.revised.md reports/demo_answers/qr/qr.round2.revised.review.md --provider claude_cli --model sonnet
```

Отчёт «до» без ответов (тот же прогон, что внутри первой команды):
`python -m bcc_review evaluation/v2/open2/qr/source.md reports/demo_answers/qr/qr.before.md --provider claude_cli --model sonnet`.
Любой отчёт проверяется независимо от агента: `python -m bcc_review verify reports/demo_answers/qr/qr.json evaluation/v2/open2/qr/source.md`.

**Шаг 1 → 2.** Четыре блокера исходного ТЗ — обещанные, но не описанные методы создания и получения данных
QR-кода; граница 500 000 ₸ «включительно» в Ф-1 против отказа в критерии приёмки; срок QR без суммы 15 минут
против «до конца дня»; отказ антифрода под кодом 200, который документ называет успешным. Каждый — в своём
блокирующем вопросе с цитатами обеих сторон и вариантами. Пересмотр: снято 13 дефектов, у каждого назван
закрывший ответ (`Q-…` или общее решение), уточнён 1, **открытым оставлен 1** — D-09 «что считается оплатой
QR без суммы»: ответ Q-07 описал только QR с суммой, и агент это заметил. Новых конфликтов 0.

**Шаг 3.** Редакция: 22 замены, 2 вставки, не применено 0, одна пометка `<уточнить: …>` (вопрос D-09 без
ответа), самопроверка редакции исправила 2 противоречия правок; все места помечены `[изменено: D-…]`.
Повторная проверка нашла **новый критичный конфликт, который внёс ответ владельца**: по ответу Q-07 «отмена во
время перевода не прерывает его» и «после отказа антифрода QR снова активен» — какой статус у QR, отменённого
получателем, пока шёл перевод? Ф-5 и шаги 7–8 метода дают разные исходы. Плюс 4 существенных: внешний документ
«QR-коды — REST API» ещё не приложен, пометка `<уточнить>` в Ф-5, блокировка QR не отражена в данных, «несколько
раз» без числа.

**Шаг 4 → 5.** Владелец ответил на 4 вопроса повторной проверки (`answers.round2.md`): снято 5 из 5, редакция
второго круга — 8 замен, пометок `<уточнить>` 0. Повторная проверка: **0 критичных, вердикт «с условиями»**.
Существенных 9 — замечания к новому тексту (повтор `requestId` после ошибки, возврат QR в «активен» через
60 секунд и двойная оплата, внешний документ методов QR): редакция длиннее исходника (212 строк против 202), и
ревью проверяет уже её.

Время и вызовы (sonnet): шаг 1 — 2 мин 53 с, 9 вызовов; шаг 2 — 1 мин 39 с, 3 вызова (пересмотр, редакция,
самопроверка редакции; ревью исходника — из кэша шага 1); шаг 3 — 2 мин 33 с, 9 вызовов; шаг 4 — 1 мин 11 с,
3 вызова; шаг 5 — 2 мин 56 с, 9 вызовов.
