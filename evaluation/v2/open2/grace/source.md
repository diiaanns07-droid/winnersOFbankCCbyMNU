## Часть A. Новый функционал

### Общие сведения

| **Бизнес-процесс** | Обслуживание кредитной карты |

| **Задача в JIRA** | CARD-2417 |

### Цели
Клиент заранее видит, до какой даты и какую сумму нужно внести, чтобы не платить проценты за покупки по кредитной карте. Снизить долю клиентов, которые теряют льготный период из-за пропущенной даты платежа.

### Архитектура решения
Мобильное приложение → API кредитных карт → кредитный модуль. Кредитный модуль → сервис уведомлений → push-уведомление клиенту.

### Дизайн процесса UI
Главная → Кредитная карта → блок «Льготный период». В блоке показаны дата окончания платёжного периода, сумма для погашения без процентов, сколько дней осталось, кнопка «Пополнить» и переключатель «Напоминать о платеже». Если льготный период утрачен, вместо даты показывается надпись «Начисляются проценты» и общая сумма задолженности.

### Требования к изменениям

#### BPMN схема процесса
Формирование выписки → расчёт суммы для погашения → ожидание платежа → напоминание за 3 дня → проверка погашения в конце платёжного периода → сохранение или утрата льготного периода.

#### Функциональные требования
* **Ф-1.** Льготный период действует для покупок по кредитной карте и длится до 55 календарных дней. Расчётный период равен календарному месяцу, выписка формируется 1-го числа следующего месяца, платёжный период заканчивается 25-го числа того же месяца.
* **Ф-2.** Сумма для погашения без процентов равна задолженности по покупкам расчётного периода на дату выписки. Покупка относится к расчётному периоду по дате её отражения на счёте карты. Снятие наличных и переводы с кредитной карты в льготный период не входят: проценты по ним начисляются с даты операции.
* **Ф-3.** Если клиент внёс сумму для погашения полностью до окончания платёжного периода включительно, проценты по покупкам расчётного периода не начисляются. Если внесено меньше, проценты начисляются на всю задолженность по покупкам расчётного периода с даты каждой покупки.
* **Ф-4.** Если переключатель «Напоминать о платеже» включён и сумма для погашения не внесена полностью, за 3 календарных дня до окончания платёжного периода клиент получает push с датой окончания и оставшейся суммой. По умолчанию переключатель включён.
* **Ф-5.** Внесённый платёж уменьшает оставшуюся сумму для погашения. Возврат покупки, отражённый до окончания платёжного периода, тоже уменьшает оставшуюся сумму. Покупки, отражённые на счёте после даты выписки, относятся к следующему расчётному периоду и сумму для погашения не меняют.

### Sequence Diagram
Мобильное приложение → API кредитных карт: запросить сведения о льготном периоде. API кредитных карт → кредитный модуль: получить выписку и платежи. Кредитный модуль → сервис уведомлений: передать дату окончания и оставшуюся сумму для напоминания.

### Нефункциональные требования
Сведения о льготном периоде отображаются быстро и всегда актуальны. Напоминания отправляются своевременно.

### Требования к данным
Хранить идентификатор карты, расчётный период, дату выписки, сумму для погашения в тиынах, сумму внесённых платежей в тиынах, признак сохранения льготного периода и признак включения напоминания.

### Требования к интеграции
Приложение получает сведения о льготном периоде и включает или выключает напоминание через дочерний документ «Льготный период по кредитной карте — REST API». Кредитный модуль передаёт в сервис уведомлений одно напоминание на карту за платёжный период.

## Часть B. REST API

Дочерний документ части A: «Льготный период по кредитной карте — REST API».

### Общие параметры

| Поле | Значение |
| :--- | :--- |
| **Description** | Получение сведений о льготном периоде по кредитной карте |
| **REST type** | GET |
| **Authorization** | Bearer, сессия клиента — владельца карты |
| **Controller** | GraceController |
| **URL type** | Dev / Prod |
| **Request URL** | Dev: `https://api-dev.bank.local/cards/{cardId}/grace` . Prod: `https://api.bank.local/cards/{cardId}/grace` |
| **CURL** | `curl "$BASE/cards/cc-1007/grace" -H "Authorization: Bearer $TOKEN"` |
| **Swagger** | `https://api-dev.bank.local/swagger/grace` |
| **Gitlab project** | cards/grace-api |
| **Framework** | Spring Boot 3 |
| **Author** | Аналитик команды карт |
| **Developer** | Команда кредитных карт |

### Логика работы метода
1. Проверить сессию клиента.
2. Проверить, что карта принадлежит клиенту и является кредитной.
3. Получить из кредитного модуля последнюю выписку и платежи после даты выписки.
4. Рассчитать оставшуюся сумму для погашения и количество дней до окончания платёжного периода.
5. Вернуть сведения о льготном периоде и прогноз процентов на случай частичного погашения.
6. Если карта не кредитная, вернуть 200 с `status` = `NOT_APPLICABLE`.

### Особые правила
1. Сумма для погашения не может быть отрицательной: переплата показывается как 0.
2. При частичном погашении прогноз процентов считается только на непогашенную часть суммы для погашения.
3. Если выписка ещё не сформирована, возвращаются сведения по предыдущему платёжному периоду.

### Схема
```text
Приложение → GraceController → кредитный модуль → GraceController → приложение.
```

### Ответ
Если результат 200 — успешный. Если результат 401, 404, 422 или 500 — неуспешный.

| Parameter | Format | Logic | Description | DB field |
| :--- | :--- | :--- | :--- | :--- |
| `status` | string | ACTIVE / LOST / NOT_APPLICABLE | Состояние льготного периода | `grace_status` |
| `paymentDueDate` | string | ДД.ММ.ГГГГ | Дата окончания платёжного периода | `due_date` |
| `graceAmount` | integer | ≥ 0 | Оставшаяся сумма для погашения без процентов, тиыны | `grace_amount` |
| `daysLeft` | integer | ≥ 0 | Количество рабочих дней до окончания платёжного периода | — |
| `interestForecast` | integer | ≥ 0 | Прогноз процентов, если оставшаяся сумма не будет внесена до окончания платёжного периода, тиыны | — |
| `totalDebt` | integer | ≥ 0 | Общая задолженность по карте на дату запроса, тиыны | `total_debt` |
| `reminderEnabled` | boolean | true / false | Признак включения напоминания | `reminder_enabled` |

### Статусы

**200.** Ответ в случае успешного выполнения метода.  
**401.** Ответ в случае, если запрос выполнен без необходимой авторизации.  
**404.** Ответ в случае, если карта не найдена или принадлежит другому клиенту.  
**422.** Ответ в случае, если карта не является кредитной.  
**500.** Ответ в случае, если произошла внутренняя ошибка сервера.

#### 200. Successful
```json
{"status":"ACTIVE","paymentDueDate":"2026-03-25","graceAmount":12000000,"daysLeft":9,"interestForecast":0,"totalDebt":12000000,"reminderEnabled":true}
```

#### 401. Unsuccessful — Unauthorized
```json
{"message":"Требуется вход"}
```

#### 404. Unsuccessful — Not found
```json
{"message":"Карта не найдена"}
```

#### 422. Unsuccessful — Unprocessable entity
```json
{"message":"Для этой карты льготный период не предусмотрен"}
```

#### 500. Unsuccessful — Internal server error
```json
{"message":"Ошибка сервиса"}
```
