# Открытый набор №18: четыре новых ТЗ с эталоном

Проверка обобщения: агент до сих пор мерился только на официальном документе и на корпусе из четырёх тем
(кэшбэк, автопополнение, блокировка карты, лимит переводов). Здесь — четыре новых домена в шаблоне
официального документа (часть A «Новый функционал» + часть B «REST API»), у каждого есть дефектная версия с
эталоном, чистая версия для замера ложных тревог, а у страхования — ещё вариант со вставкой для модели.

| `grace` | Льготный период по кредитной карте (GET сведений) | 193 | 4 / 5 / 4 фоновых | `grace_clean`, 212 строк |
| `qr` | Перевод по QR-коду (POST перевода) | 202 | 4 / 5 / 1 + 4 фоновых | `qr_clean`, 212 строк |

В каждом кейсе: `source.md` (основной), `source.pdf` и `source.docx` (рендер корпуса `evaluation/dev/render.py`,
текст извлекается обратно — проверяет сборщик), `gold.yaml` в формате счётчика №15 (`bcc-v2-gold/1`).

М1–М4 (`background.yaml`) есть и в чистых версиях: шаблон банка в них оставлен незаполненным, как в официальном
документе. На чистой версии они — законные minor, а всё остальное critical/major — ложная тревога (или
непреднамеренный дефект документа; такие случаи разбираются в `docs/plan-v2/status/18.md`).

## Как собрано

* Документ и эталон написаны **до** первого прогона агента (коммит `c1b8d34`, прогоны — после него).
* `<кейс>/spec.yaml` — эталон цитатами и правки `fix` для чистой версии. `build.py` находит строки цитат
  (каждая встречается ровно один раз), пишет `gold.yaml`, применяет правки (каждая `old` — ровно одно вхождение) →
  `<кейс>_clean/`, вставляет фразу для модели → `insurance_inject/`, рендерит PDF/DOCX и проверяет извлечение.
* `gold.yaml` руками не правится: `python -m evaluation.v2.open2.build`, проверка — `--check`.

## Как мерить

```bash
# один документ — обычный счётчик №15
python -m bcc_review evaluation/v2/open2/qr/source.md out/qr.md --provider claude_cli --model sonnet
python -m evaluation.v2.score out/qr.json --gold evaluation/v2/open2/qr/gold.yaml \
    --cache evaluation/v2/open2/qr/arbiter_cache.jsonl

# весь набор: прогон (параллельно) и сводка — results/<метка>/summary.md
python -m evaluation.v2.open2.run run --label sonnet_0700 --model sonnet --jobs 3
python -m evaluation.v2.open2.run run --label pdf_0700 --model sonnet --cases grace,qr --formats pdf,docx
python -m evaluation.v2.open2.run score --label sonnet_0700
```

Ворота счётчика №15 в `score.md` подписаны под официальный документ («К1–К5», «/20»); для этого набора смотрите
`results/<метка>/summary.md`: там число пунктов берётся из эталона кейса, отдельно — ложные тревоги на чистых
версиях с источником (какой этап выдал) и обнаружение вставки.
