# Исправления точности перед сдачей

Рабочая ветка `codex/precision-owner`. Сравниваются релизная база `3e7133c2` и код `9d1e157c`. На срезе в 19:26 по Астане в релизе `1933b20c` изменились только три файла документации. Код валидатора совпадает с базой эксперимента. При слиянии базы обнаружили, что точечная правка №32 о спорящих ответах уже вошла в релиз через `acbfbd88`. Её три регрессионных теста проходят на обеих версиях.

## Что изменилось для владельца

- Если два новых вопроса одинаково соответствуют ответу или буква указывает на исчезнувшую тему, агент сохраняет реплику для подтверждения. Ответ по другой редакции, для которого не нашлось подтверждённой темы, остаётся у владельца. Два числа в одинаково озаглавленных репликах могут обозначать независимые величины, например срок и сумму. Агент сохраняет такие решения раздельно. Для файлов ответов доступны проверка SHA-256 и готовая строка в приложении к отчёту.
- Кандидат нового противоречия проходит проверку на дубль по смыслу заголовка или по точным цитатам из нескольких строк. Совпадение соседних строк само по себе было причиной двух ошибочных отказов. Судья получает полный привязанный ответ как самостоятельный источник и сверяет его с цитатой ТЗ.
- Первая страница отчёта с ответами указывает, что вердикт предварительный. У снятого блокера видны основание и первая применённая правка с местом в исходнике. Готовность самой редакции устанавливает отдельный прогон по `*.revised.md`. Предварительность также видна в HTML и консоли. На опубликованном примере QR интерактивный отчёт показывал четыре уже снятых блокера в верхнем счётчике. После правки в нём ноль открытых critical и один открытый major. Историю четырёх снятых можно открыть фильтром.

## Воспроизведение

Выполнить из рабочей копии этой ветки в Python-окружении проекта. Скрипт читает опубликованные материалы F4 и фикстуры №27 из двух закреплённых коммитов.

```powershell
git fetch origin
git worktree add --detach ../precision-base 3e7133c2
git worktree add --detach ../precision-patch 9d1e157c
python evaluation/v2/precision_owner/replay.py --tree ../precision-base --out out/precision-base.json
python evaluation/v2/precision_owner/replay.py --tree ../precision-patch --out out/precision-patch.json
```

Чтобы изолировать влияние модели, вызовите судью на одном и том же входе с `--model sonnet` и `--model haiku` в разных каталогах. Параметры рассуждения фиксируются на `low`, кэш и запасная модель отключены. С флагом `--prepare-only` команда сохраняет вход без вызова модели.

```powershell
python evaluation/v2/precision_owner/judge.py --tree ../precision-patch --case car-loan --model sonnet --out out/precision/sonnet
python evaluation/v2/precision_owner/judge.py --tree ../precision-patch --case car-loan --model haiku --out out/precision/haiku
```
