### Цели
Дать клиенту возможность узнать о достижении личного бюджета в момент проведения покупки по карте. [изменено: D-04]

### Архитектура решения
Мобильное приложение → сервис настроек. Карточный процессинг → сервис расходов → сервис push. Сервис расходов → сервис настроек. [изменено: D-08]

### Дизайн процесса UI
Карты → Расходы → Уведомления. На экране видны переключатель, поле «Порог, ₸», сумма за месяц и кнопка «Сохранить». При ошибке ввода сообщение появляется под полем.

### Требования к изменениям

#### BPMN схема процесса
Проведение покупки → пересчёт расходов → проверка порога → при достижении отправка push → завершение.

#### Функциональные требования
* **Ф-1.** Держатель активной карты KZT, выпущенной на его имя, задаёт целый порог от 1 000 до 1 000 000 ₸ включительно. По умолчанию уведомление выключено. [изменено: D-09]
* **Ф-2.** Месяц определяется по дате проведения покупки в банковской книге по времени Алматы. В расходы входят проведённые покупки. Возврат уменьшает расходы месяца исходной покупки. Возврат не сбрасывает признак отправки: повторный push за этот месяц по карте не отправляется. Переводы и снятие наличных исключаются. [изменено: D-02, D-11]
* **Ф-3.** Когда расходы переходят от суммы ниже порога к сумме, равной порогу или выше, клиент получает push. На карту приходится максимум один такой push за календарный месяц.
* **Ф-4.** При изменении порога накопленная сумма сохраняется. Если она ниже нового порога, следующее достижение вызывает push, если по этой карте в этом календарном месяце push ещё не отправлялся. [изменено: D-03]
* Ф-5. Если при сохранении включённого порога (enabled = 1) накопленная сумма равна порогу или выше, система сразу отправляет push, если по этой карте в этом календарном месяце push ещё не отправлялся. Если по этой карте в этом календарном месяце push уже отправлялся, push не отправляется. [добавлено: D-13]

### Sequence Diagram
Процессинг → сервис расходов: проведена покупка. Сервис расходов → сервис настроек: получить порог карты. Сервис расходов → push: передать последние четыре цифры карты и сумму при достижении порога. [изменено: D-08]

### Нефункциональные требования
Сервис передаёт push на отправку в течение минуты после получения события о проведении покупки. [изменено: D-04]

### Требования к данным
Хранить идентификатор карты, последние четыре цифры карты, месяц, идентификатор операции, тип операции, идентификатор исходной операции для возврата, дату проведения, сумму покупки в тиынах, признак отправки, порог в тенге и признак включения. [изменено: D-10]
Сумма расходов хранится в тиынах, порог — в тенге. При сравнении порог переводится в тиыны (1 ₸ = 100 тиын). Порог 12 345 ₸ считается достигнутым при расходах 1 234 500 тиын и выше, при 1 234 499 тиын — не достигнутым. Округление расходов не применяется. [добавлено: D-06]

### Требования к интеграции
Приложение читает и сохраняет настройки через дочерний документ «Уведомление о расходах по карте — REST API». Повтор события процессинга распознаётся по идентификатору операции. Повторная доставка не меняет сумму расходов и не вызывает повторный push. Возврат имеет собственный идентификатор операции и ссылку на исходную покупку. [изменено: D-12]

### Логика работы метода
1. Проверить пользовательскую сессию.
2. Проверить, что карта выпущена на имя держателя из сессии; владение счётом доступа к настройкам чужой карты не даёт. [изменено: D-09]
3. Проверить сумму и переключатель.
4. Заменить настройку и вернуть результат сохранения.
5. При отклонении суммы вернуть прежнее состояние и код 400 с телом: result ERROR, message, прежние amount и enabled. [изменено: D-15]

### Особые правила
1. Целое число тенге, обе границы включены.
2. Повторное сохранение заменяет действующую настройку.
3. Изменение порога сохраняет накопленные расходы.
