### 3.2. Критичные и существенные дефекты

#### <a id="d-01"></a>🟠 D-01. Не определён ответ метода перевода для оплаченного или обрабатываемого QR-кода

- Ф-5, строка 44: «После отмены или истечения срока действия при сканировании показывается «QR-код недействителен»
- критерий приёмки №4, строка 71: «Показано «QR-код недействителен»
- Логика работы метода, п. 6, строка 130: «Если QR-код с суммой уже оплачен, вернуть <уточнить: код и message для оплаченного QR-кода>»
- Часть B › Статусы, строка 176: «<уточнить: код ответа>. Ответ в случае, если QR-код с суммой уже оплачен. \[добавлено: D-10\]»

**Проблема.** В строках 130 и 176 код и message для оплаченного QR — заглушки; для QR «обрабатывается другим запросом» ответа нет. Критерий приёмки строки 71 ждёт «QR-код недействителен», но из требований это не следует.  
**Сценарий.** Два отправителя одновременно платят по QR на 7 000 ₸: второй получает неизвестный код, а тест по строке 71 не обоснуем.  
**Последствия.** Реализация и тест по неопределённому коду невозможны, клиенты разберут отказ по-разному.  
**Как исправить.** Выбрать код (например 409 или 410) и message для оплаченного QR-кода и отдельно для QR-кода в обработке, добавить тела в примеры.  
**Было → стало (места «<уточнить>» заполнит ответ владельца).** Строка 130: «Если QR-код с суммой уже оплачен, вернуть <уточнить: код и message для оплаченного QR-кода>» → «410. Ответ в случае, если QR-код с суммой уже оплачен: {"message":"QR-код уже оплачен"}; <уточнить: код и message для QR-кода, который обрабатывается другим запросом>.»  
**Вопрос владельцу.** Какой код и message возвращать для оплаченного QR-кода и для QR-кода в обработке? → [Q-01](#q-01) (варианты ответа)

#### <a id="d-02"></a>🟠 D-02. Код и тело ответа при окончательном отказе антифрода не выбраны

- Логика работы метода, п. 7, строка 131: «При окончательном отказе антифрода вернуть <уточнить: код ответа — 422 или 403>, деньги не списывать, статус QR-кода оставить…»
- Часть B › Статусы, строка 178: «<уточнить: код ответа — 422 или 403>. Ответ в случае окончательного отказа антифрода; деньги не списываются. \[добавлено: D-10\]»

**Проблема.** В строках 131 и 178 код — заглушка «422 или 403», тело ответа не задано, «окончательный» отказ не определён.  
**Сценарий.** Антифрод отклонил перевод 5 000 ₸: сервер вернёт 422 или 403 по усмотрению разработчика, приложение не знает, что показать.

- **C** 422 с message «Операция отклонена»; неокончательный отказ (ручная проверка) — ответ 202, окончательный — 422

Зачем: Без выбора кода клиент и тесты не смогут отличить отказ антифрода от других ошибок.

**<a id="q-03"></a>Q-03** Отмена QR-кода во время перевода · можно ответить позже · кому: Владелец продукта · к [D-03](#d-03)

Где: Ф-5, строка 44: «Получатель может отменить QR-код в статусе «активен», включая QR-код без суммы после…»; Логика работы метода, п. 6, строка 130: «операции по одному QR-коду с суммой выполняются строго по одной»

- **A** Отмена во время обработки перевода отклоняется ответом 409; перевод завершается
- **B** Отмена принимается, но уже начатый перевод завершается; отмена действует для следующих сканирований
- **C** Отмена принимается, перевод в обработке откатывается, отправителю возвращается 410

Зачем: Без правила две реализации по-разному поведут себя при гонке отмены и оплаты, возможен спор о деньгах.

**<a id="q-04"></a>Q-04** Нормативы времени ответа и нагрузки · можно ответить позже · кому: Владелец продукта · к [D-04](#d-04)

**Шкала серьёзности**

- 🔴 **Критичный** — два места документа дают несовместимый результат для одного входа; ключевое правило нельзя однозначно реализовать или проверить; нет информации, без которой основную функцию не реализовать.
- 🟠 **Существенный** — неоднозначность или неполнота, ведущая к неверной реализации или спору при приёмке; непокрытая ветка (ошибки, повторы, отмены, границы); риск ИБ; расхождение типов, единиц, терминов.
- 🟡 **Незначительный** — оформление, незаполненный шаблон, версия и согласования, отсутствие ID и приоритетов, стиль.

**Вердикт.** Критичный дефект, блокирующий разработку, — разработку начинать нельзя; то же для тестирования. Иначе при трёх и более существенных дефектах по направлению — «можно с условиями»: начинать части, не затронутые дефектами, и исправлять их параллельно. Иначе — «можно». Частичный прогон не даёт «можно»: в лучшем случае «с условиями».

**Сверка цитат.** Сравнение без учёта регистра, вида кавычек и тире, лишних пробелов и разметки; цитата ищется у указанной строки, затем во всём документе, ближе к требованию. Нечёткое совпадение (не ниже 92 %) допускается только рядом с указанной строкой.
