### Цели
Клиент получает перевод от другого клиента банка, показав QR-код на экране телефона, без диктовки номера карты или телефона. Снизить число переводов по ошибочным реквизитам.

### Архитектура решения
Приложение получателя → сервис QR-кодов. Приложение отправителя → сервис QR-кодов → сервис переводов → антифрод. Сервис переводов → сервис уведомлений.

### Дизайн процесса UI
Получатель: Платежи → «Получить по QR» → выбор карты зачисления, необязательное поле «Сумма, ₸» и кнопка «Создать QR». QR-код показывается с таймером обратного отсчёта и кнопкой «Отменить».
Отправитель: Платежи → «Сканировать QR» → экран подтверждения с маскированным именем получателя («Айгерим С.»), суммой, картой списания, надписью «Без комиссии» и кнопкой «Перевести». Если сумма задана в QR-коде, изменить её нельзя.

### Требования к изменениям

#### BPMN схема процесса
Создание QR-кода получателем → сканирование отправителем → проверка QR-кода → подтверждение отправителем → проверка антифродом → списание и зачисление → push получателю и отправителю → завершение.

#### Функциональные требования
* **Ф-1.** Получатель — клиент банка с активной картой KZT. QR-код создаётся без суммы или с суммой от 100 до 500 000 ₸ включительно; сумма — целое число тенге.
* **Ф-2.** QR-код с суммой действует 15 минут с момента создания. QR-код без суммы действует до 23:59:59 календарного дня создания по времени Астаны (UTC+5). QR-код с суммой можно оплатить один раз, QR-код без суммы можно оплатить неограниченное число раз в течение срока действия, после каждой оплаты он остаётся в статусе «активен» до отмены или истечения срока. [изменено: D-02, D-09]
* **Ф-3.** Перед подтверждением отправитель видит маскированное имя получателя, сумму и надпись «Без комиссии». Для QR-кода без суммы отправитель вводит сумму от 100 до 500 000 ₸.
* **Ф-4.** Комиссия за перевод по QR-коду не взимается.
* **Ф-5.** Получатель может отменить QR-код в статусе «активен», включая QR-код без суммы после оплаты. После отмены или истечения срока действия при сканировании показывается «QR-код недействителен». [изменено: D-09]
* **Ф-6.** После зачисления получатель и отправитель получают push с суммой перевода и маскированным именем второй стороны.

QR-код содержит идентификатор QR-кода и сумму, если она задана. Карту зачисления сервис находит по идентификатору QR-кода. ### Логика работы метода
1. Проверить сессию отправителя.
2. Проверить, что карта списания принадлежит плательщику, активна и открыта в тенге. Если карта чужая, закрытая или не в тенге, вернуть 400 с message «Карта недоступна», операцию не создавать. [изменено: D-13]
3. Найти QR-код по `qrId`. Если QR-код не найден, вернуть 404.
4. Проверить срок действия: для QR-кода с суммой текущее время не позже времени создания QR-кода + ttl минут, для QR-кода без суммы не позже 23:59:59 дня создания по времени Астаны (UTC+5). Если срок истёк, вернуть 410 с message «Срок действия QR-кода истёк». Если QR-код отменён, вернуть 410. [изменено: D-02]
5. Если в QR-коде задана сумма, использовать её, а поле `amount` запроса не учитывать. Если суммы нет, проверить amount: от 100 до 500 000 ₸ включительно. Если amount не задан или вне диапазона, вернуть 400 с message «Проверьте сумму», операцию не создавать. [изменено: D-12]
6. Проверить, что QR-код с суммой ещё не оплачен и не обрабатывается другим запросом; операции по одному QR-коду с суммой выполняются строго по одной. Если QR-код с суммой уже оплачен, вернуть <уточнить: код и message для оплаченного QR-кода>. [изменено: D-07]
7. Передать операцию в антифрод. При окончательном отказе антифрода вернуть <уточнить: код ответа — 422 или 403>, деньги не списывать, статус QR-кода оставить «активен». [изменено: D-07]
8. Выполнить списание и зачисление, после успешного зачисления перевести QR-код с суммой в статус «оплачен» и вернуть результат. При сбое списания или зачисления статус QR-кода оставить «активен». [изменено: D-07]

### Особые правила
1. QR-код без суммы действует до 23:59:59 календарного дня создания по времени Астаны (UTC+5), QR-код с суммой — 15 минут с момента создания. [изменено: D-02]
2. Повторный запрос с тем же `requestId` возвращает результат первого запроса.
