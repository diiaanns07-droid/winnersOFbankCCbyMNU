# Расчёт стоимости аренды банковской ячейки

## Часть A. Новый функционал

### Назначение и участники

Клиент мобильного банка до визита в отделение рассчитывает стоимость аренды ячейки. Расчёт справочный. Оформление договора и резервирование ячейки выполняет сотрудник отделения при личном визите. Функция не списывает деньги.

**Паспорт.** Мобильный банк, раздел «Сейфовые услуги». Владелец процесса — управление депозитарных услуг. Путь данных — форма калькулятора → API расчёта → справочник тарифов → расчёт → экран результата.

### Функциональные требования

- Ф-1. Клиент выбирает размер S или L и две календарные даты. Первый и последний день входят в срок аренды. Допустимый срок от 1 до 30 дней включительно. Дата начала допускается с сегодняшнего дня по 90-й календарный день после него включительно. Сегодня — местная дата отделения в UTC+5 на момент получения запроса. Последняя дата аренды может выйти за пределы 90-дневного окна.
- Ф-2. К цене каждого дня применяется ставка выбранного размера, действующая на этот календарный день. Если тариф сменился внутри интервала, каждая дата рассчитывается отдельно. Тарифы всех отделений этой услуги одинаковы.
- Ф-3. Для срока от 10 дней включительно цена всей аренды уменьшается на 7,5 %. Скидка рассчитывается один раз от суммы дневных ставок и округляется до целого тиына, половина тиына округляется вверх. Итог равен сумме до скидки за вычетом округлённой скидки. Сто тиынов составляют один тенге.
- Ф-4. Клиент видит количество дней, сумму до скидки, скидку и итог. Суммы в интерфейсе показываются в тенге с двумя десятичными знаками. При отсутствии хотя бы одной дневной ставки расчёт целиком недоступен.
- Ф-5. Повтор с теми же параметрами на неизменной версии тарифов в пределах одной местной даты даёт тот же результат. При изменении тарифа следующий запрос использует новую версию. Результат запроса не хранится и не обязывает банк сохранить цену.

### Данные, интеграция и НФТ

- Д-1. Справочник хранит цену дня в целых тиынах, от 1 до 1 000 000 включительно. Для пары «размер, дата» одна ставка в пределах версии. Версия имеет непустой строковый идентификатор. Все суммы расчёта передаются целыми тиынами.
- И-1. Сервис тарифов по размеру и интервалу возвращает единый снимок действующей версии, её идентификатор и цены по датам. При недоступности справочника возвращается 503 TARIFF_DOWN. Если справочник доступен и в снимке есть пропуск, возвращается 422 RATE_GAP.
- НФ-1. На приёмочном стенде из 6 000 последовательных по времени поступления валидных запросов при 20 запросах в секунду и полном доступном снимке цен не менее 95 % получают ответ за 400 мс или меньше. Замер на сервере от получения запроса до окончания записи ответа.

### Критерии приёмки

Для КП-1–КП-4 текущая дата отделения 1 декабря 2026 года. Оба дня границы срока включаются. Денежные значения ниже в тиынах.

| ID | Данные | Действие | Результат |
|---|---|---|---|
| КП-1 | Размер S, цена 12010 на каждый день | Запросить с 2 по 2 декабря | 1 день, сумма 12010, скидка 0, итог 12010 |
| КП-2 | Размер L, цена 101 до 9 декабря включительно и 105 с 10 декабря | Запросить с 1 по 10 декабря | 10 дней, сумма 1014, скидка 76, итог 938 |
| КП-3 | Размер S, цена 102 на каждый день | Запросить с 1 по 10 декабря | 10 дней, сумма 1020, скидка 77, итог 943 |
| КП-4 | Справочник доступен, 5 декабря цена отсутствует | Запросить с 1 по 6 декабря | 422 RATE_GAP, все суммы отсутствуют |
| КП-5 | Текущая местная дата 1 декабря, указаны 31 последовательный день | Запросить стоимость | 400 TERM, обращений в справочник нет |

## Часть B. Спецификация REST API

Единственная операция — GET /v1/safe-box/quote. Требуется действующая сессия Bearer. Тело запроса отсутствует. Параметры query обязательны, каждый передаётся ровно один раз. Дополнительные параметры запрещены.

| Параметр | Формат |
|---|---|
| size | Строка S или L, регистр значим |
| start | Существующая календарная дата YYYY-MM-DD без времени |
| end | Существующая календарная дата YYYY-MM-DD без времени |

Порядок проверок — сессия (401 SESSION), затем состав и формат запроса (400 INPUT), допустимое начало по Ф-1 (400 START), затем длительность в днях по Ф-1 (400 TERM). При успехе запросить снимок по И-1. Для технического отказа справочника вернуть 503 TARIFF_DOWN. Для неполного снимка вернуть 422 RATE_GAP.

Успех — 200 и объект JSON с обязательными полями days (целое число дней), subtotalMinor (сумма дневных ставок), discountMinor (скидка), totalMinor (итог к показу), tariffVersion (строка, идентификатор полученного снимка). Три денежных поля имеют тип integer с единицей «тиын». Ошибка — JSON с единственным строковым полем code, без сумм. Пример для КП-3 при версии v12 — `{"days":10,"subtotalMinor":1020,"discountMinor":77,"totalMinor":943,"tariffVersion":"v12"}`.
