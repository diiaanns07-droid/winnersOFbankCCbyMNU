# Запись на консультацию в отделение

## Часть A. Новый функционал

### Назначение и участники

В мобильном банке клиент занимает одно место на очной консультации или освобождает его. Из существующего календаря клиент открывает карточку конкретного слота. Календарь передаёт slotId. Поиск отделений и публикация слотов выполняются действующим календарём.

**Паспорт.** Мобильный банк, раздел «Отделения». Владелец процесса — управление розничной сети. Путь данных — карточка в приложении → API записи → сервис расписания.

### Функциональные требования

- Ф-1. Карточка показывает время начала в часовом поясе отделения UTC+5 и одно из состояний FREE (свободен), MINE (записан текущий клиент), BUSY (записан другой клиент). Карточка BUSY скрывает личность записанного клиента. Кнопки «Записаться» и «Отменить» доступны соответственно в FREE и MINE в указанные ниже сроки.
- Ф-2. Новая запись возможна, если до начала осталось не менее 15 минут. Время решения — момент атомарной проверки слота на сервере. Сравнение выполняется с точностью до секунды.
- Ф-3. У слота одно место. До начала консультации повторная запись владельца возвращает MINE, в том числе внутри последних 15 минут. Для другого клиента уже занятый слот даёт 409 OCCUPIED. Проверки идут в порядке части B.
- Ф-4. Владелец может отменить запись строго до начала консультации. Успешная отмена освобождает место. Повторная отмена свободного места до начала завершается успешно без изменения данных. При отмене записи другого клиента возвращается 409 OCCUPIED.
- Ф-5. При одновременных изменениях одного слота сервис выполняет проверку и запись как единую операцию. При одном свободном месте и двух разных клиентах успешна только одна запись. На один клиентский идентификатор могут приходиться записи в разных слотах.

### Данные, интеграция и НФТ

- Д-1. Сервис расписания хранит slotId (ровно 12 заглавных латинских букв или цифр), startsAt (момент начала в UTC), holderId (идентификатор клиента либо null). Новая запись меняет только holderId. Закрытые по времени слоты остаются доступны для чтения.
- И-1. Сервис расписания — источник состояния. Он предоставляет атомарное применение операции и возвращает итоговое состояние. При недоступности до фиксации сервис отвечает 503, изменения отсутствуют. Если соединение оборвалось после фиксации, приложение читает карточку тем же GET и показывает фактическое состояние.
- НФ-1. На приёмочном стенде при 40 запросах в секунду не менее 95 % из 12 000 последовательных по времени поступления запросов GET завершаются не дольше чем за 350 мс от получения запроса сервером до окончания записи ответа. Выборка состоит из запросов с действующей сессией к существующим слотам при доступном расписании.

### Критерии приёмки

| ID | До действия | Действие | Результат |
|---|---|---|---|
| КП-1 | Свободный слот начинается в 10:00:00Z | Записаться в 09:45:00Z | 200, MINE |
| КП-2 | Такой же свободный слот | Записаться в 09:45:01Z | 409, TOO_LATE |
| КП-3 | Запись уже принадлежит клиенту | Повторить запись в 09:59:59Z | 200, MINE, владелец прежний |
| КП-4 | Два клиента одновременно записываются в свободный слот за 20 минут до начала | Дождаться двух ответов | Один 200, один 409 OCCUPIED, один владелец |
| КП-5 | Консультация начинается в 10:00:00Z | Владельцу отменить в 09:59:59Z, затем прочитать карточку | 204 без тела, затем 200 с FREE |
| КП-6 | Запись принадлежит клиенту, наступило ровно время начала | Попытаться отменить | 409 STARTED, запись сохранена |

## Часть B. Спецификация REST API

Базовый путь /v1. Все три операции используют сессию Bearer. Сначала проверяется сессия (401 SESSION), затем формат slotId и отсутствие тела и query (400 INPUT), доступность расписания (503 SCHEDULE_DOWN) и наличие слота (404 SLOT). Некорректная сессия проверяется до обращения к расписанию. Слот общедоступен для чтения клиентам с действующей сессией. Все ошибки содержат единственное поле code типа string, тело JSON. Запросы без тела и без query-параметров.

| Операция | Путь | Ответ и порядок проверки после общих проверок |
|---|---|---|
| Прочитать карточку | GET /slots/{slotId} | 200 с объектом Slot, определённым ниже. Чтение доступно и после начала. |
| Записаться | PUT /slots/{slotId}/booking | Сначала при наступившем начале вернуть 409 STARTED. При том же владельце вернуть 200 с Slot. При другом владельце вернуть 409 OCCUPIED. Для свободного места проверить Ф-2, при нарушении вернуть 409 TOO_LATE. Иначе сохранить клиента и вернуть 200 с Slot. |
| Отменить запись | DELETE /slots/{slotId}/booking | При наступившем начале вернуть 409 STARTED. При другом владельце вернуть 409 OCCUPIED. Иначе освободить место и вернуть 204 без тела. |

Slot содержит ровно slotId (string формата Д-1), startsAt (string RFC 3339, UTC с суффиксом Z и секундами), state (string из FREE, MINE, BUSY). При чтении идентификатор владельца в ответ не включается. Пример ответа владельцу для слота 2 декабря — `{"slotId":"BR0000000042","startsAt":"2026-12-02T10:00:00Z","state":"MINE"}`.
