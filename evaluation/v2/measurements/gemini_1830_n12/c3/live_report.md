#### <a id="d-01"></a>🔴 D-01. Не определено ключевое событие карточной операции для расчёта расходов

**Проблема.** В цели строки 23 декларируется информирование в момент покупки, а в Ф-2 строка 38 указаны проведённые покупки (клиринг, с задержкой в 1-3 дня). Не определено, какое именно событие процессинга является триггером расчёта.  
**Сценарий.** Покупка 15-го числа с превышением порога: при авторизации push уйдёт 15-го числа, а при клиринге — 17-го числа, что противоречит цели информирования в момент покупки.

**Как исправить.** Явно зафиксировать событие карточного процессинга (авторизация или клиринг), которое запускает пересчёт лимита.

#### <a id="d-03"></a>🔴 D-03. Противоречие правила Ф-2 и критерия приёмки по месяцу покупки

#### <a id="d-04"></a>🔴 D-04. Противоречие ограничения одного push в месяц и правила отправки при смене порога Ф-4

#### <a id="d-05"></a>🟠 D-05. Противоречие в коде ответа при ошибочной сумме

**Как исправить.** Либо добавить result во все тела ошибок, либо указать в таблице ответа, при каких кодах поле result присутствует.  
**Предлагаемая формулировка (места «<уточнить>» заполнит ответ владельца).** «result | <уточнить: тип> | Обязательно во всех ответах | Признак результата»  
*Существенный, блокирует разработку · критерий «Согласованность» (ISO/IEC/IEEE 29148:2018 п. 5.2.6; IEEE 830-1998 п. 4.3.4) · требование [R-31](#r-31 "Параметр result ответа") · нашли: правило «контракт API»*

#### <a id="d-18"></a>🟠 D-18. Несогласованность кодов ответа 403 и 404 при запросе чужой карты

- Часть B › 200. Successful — Created, строка 175: «403. Ответ в случае, если на указанный ресурс доступ запрещен»
- Часть B › 403. Unsuccessful — Forbidden, строки 188 и 189: «403. Unsuccessful — Forbidden» · «Для чужой карты возвращается 404, как и для отсутствующей карты»

**Проблема.** В строке 175 для запрета доступа указан статус 403, а в строке 189 для чужой карты требуется возвращать 404 Not Found, которого нет в списке статусов.  
**Сценарий.** Клиент отправляет запрос с валидным токеном, но указывает `cardId` другого клиента. Статус 403: возвращается HTTP-код 403 Forbidden. Описание API, строка 189: возвращается HTTP-код 404 Not Found.  
**Последствия.** Противоречие в обработке ошибок, невозможность написать однозначные автотесты.  
**Как исправить.** Зафиксировать единый код HTTP-ответа (404 или 403) для чужой карты.  
**Предлагаемая формулировка (места «<уточнить>» заполнит ответ владельца).** «404. <уточнить: когда возвращается>. Тело ответа: <уточнить>.»  
**Вопрос владельцу.** Что верно: «возвращается HTTP-код 403 Forbidden» (как в «Статус 403») или «возвращается HTTP-код 404 Not Found» (как в «описание API, строка 189»)?  
*Существенный, блокирует разработку и тестирование · критерий «Согласованность» (ISO/IEC/IEEE 29148:2018 п. 5.2.6; IEEE 830-1998 п. 4.3.4) · требования [R-38](#r-38 "Статус 403 запрета доступа"), [R-40](#r-40 "Правило обработки чужой карты 404") · нашли: проверка набора, правило «контракт API»*

**Шкала серьёзности**

- 🔴 **Критичный** — два места документа дают несовместимый результат для одного входа; ключевое правило нельзя однозначно реализовать или проверить; нет информации, без которой основную функцию не реализовать.
- 🟠 **Существенный** — неоднозначность или неполнота, ведущая к неверной реализации или спору при приёмке; непокрытая ветка (ошибки, повторы, отмены, границы); риск ИБ; расхождение типов, единиц, терминов.
- 🟡 **Незначительный** — оформление, незаполненный шаблон, версия и согласования, отсутствие ID и приоритетов, стиль.

**Вердикт.** Критичный дефект, блокирующий разработку, — разработку начинать нельзя; то же для тестирования. Иначе при трёх и более существенных дефектах по направлению — «можно с условиями»: начинать части, не затронутые дефектами, и исправлять их параллельно. Иначе — «можно». Частичный прогон не даёт «можно»: в лучшем случае «с условиями».

**Сверка цитат.** Сравнение без учёта регистра, вида кавычек и тире, лишних пробелов и разметки; цитата ищется у указанной строки, затем во всём документе, ближе к требованию. Нечёткое совпадение (не ниже 92 %) допускается только рядом с указанной строкой.
