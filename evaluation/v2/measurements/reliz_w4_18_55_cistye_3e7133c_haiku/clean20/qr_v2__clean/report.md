**<a id="q-01"></a>Q-01** Путь вызова перевода отправителем · можно ответить позже · кому: Архитектор · к [D-01](#d-01)  
Идёт ли перевод по QR-коду от приложения отправителя через сервис QR-кодов или напрямую в сервис переводов? В архитектуре и в схеме метода перевод идёт через сервис QR-кодов, а в sequence-диаграмме приложение отправителя вызывает сервис переводов напрямую.  
Где: Часть A › Архитектура решения, строка 25: «Приложение отправителя → сервис QR-кодов → сервис переводов → антифрод»; Часть A › Sequence Diagram, строка 45: «Приложение отправителя → сервис переводов: выполнить перевод по QR-коду»; Часть B › Схема, строка 139: «Приложение отправителя → QrTransferController → сервис QR-кодов → сервис переводов»

- **A** Перевод идёт через сервис QR-кодов: приложение отправителя вызывает метод перевода, сервис QR-кодов проверяет QR-код и передаёт операцию в сервис переводов; диаграмма и архитектура переписываются под этот путь
- **B** Приложение отправителя вызывает сервис переводов напрямую; сервис QR-кодов только выдаёт данные QR-кода, архитектура и схема метода переписываются под этот путь

Зачем: Без выбора нельзя определить, кто проверяет QR-код перед списанием и какой сервис отвечает за идемпотентность `requestId`; реализация и интеграционные тесты пойдут по разным путям.

**Шкала серьёзности**

- 🔴 **Критичный** — два места документа дают несовместимый результат для одного входа; ключевое правило нельзя однозначно реализовать или проверить; нет информации, без которой основную функцию не реализовать.
- 🟠 **Существенный** — неоднозначность или неполнота, ведущая к неверной реализации или спору при приёмке; непокрытая ветка (ошибки, повторы, отмены, границы); риск ИБ; расхождение типов, единиц, терминов.
- 🟡 **Незначительный** — оформление, незаполненный шаблон, версия и согласования, отсутствие ID и приоритетов, стиль.

**Вердикт.** Критичный дефект, блокирующий разработку, — разработку начинать нельзя; то же для тестирования. Иначе при трёх и более существенных дефектах по направлению — «можно с условиями»: начинать части, не затронутые дефектами, и исправлять их параллельно. Иначе — «можно». Частичный прогон не даёт «можно»: в лучшем случае «с условиями».

**Сверка цитат.** Сравнение без учёта регистра, вида кавычек и тире, лишних пробелов и разметки; цитата ищется у указанной строки, затем во всём документе, ближе к требованию. Нечёткое совпадение (не ниже 92 %) допускается только рядом с указанной строкой.
