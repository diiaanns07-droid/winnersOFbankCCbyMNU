### 3.2. Критичные и существенные дефекты

#### <a id="d-01"></a>🟠 D-01. Дата выдачи кредита нужна для Ф-3, но не передаётся из АБС

- Ф-3, строка 34: «а если погашений не было — дата выдачи кредита»
- Часть A › Требования к интеграции, строка 50: «дата предыдущего погашения, дата очередного платежа»

**Проблема.** Ф-3 берёт дату выдачи, если погашений не было (строка 34), но в перечне полей GET `/abs/loans/{loanId}` (строка 50) даты выдачи нет, а дата предыдущего погашения для нового кредита не определена.  
**Сценарий.** Кредит выдан 01.02.2027, первое досрочное погашение 15.03.2027 до первого платежа. Дату выдачи для процентов взять неоткуда, расчёт невозможен или неверен.  
**Последствия.** Разработчик не сможет посчитать проценты для кредита без платежей, тестировщик не сможет проверить этот случай; клиент может получить неверную сумму.  
**Как исправить.** Добавить дату выдачи кредита в перечень данных АБС или явно указать, что АБС возвращает в поле даты предыдущего погашения для кредита без погашений.  
**Было → стало.** Строка 50: «дата предыдущего погашения, дата очередного платежа» → «дата предыдущего погашения (при отсутствии погашений — дата выдачи кредита), дата очередного платежа»  
**Вопрос владельцу.** Возвращает ли АБС дату выдачи кредита и где она находится в ответе? → [Q-01](#q-01) (варианты ответа)  
*Существенный, блокирует разработку · критерий «Полнота требования» (ISO/IEC/IEEE 29148:2018 п. 5.2.5; IEEE 830-1998 п. 4.3.3) · требования [R-012 / Ф-3](#r-012 "Расчёт процентов по ставке, делённой на 360, за дни"), [R-024](#r-024 "Методы АБС: данные кредита, расчёт, проведение, статус") · нашли: аналитик, архитектор, проверка набора*

**<a id="q-01"></a>Q-01** Дата выдачи кредита для первого расчёта процентов · можно ответить позже · кому: Архитектор · к [D-01](#d-01)  
Откуда берётся дата выдачи кредита для расчёта процентов первого погашения, если погашений ещё не было: АБС её возвращает, и в каком поле, или правило должно опираться на другую дату?  
Где: Ф-3, строка 34: «а если погашений не было — дата выдачи кредита»; Часть A › Требования к интеграции, строка 50: «дата предыдущего погашения, дата очередного платежа»

- **A** АБС добавляет в ответ GET `/abs/loans/{loanId}` поле дата выдачи, и Ф-3 использует его при отсутствии погашений
- **B** Для кредита без погашений используется дата первого очередного платежа минус один месяц, а не дата выдачи
- **C** Для кредита без погашений досрочное погашение недоступно до первого платежа по графику, код отказа — `OVERDUE_DEBT`

Зачем: Без источника даты разработчик не может посчитать проценты первого досрочного погашения, и расчёт по Ф-3 нельзя проверить на первом погашении.

## <a id="pe"></a>Приложение Е. Методика

Статическое ревью текста до разработки: программа не запускается. Документ нумеруется построчно; проверяющие роли (аналитик, тестировщик, архитектор, риски, набор целиком) предлагают кандидатов с дословными цитатами; программа находит каждую цитату в документе и сама определяет строку; судья объединяет дубли, отклоняет ложные и калибрует серьёзность; вердикт считает программа.

**Шкала серьёзности**

- 🔴 **Критичный** — два места документа дают несовместимый результат для одного входа; ключевое правило нельзя однозначно реализовать или проверить; нет информации, без которой основную функцию не реализовать.
- 🟠 **Существенный** — неоднозначность или неполнота, ведущая к неверной реализации или спору при приёмке; непокрытая ветка (ошибки, повторы, отмены, границы); риск ИБ; расхождение типов, единиц, терминов.
- 🟡 **Незначительный** — оформление, незаполненный шаблон, версия и согласования, отсутствие ID и приоритетов, стиль.

**Вердикт.** Критичный дефект, блокирующий разработку, — разработку начинать нельзя; то же для тестирования. Иначе при трёх и более существенных дефектах по направлению — «можно с условиями»: начинать части, не затронутые дефектами, и исправлять их параллельно. Иначе — «можно». Частичный прогон не даёт «можно»: в лучшем случае «с условиями».

**Сверка цитат.** Сравнение без учёта регистра, вида кавычек и тире, лишних пробелов и разметки; цитата ищется у указанной строки, затем во всём документе, ближе к требованию. Нечёткое совпадение (не ниже 92 %) допускается только рядом с указанной строкой.
