34Функциональные требования
35R-05Ф-1. Клиент обменивает средства между двумя своими текущими счетами (type = CURRENT) со статусом OPEN. Поддерживаемые пары: KZT → USD, KZT → EUR, KZT → RUB и обратные USD → KZT, EUR → KZT, RUB → KZT. Обмен между двумя иностранными валютами и между счетами в одной валюте не выполняется.
36R-06Ф-2. Клиент вводит сумму списания в валюте счёта списания; сумма зачисления не вводится, а рассчитывается по Ф-6.
37R-07Ф-3. Лимит суммы списания в валюте счёта списания, обе границы включительно: KZT — от 1 000.00 до 10 000 000.00; USD и EUR — от 2.00 до 20 000.00; RUB — от 200.00 до 2 000 000.00. Сумма зачисления лимитом не ограничивается; других ограничений суммы, кроме Ф-3 и Ф-4, нет.
38R-08Ф-4. Сумма списания не больше доступного остатка счёта списания (равенство допускается). Остаток проверяется при создании котировки по данным сервиса счетов и повторно АБС при проводке; котировка средства не резервирует.
39R-09Ф-5. Тип курса определяется по времени получения запроса котировки: рабочее время (WORKING) — с 09:00:00 включительно до 18:00:00 не включительно в день, отмеченный рабочим в производственном календаре АБС; всё остальное время — нерабочее (NON_WORKING). Курсы обоих типов публикует сервис курсов.
40R-10Ф-6. Курс котировки — число KZT за 1 единицу иностранной валюты с двумя знаками после точки: для обмена из KZT — курс продажи (банк продаёт иностранную валюту), для обмена в KZT — курс покупки (банк покупает иностранную валюту). Сумма зачисления: из KZT — сумма списания ÷ курс, в KZT — сумма списания × курс; результат округляется вниз до 0.01 единицы валюты зачисления (знаки после второго отбрасываются, разница остаётся у банка). Комиссия за обмен не взимается.
41R-11Ф-7. Котировка фиксирует счета, суммы, курс и тип курса и действует 60 секунд: expiresAt = createdAt + 60 с, где createdAt — время получения запроса котировки. Обмен выполняется по курсу котировки, если запрос обмена получен сервисом обмена не позднее expiresAt, даже если тип курса к этому времени сменился; время обмена executedAt может быть позже expiresAt. Запрос, полученный позже expiresAt, отклоняется с errorCode = QUOTE_EXPIRED.D-05D-06
42R-12Ф-8. По одной котировке выполняется не более одного обмена. Повторный запрос с тем же ключом идемпотентности (quoteId + requestId) возвращает результат выполненного обмена и не создаёт второй; срок хранения ключа и остальные случаи — часть B, особое правило 1.D-01
43R-13Ф-9. Списание и зачисление выполняются одной проводкой АБС: проходят обе или ни одна. Если АБС отказала в проводке, остатки не меняются; если не дала результата за время таймаута (И-2), сервис обмена отменяет проводку (часть B, особое правило 2). В обоих случаях обмен не выполнен, котировка действует до expiresAt.D-07D-08
44R-14Ф-10. После выполненного обмена клиент получает один push: «Обмен выполнен: списано {debitAmount} {debitCurrency}, зачислено {creditAmount} {creditCurrency}, курс {rate} KZT за 1 {foreignCurrency}», где {foreignCurrency} — валюта пары, отличная от KZT. Номера счетов в push не входят; невыполненный обмен push не порождает; сбой отправки push не меняет результат обмена.

55Требования к интеграции
56R-18И-1. Приложение создаёт котировку и выполняет обмен по котировке через дочерний документ «Обмен валюты между своими счетами — REST API» (часть B, методы 2 и 1); список счетов получает существующим методом сервиса счетов GET /accounts/v1/accounts (поля accountId, maskedNumber, currency, type, status, availableBalance). И-2. Сервис обмена вызывает существующие методы без их доработки (суммы и курсы — в формате части B): сервис счетов GET /accounts/v1/accounts/{accountId} (clientId, currency, type, status, availableBalance); АБС GET /abs/v1/calendar/{date} (workingDay: true / false), POST /abs/v1/fx-postings (проводка одной транзакцией с ключом exchangeId; результат «проведено», «недостаточно средств», «счёт недоступен» или «отказ») и POST /abs/v1/fx-postings/{exchangeId}/cancel (отмена проводки, результат «отменено»); сервис курсов GET /rates/v1/retail?currency={currency}&rateType={rateType} (buyRate, sellRate); сервис уведомлений POST /notifications/v1/push (clientId, text). Таймаут ожидания ответа — 10 с для проводки АБС и 3 с для остальных методов. И-3. Если ответ метода 1 не получен за 15 с, приложение один раз повторяет запрос с тем же requestId; каждое новое нажатие «Подтвердить» создаёт новый requestId. И-4. Push передаётся в сервис уведомлений после проводки асинхронно и не задерживает ответ метода 1; при ответе сервиса уведомлений с ошибкой передача повторяется до 2 раз с интервалом 10 с, после чего push не отправляется; при отсутствии ответа за время таймаута (И-2) повтор не выполняется.
