# Что у соперников действительно делает код

Срез 27 ноября. Ниже результаты чтения исполняемых путей, повторного подсчёта по опубликованным данным и запуска узких автономных функций на новой паре ТЗ F4. Участие модели в полном прогоне соперников в этом опыте не измерялось. [Числа, входные хеши и ревизии](code-observations.json)

## Кто меняет вердикт при изменении ТЗ

**yerassyl-sailaubay.** В обычном CLI вход читается с переданного пути. Извлечение, сквозная проверка и критик получают блоки этого документа. Вызов модели идёт через OpenAI Responses. В промпте есть подсказки о конфликтах лимитов частоты, кодов HTTP и выключенного переключателя. Эти подсказки близки к выданному банковскому примеру. Для попадания в отчёт всё равно нужны найденные цитаты. [Вход](https://github.com/yerassyl-sailaubay/bcc-case/blob/4e5fc8bc801deb3f0290596eafc24a914960b86b/src/bcc_review/cli.py#L65) · [Обращение к модели](https://github.com/yerassyl-sailaubay/bcc-case/blob/4e5fc8bc801deb3f0290596eafc24a914960b86b/src/bcc_review/engine.py#L116) · [Входы критика](https://github.com/yerassyl-sailaubay/bcc-case/blob/4e5fc8bc801deb3f0290596eafc24a914960b86b/src/bcc_review/engine.py#L251) · [Ориентиры промпта](https://github.com/yerassyl-sailaubay/bcc-case/blob/4e5fc8bc801deb3f0290596eafc24a914960b86b/src/bcc_review/engine.py#L37)

По исходным полям `findings.severity` и `impact` в 42 записях пересчитал обе готовности по правилам рендера. В паре про права доступа решение сменилось с «нет блокера» на «требует решения» 3/3, в паре про возвраты — 3/3, про срок действия кода — 1/3. В отдельной паре про единицы времени — 1/1. По отложенным дефектам итого 7/9. Контроли — пять различных входов, 11 прогонов. Ложных блокировок ноль, но в трёх контрольных прогонах остались major, суммарно на контролях пять карточек. Один проход модели на тех же контролях дал ноль карточек. При правке только месяца в официальном ТЗ остаются другие блокеры и прежний запрет в целом. У новой серии опубликованы 20/29 и 13/15. Авторы указывают каталоги `.artifacts/precision-95` и `.artifacts/architecture-robustness-20261127`. В полных деревьях трёх проверенных веток этих каталогов нет. Сырой пересчёт предыдущего C и оценку авторов о шести новых документах стоит показывать раздельно. **QAIRU.** У CLI отдельные реализации настоящего вызова Claude, чтения прежнего журнала и тестовых ответов. После уточнения по оставшимся карточкам пересчитывается светофор. По собственной неслепой вычитке команды 20/27 находок описывают именно внесённый дефект. В десяти сохранённых отчётах, включая оба исходных документа и две одиночные мутации, светофор везде красный. Оба исходника уже дефектны. На их основе нельзя присвоить QAIRU место по ложным запретам на чистых ТЗ. ## Что меняется на общей новой паре F4

Одна замена в банковском ТЗ изменила верхнюю границу REST API с 12 700 до 24 500 тенге. В функциональном требовании осталось 12 700. Каждый содержательный абзац передавался как одна единица с той же цитатой и номером строки. Автономный код взят по закреплённым SHA. Вклад модельного выделения требований и решения судьи здесь отсутствует. [Сырой результат](code-observations.json)

У **VllSunday** проявилось конкретное ограничение для владельца. Ключ ответа вычисляется из нормализованного текста вопроса. После добавочных пробелов ключ остался `fa0d1b09`. Перефразировка «Какой верхний предел суммы одного перевода?» → «Какова максимальная сумма одного перевода?» дала `5630cab2`. Этап перепроверки ищет ответ только по этому ключу, поэтому ранее введённое решение попадёт в число непривязанных, если агент на следующем прогоне переформулирует вопрос именно так. Сам этап с найденными ответами действительно вызывает модель.
