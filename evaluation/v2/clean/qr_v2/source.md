## Часть A. Новый функционал

### Общие сведения

| Поле | Значение |
| :--- | :--- |
| **Наименование задачи** | Перевод между клиентами банка по QR-коду |
| **Продукт** | Мобильный банк, переводы |
| **Бизнес-процесс** | Переводы между физическими лицами |
| **Business owner / Product owner / Аналитик** | Дирекция розничных платежей / владелец раздела «Переводы» / аналитик команды переводов |
| **Тип работы** | Новый функционал |
| **Влияние на ИС** | Мобильный банк, сервис QR-кодов, сервис переводов, антифрод, сервис уведомлений |
| **Задача в JIRA** | PAY-1182 |

### Цели
Клиент получает перевод от другого клиента банка, показав QR-код на экране телефона, без диктовки номера карты или телефона. Снизить число переводов по ошибочным реквизитам.

### Архитектура решения
Приложение получателя → сервис QR-кодов. Приложение отправителя → сервис QR-кодов → сервис переводов → антифрод. Сервис переводов → сервис уведомлений.

### Дизайн процесса UI
Получатель: Платежи → «Получить по QR» → выбор карты зачисления, необязательное поле «Сумма, ₸» и кнопка «Создать QR». QR-код показывается с таймером обратного отсчёта и кнопкой «Отменить».
Отправитель: Платежи → «Сканировать QR» → экран подтверждения с маскированным именем получателя («Айгерим С.»), суммой, картой списания, надписью «Без комиссии» и кнопкой «Перевести». Если сумма задана в QR-коде, изменить её нельзя.

### Требования к изменениям

#### BPMN схема процесса
Создание QR-кода получателем → сканирование отправителем → проверка QR-кода → подтверждение отправителем → проверка антифродом → списание и зачисление → push получателю и отправителю → завершение.

#### Функциональные требования
* **Ф-1.** Получатель — клиент банка с активной картой KZT. QR-код создаётся без суммы или с суммой от 100 до 500 000 ₸ включительно; сумма — целое число тенге.
* **Ф-2.** QR-код действует 15 минут с момента создания. QR-код с суммой можно оплатить один раз, QR-код без суммы — несколько раз в течение срока действия. QR-код с суммой считается оплаченным с момента, когда сервис переводов принял перевод по нему в обработку; если перевод отклонён (`REJECTED`) или не выполнен из-за ошибки, QR-код снова можно оплатить до конца срока действия.
* **Ф-3.** Перед подтверждением отправитель видит маскированное имя получателя, сумму и надпись «Без комиссии». Для QR-кода без суммы отправитель вводит сумму от 100 до 500 000 ₸.
* **Ф-4.** Комиссия за перевод по QR-коду не взимается.
* **Ф-5.** Получатель может отменить QR-код, если он не оплачен (для QR-кода с суммой) и по нему нет перевода в обработке. Если отправитель подтверждает перевод после отмены, он получает «QR-код недействителен» (ответ 410). После отмены или истечения срока действия при сканировании показывается «QR-код недействителен».
* **Ф-6.** После зачисления получатель и отправитель получают push с суммой перевода и маскированным именем второй стороны.

### Sequence Diagram
Приложение получателя → сервис QR-кодов: создать QR-код. Приложение отправителя → сервис QR-кодов: получить данные QR-кода. Приложение отправителя → сервис переводов: выполнить перевод по QR-коду. Сервис переводов → антифрод: проверить операцию. Сервис переводов → сервис уведомлений: перевод зачислен.

### Нефункциональные требования
Создание QR-кода и получение его данных — не дольше 500 мс для 95 % запросов; перевод по QR-коду — не дольше 3 с для 95 % запросов от получения запроса до ответа. Сервис выдерживает 200 переводов по QR-коду в секунду.

### Требования к данным
QR-код содержит только идентификатор QR-кода; карта получателя и сумма хранятся в сервисе QR-кодов и в QR-код не выводятся. Хранить идентификатор QR-кода, идентификатор клиента-получателя, карту зачисления, сумму в тенге, время создания, срок действия `ttl` в минутах, статус (активен, оплачен, отменён, истёк) и идентификаторы переводов.

### Требования к интеграции
Приложения создают и отменяют QR-код, получают данные QR-кода перед подтверждением и выполняют перевод через дочерний документ «Перевод по QR-коду — REST API». Повторный запрос перевода с тем же `requestId` не создаёт второй перевод.

### Требования к тестированию

#### Тестирование требований
Функциональные тесты — по функциональным требованиям и таблице «Критерии приемки» на тестовом стенде; негативные тесты — по каждому коду ответа части B; нагрузочный тест — по нефункциональным требованиям.

### Критерии приемки

| Исходные условия | Действие | Ожидаемый результат |
| :--- | :--- | :--- |
| QR-код без суммы создан в 10:00 | Отсканировать в 10:14 и перевести 5 000 ₸ | Перевод выполнен, получатель получил push |
| QR-код с суммой 3 000 ₸ создан в 10:00 | Отсканировать в 10:16 | Показано «QR-код недействителен» |
| QR-код на сумму 500 000 ₸ | Подтвердить перевод | Перевод выполнен на 500 000 ₸ |
| QR-код с суммой 7 000 ₸ уже оплачен | Отсканировать повторно | Показано «QR-код недействителен» |
| Получатель отменил QR-код | Отсканировать | Показано «QR-код недействителен» |

## Часть B. REST API

Дочерний документ части A: «Перевод по QR-коду — REST API». Метод 1 — перевод по QR-коду; методы 2–4 сервиса QR-кодов (создание, получение данных и отмена QR-кода) описаны в конце документа.

### Общие параметры

| Поле | Значение |
| :--- | :--- |
| **Description** | Выполнение перевода по QR-коду |
| **REST type** | POST |
| **Authorization** | Bearer, сессия клиента-отправителя |
| **Controller** | QrTransferController |
| **URL type** | Dev / Prod |
| **Request URL** | Dev: `https://api-dev.bank.local/qr/transfer` . Prod: `https://api.bank.local/qr/transfer` |
| **CURL** | `curl -X POST "$BASE/qr/transfer" -H "Authorization: Bearer $TOKEN" -H "Content-Type: application/json" -d '{"qrId":"qr-7b31","cardId":"c-2001","amount":5000,"requestId":"7c1e9a52-4b7d-4f0e-9a51-2d3c5e6f7a80"}'` |
| **Swagger** | `https://api-dev.bank.local/swagger/qr-transfer` |
| **Gitlab project** | payments/qr-transfer |
| **Framework** | Spring Boot 3 |
| **Author** | Аналитик команды переводов |
| **Developer** | Команда переводов |

### Логика работы метода
1. Проверить сессию отправителя.
2. Проверить, что карта списания принадлежит отправителю, активна и открыта в тенге; если нет, вернуть 400.
3. Найти QR-код по `qrId`. Если QR-код не найден, вернуть 404. Если карта зачисления получателя закрыта или заблокирована, вернуть 410.
4. Проверить срок действия: текущее время не позже времени создания QR-кода + `ttl` минут. Если срок истёк или QR-код отменён, вернуть 410.
5. Если в QR-коде задана сумма, использовать её, а поле `amount` запроса не учитывать. Если суммы нет, поле `amount` обязательно: от 100 до 500 000 ₸, иначе вернуть 400.
6. Проверить, что QR-код с суммой ещё не оплачен; если оплачен, вернуть 410.
7. Передать операцию в антифрод. При отказе антифрода вернуть 200 со `status` = `REJECTED`.
8. Выполнить списание и зачисление одной операцией сервиса переводов (если на карте списания недостаточно средств или произошёл сбой, не проводится ни одна из них; ответ 400 или 500 соответственно) и вернуть результат.

### Особые правила
1. QR-код без суммы, как и QR-код с суммой, действует 15 минут с момента создания (Ф-2).
2. Повторный запрос с тем же `requestId` возвращает результат первого запроса.

### Схема
```text
Приложение отправителя → QrTransferController → сервис QR-кодов → сервис переводов (антифрод, списание, зачисление) → QrTransferController → приложение.
```

### Параметры запроса

#### Path-параметры
Не используются.

#### Request body
Content-Type: `application/json`.

| Parameter | Format | Size | Mandatory | Logic | Description | DB field |
| :--- | :--- | :--- | :--- | :--- | :--- | :--- |
| `qrId` | string | 1–36 | Да | Из QR-кода | Идентификатор QR-кода | `qr_id` |
| `cardId` | string | 1–64 | Да | Карта отправителя | Карта списания | `debit_card_id` |
| `amount` | integer | 32 bit | Нет | 100–500 000 | Сумма в тенге, если в QR-коде нет суммы | `amount_kzt` |
| `requestId` | string | 36 | Да | UUID | Ключ идемпотентности | `request_id` |

### Ответ
Если результат 200 — запрос обработан: перевод выполнен (`DONE`) или отклонён антифродом (`REJECTED`). Если результат 400, 401, 404, 410 или 500 — неуспешный.

| Parameter | Format | Logic | Description | DB field |
| :--- | :--- | :--- | :--- | :--- |
| `status` | string | DONE / REJECTED | Результат перевода | `status` |
| `transferId` | string | При DONE | Идентификатор перевода | `transfer_id` |
| `amount` | integer | — | Сумма перевода в тенге | `amount_kzt` |
| `recipientName` | string | «Имя Ф.» | Маскированное имя получателя | — |
| `message` | string | При REJECTED или ошибке | Описание результата | — |

### Статусы

**200.** Ответ в случае, если перевод выполнен или отклонён антифродом.  
**400.** Ответ в случае, если параметры запроса заполнены неверно, карта списания недоступна или на ней недостаточно средств.  
**401.** Ответ в случае, если запрос выполнен без необходимой авторизации.  
**404.** Ответ в случае, если QR-код не найден.  
**410.** Ответ в случае, если срок действия QR-кода истёк, QR-код отменён получателем, QR-код с суммой уже оплачен или карта получателя недоступна.  
**500.** Ответ в случае, если произошла внутренняя ошибка сервера.

#### 200. Successful
```json
{"status":"DONE","transferId":"tr-90311","amount":5000,"recipientName":"Айгерим С."}
```

#### 400. Unsuccessful — Bad request
```json
{"message":"Некорректный запрос"}
```

#### 401. Unsuccessful — Unauthorized
```json
{"message":"Требуется вход"}
```

#### 404. Unsuccessful — Not found
```json
{"message":"QR-код не найден"}
```

#### 410. Unsuccessful — Gone
```json
{"message":"QR-код недействителен"}
```

#### 500. Unsuccessful — Internal server error
```json
{"message":"Ошибка сервиса"}
```

### Методы сервиса QR-кодов

Методы 2–4 используют ту же авторизацию (Bearer, сессия клиента), Gitlab project и Framework, что и метод 1; ответы 401 и 500 — как у метода 1; тело остальных ошибок — `{"message":"…"}`, для 410 — «QR-код недействителен». Время в ответах — по Астане (UTC+5).

| Метод | REST type и URL | Параметры | Ответ 200 | Ошибки |
| :--- | :--- | :--- | :--- | :--- |
| 2. Создание QR-кода | POST `/qr` | body: `cardId` (string, 1–64, обязательный) — карта зачисления получателя; `amount` (integer, необязательный) — сумма в тенге, 100–500 000 | `{"qrId":"qr-5f2a","qrPayload":"BANKQR:qr-5f2a","expiresAt":"2026-03-01T10:15:00+05:00"}` | 400 — сумма вне диапазона, карта не активна или открыта не в тенге; 404 — карта не найдена или принадлежит другому клиенту |
| 3. Данные QR-кода | GET `/qr/{qrId}` | path: `qrId` (string, 1–36, обязательный) | `{"recipientName":"Айгерим С.","amount":3000,"expiresAt":"2026-03-01T10:15:00+05:00"}`; для QR-кода без суммы `amount` = `null` | 404 — QR-код не найден; 410 — срок действия истёк, QR-код отменён или (для QR-кода с суммой) уже оплачен |
| 4. Отмена QR-кода | DELETE `/qr/{qrId}` | path: `qrId` (string, 1–36, обязательный); отменить может только получатель | `{"status":"CANCELLED"}` | 404 — QR-код не найден или принадлежит другому клиенту; 410 — QR-код с суммой уже оплачен, по QR-коду есть перевод в обработке, QR-код уже отменён или срок истёк |
