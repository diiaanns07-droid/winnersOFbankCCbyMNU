## Часть A. Новый функционал

### Общие сведения

| Поле | Значение |
| :--- | :--- |
| **Наименование задачи** | Выбор способа выплаты процентов по накопительному счёту: капитализация или перечисление на карту |
| **Продукт** | Мобильный банк, сбережения |
| **Бизнес-процесс** | Обслуживание накопительных счетов |
| **Business owner / Product owner / Аналитик** | Дирекция пассивных продуктов / владелец раздела «Накопления» / аналитик команды сбережений |
| **Тип работы** | Новый функционал |
| **Влияние на ИС** | Мобильный банк, API сбережений, депозитный модуль, сервис уведомлений |
| **Задача в JIRA** | SAV-631 |

### Цели
Клиент сам выбирает, прибавлять проценты по накопительному счёту к остатку или получать их на карту, и видит, сколько процентов начислено за текущий месяц. Снизить число обращений в контакт-центр о способе выплаты процентов.

### Архитектура решения
Мобильное приложение → API сбережений → депозитный модуль. Депозитный модуль → сервис уведомлений → push-уведомление клиенту.

### Дизайн процесса UI
Накопления → накопительный счёт → «Проценты». На экране: ставка, проценты за текущий месяц, переключатель «Капитализация / На карту», выбор карты для выплаты (виден при выборе «На карту»), кнопка «История начислений» и кнопка «Сохранить». После сохранения под переключателем показывается дата, с которой действует новый способ.

### Требования к изменениям

#### BPMN схема процесса
Ежедневное начисление процентов → последний день месяца → определение способа выплаты → капитализация или перечисление на карту → push клиенту → завершение.

#### Функциональные требования
* **Ф-1.** Владелец накопительного счёта в тенге выбирает способ выплаты процентов: капитализация (проценты прибавляются к остатку счёта) или перечисление на свою карту KZT. По умолчанию — капитализация.
* **Ф-2.** Проценты начисляются ежедневно на остаток счёта на конец дня по ставке 14 % годовых, база — фактическое число дней в году. Остаток на конец дня — остаток счёта на 23:59:59 по времени Астаны (UTC+5). Проценты, начисленные за месяц, выплачиваются в последний календарный день месяца.
* **Ф-3.** Новый способ выплаты применяется начиная со следующего календарного месяца; проценты текущего месяца выплачиваются прежним способом. Проценты, выплачиваемые на карту, перечисляются на последнюю карту, указанную клиентом для способа «На карту».
* **Ф-4.** Если остаток счёта на конец дня меньше неснижаемого остатка 1 000 ₸, проценты за этот день не начисляются.
* **Ф-5.** После выплаты клиент получает push с суммой процентов и способом выплаты. Если на дату выплаты карта для выплаты не активна (закрыта или заблокирована), проценты за месяц капитализируются, а в push указывается причина.
* **Ф-6.** При закрытии счёта проценты за неполный месяц выплачиваются в день закрытия вместе с остатком счёта.

### Sequence Diagram
Приложение → API сбережений: получить условия и проценты. Приложение → API сбережений: сохранить способ выплаты. API сбережений → депозитный модуль: записать способ с 1-го числа следующего месяца. Депозитный модуль → сервис уведомлений: проценты выплачены.

### Нефункциональные требования
Ежедневные проценты округляются до тиына по математическому правилу; проценты за месяц — сумма округлённых ежедневных. Методы API отвечают не дольше 1 с для 95 % запросов, доступность — не ниже 99,9 % в месяц.

### Требования к данным
Хранить идентификатор счёта, способ выплаты, карту для выплаты, дату начала действия нового способа, ставку в процентах годовых, ежедневные начисления и выплаты процентов по месяцам в тенге с точностью до тиына.

### Требования к интеграции
Приложение получает ставку, проценты за текущий месяц и историю начислений и сохраняет способ выплаты через дочерний документ «Проценты по накопительному счёту — REST API».

## Часть B. REST API

Дочерний документ части A: «Проценты по накопительному счёту — REST API». Метод 1 — изменение способа выплаты; методы 2 и 3 (условия и проценты, история начислений) описаны в конце документа.

### Общие параметры

| Поле | Значение |
| :--- | :--- |
| **Description** | Изменение способа выплаты процентов по накопительному счёту |
| **REST type** | PUT |
| **Authorization** | Bearer, сессия клиента — владельца счёта |
| **Controller** | SavingsInterestController |
| **URL type** | Dev / Prod |
| **Request URL** | Dev: `https://api-dev.bank.local/savings/{accountId}/payout-mode` . Prod: `https://api.bank.local/savings/{accountId}/payout-mode` |
| **CURL** | `curl -X PUT "$BASE/savings/sa-3301/payout-mode" -H "Authorization: Bearer $TOKEN" -H "Content-Type: application/json" -d '{"mode":"CARD","cardId":"c-2001"}'` |
| **Swagger** | `https://api-dev.bank.local/swagger/savings-interest` |
| **Gitlab project** | savings/interest-api |
| **Framework** | Spring Boot 3 |
| **Author** | Аналитик команды сбережений |
| **Developer** | Команда сбережений |

### Логика работы метода
1. Проверить сессию клиента.
2. Проверить, что накопительный счёт принадлежит клиенту и открыт.
3. Если `mode` = `CARD`, проверить, что карта `cardId` принадлежит клиенту, активна и открыта в тенге.
4. Сохранить способ выплаты с датой начала действия — 1-е число следующего месяца по времени Астаны (UTC+5).
5. Вернуть способ выплаты текущего и следующего месяца, ставку и проценты за текущий месяц.

### Особые правила
1. Повторная установка уже выбранного способа не считается ошибкой: возвращается 200 с текущими условиями.
2. Если клиент несколько раз сменил способ в течение месяца, со следующего месяца действует последний выбранный.
3. Для способа `CAPITALIZATION` поле `cardId` не передаётся; переданное значение не сохраняется.

### Схема
```text
Приложение → SavingsInterestController → депозитный модуль → SavingsInterestController → приложение.
```

### Параметры запроса

#### Path-параметры

| Parameter | Format | Size | Mandatory | Logic | Description | DB field |
| :--- | :--- | :--- | :--- | :--- | :--- | :--- |
| `accountId` | string | 1–64 | Да | Счёт клиента | Идентификатор накопительного счёта | `account_id` |

#### Request body
Content-Type: `application/json`.

| Parameter | Format | Size | Mandatory | Logic | Description | DB field |
| :--- | :--- | :--- | :--- | :--- | :--- | :--- |
| `mode` | string | — | Да | CAPITALIZATION / CARD | Способ выплаты процентов с 1-го числа следующего месяца | `next_payout_mode` |
| `cardId` | string | 1–64 | Для CARD | Карта клиента в тенге | Карта для выплаты процентов | `payout_card_id` |

### Ответ
Если результат 200 — успешный. Если результат 400, 401, 404 или 500 — неуспешный.

| Parameter | Format | Logic | Description | DB field |
| :--- | :--- | :--- | :--- | :--- |
| `currentMode` | string | CAPITALIZATION / CARD | Способ выплаты в текущем месяце | `payout_mode` |
| `nextMode` | string | CAPITALIZATION / CARD | Способ выплаты с 1-го числа следующего месяца | `next_payout_mode` |
| `effectiveFrom` | string | ГГГГ-ММ-ДД | Дата начала действия нового способа | `next_mode_from` |
| `rate` | number | — | Годовая ставка, % | `rate` |
| `accruedInterest` | number | ≥ 0 | Проценты, начисленные за текущий месяц по Ф-2 на дату запроса, ₸ | — |

### Статусы

**200.** Ответ в случае успешного выполнения метода.  
**400.** Ответ в случае, если `mode` неизвестен, для `CARD` не передан `cardId` или карта не активна либо открыта не в тенге.  
**401.** Ответ в случае, если запрос выполнен без необходимой авторизации.  
**404.** Ответ в случае, если счёт не найден или закрыт либо счёт или карта принадлежат другому клиенту.  
**500.** Ответ в случае, если произошла внутренняя ошибка сервера.

#### 200. Successful
```json
{"currentMode":"CAPITALIZATION","nextMode":"CARD","effectiveFrom":"2026-04-01","rate":14.0,"accruedInterest":5753.40}
```

#### 400. Unsuccessful — Bad request
```json
{"message":"Некорректный запрос"}
```

#### 401. Unsuccessful — Unauthorized
```json
{"message":"Требуется вход"}
```

#### 404. Unsuccessful — Not found
```json
{"message":"Счёт или карта не найдены"}
```

#### 500. Unsuccessful — Internal server error
```json
{"message":"Ошибка сервиса"}
```
