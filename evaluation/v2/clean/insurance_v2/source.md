## Часть A. Новый функционал

### Общие сведения

| :--- | :--- |
| **Наименование задачи** | Добровольное страхование жизни заёмщика при оформлении кредита наличными в мобильном банке |
| **Продукт** | Мобильный банк, кредиты наличными |
| **Бизнес-процесс** | Выдача кредита наличными |

| **Влияние на ИС** | Мобильный банк, API кредитов, кредитный конвейер, сервис страхования, страховая компания-партнёр, сервис уведомлений |
| **Задача в JIRA** | LOAN-958 |

### Цели
Клиент может добровольно подключить страхование жизни при оформлении кредита наличными и получить ставку ниже, а в период охлаждения — отказаться от страхования в приложении. Увеличить долю кредитов со страхованием без жалоб на навязывание услуги.

### Архитектура решения
Мобильное приложение → API кредитов → кредитный конвейер. API кредитов → сервис страхования. Кредитный конвейер → сервис страхования → страховая компания-партнёр. Сервис страхования → сервис уведомлений.

### Дизайн процесса UI
Кредиты → «Кредит наличными» → экран условий: сумма, срок, флажок «Страхование жизни» (по умолчанию снят; включая его, клиент даёт согласие на передачу персональных данных страховой компании-партнёру), стоимость страхования, ставка со страхованием и без него, ссылка на правила страхования.
После выдачи: Кредиты → кредит → «Страхование» → номер полиса, дата начала действия и кнопка «Отказаться от страхования».

### Требования к изменениям

#### BPMN схема процесса
Выбор условий кредита → подключение страхования по желанию клиента → расчёт премии → подписание договора кредита и заявления на страхование → выдача кредита и оплата премии → выпуск полиса → отказ в период охлаждения и возврат премии (если клиент отказался) → завершение.

#### Функциональные требования
* **Ф-1.** Страхование предлагается при оформлении кредита наличными от 300 000 до 5 000 000 ₸ на срок от 6 до 60 месяцев. Подключение добровольное: флажок по умолчанию снят, отказ от страхования не влияет на одобрение кредита.
* **Ф-2.** Страховая премия равна сумме кредита × 0,15 % × срок кредита в месяцах с округлением до целого тенге по математическим правилам; возврат по Ф-5 округляется так же. Премия оплачивается единовременно из суммы кредита при выдаче, страховая сумма равна сумме кредита.
* **Ф-3.** Ставка по кредиту со страхованием — 24 % годовых, без страхования — 27 % годовых.
* **Ф-4.** Клиент может отказаться от страхования в течение 14 календарных дней с даты выдачи кредита, которая является датой начала действия полиса (сроки в днях здесь и далее отсчитываются со дня, следующего за событием, даты — по времени Астаны, UTC+5: кредит выдан 1 марта — отказ возможен по 15 марта включительно); отказ считается оформленным в момент, когда клиент подтвердил его в приложении; премия возвращается полностью на текущий счёт клиента в течение 7 рабочих дней. После отказа ставка по кредиту повышается до 27 % годовых со дня отказа. По истечении 14 дней кнопка «Отказаться от страхования» недоступна. Если кредит погашен полностью раньше отказа, страхование уже прекращено по Ф-5 и отказ не оформляется.
* **Ф-5.** При полном досрочном погашении кредита страхование прекращается, клиенту возвращается часть премии за полные неиспользованные месяцы. При частичном досрочном погашении страхование, страховая сумма и премия не меняются.
* **Ф-6.** Страхование доступно клиенту от 18 лет, которому на дату окончания кредита будет не больше 65 полных лет.

### Sequence Diagram
Приложение → API кредитов: подключить страхование к заявке. API кредитов → сервис страхования: рассчитать премию и проверить клиента. Сервис страхования → страховая компания-партнёр: предварительная проверка клиента. Кредитный конвейер → сервис страхования: кредит выдан, выпустить полис. Сервис страхования → сервис уведомлений: полис выпущен.

### Нефункциональные требования
Расчёт стоимости и подключение страхования отвечают не дольше 2 с для 95 % запросов, включая предварительную проверку страховой компанией-партнёром. Экран условий показывает стоимость страхования и обе ставки до включения флажка.

### Требования к данным
Хранить идентификатор заявки и кредита, признак подключения страхования, дату выдачи кредита (начала действия полиса), премию в тенге, номер полиса, дату отказа и сумму возврата. Передавать страховой компании-партнёру ИИН, ФИО, дату рождения и номер телефона клиента только после согласия клиента на передачу персональных данных; анкета здоровья не запрашивается.

### Требования к интеграции
Приложение рассчитывает стоимость страхования, подключает его к заявке или снимает с неё до подписания, показывает сведения о полисе и оформляет отказ через дочерний документ «Страхование жизни к кредиту наличными — REST API». Сервис страхования получает номер полиса от страховой компании-партнёра после выдачи кредита.

#### Тестирование требований

## Часть B. REST API

Дочерний документ части A: «Страхование жизни к кредиту наличными — REST API». Метод 1 — подключение страхования; методы 2–5 (расчёт стоимости, отказ от страхования, снятие страхования с неподписанной заявки и сведения о полисе) описаны в конце документа.

### Общие параметры

| Поле | Значение |
| :--- | :--- |
| **Description** | Подключение страхования жизни к заявке на кредит наличными |
| **REST type** | POST |
| **Authorization** | Bearer, сессия клиента — заявителя по кредиту |
| **Controller** | LoanInsuranceController |
| **URL type** | Dev / Prod |
| **Request URL** | Dev: `https://api-dev.bank.local/loans/applications/{applicationId}/insurance` . Prod: `https://api.bank.local/loans/applications/{applicationId}/insurance` |
| **CURL** | `curl -X POST "$BASE/loans/applications/la-7781/insurance" -H "Authorization: Bearer $TOKEN" -H "Content-Type: application/json" -d '{"amount":1000000,"term":24,"consentPd":true}'` |
| **Swagger** | `https://api-dev.bank.local/swagger/loan-insurance` |
| **Gitlab project** | loans/insurance-api |
| **Framework** | Spring Boot 3 |
| **Author** | Аналитик команды кредитов |
| **Developer** | Команда кредитов |

### Логика работы метода
1. Проверить сессию клиента.
2. Проверить, что заявка на кредит принадлежит клиенту и ещё не подписана.
3. Проверить сумму кредита (300 000 – 5 000 000 ₸) и срок `term` (6–60).
4. Проверить возраст клиента. Если на дату подключения клиенту меньше 18 полных лет или на дату окончания кредита будет больше 65 полных лет, вернуть 422.
5. Рассчитать премию по Ф-2 и ставку со страхованием.
6. Если `consentPd` не равно `true`, вернуть 400. Передать ИИН, ФИО, дату рождения и номер телефона клиента страховой компании-партнёру для предварительной проверки, сохранить подключение страхования в заявке и вернуть результат; если страховая компания-партнёр отказала по результатам предварительной проверки, вернуть 422. Полис выпускается после выдачи кредита.

### Особые правила
1. Повторный вызов с теми же суммой и сроком возвращает действующие условия страхования.
2. Если клиент изменил сумму или срок после подключения, приложение вызывает метод повторно, и условия страхования пересчитываются; если повторный вызов вернул 400 или 422, ранее подключённое страхование снимается с заявки.
3. После отказа от страхования ставка по кредиту повышается до 27 % годовых со дня отказа (Ф-4).

### Схема
```text
Приложение → LoanInsuranceController → сервис страхования → страховая компания-партнёр → сервис страхования → LoanInsuranceController → приложение.
```

### Параметры запроса

#### Path-параметры

| Parameter | Format | Size | Mandatory | Logic | Description | DB field |
| :--- | :--- | :--- | :--- | :--- | :--- | :--- |
| `applicationId` | string | 1–64 | Да | Заявка клиента | Идентификатор заявки на кредит | `application_id` |

#### Request body
Content-Type: `application/json`.

| Parameter | Format | Size | Mandatory | Logic | Description | DB field |
| :--- | :--- | :--- | :--- | :--- | :--- | :--- |
| `amount` | integer | 32 bit | Да | 300 000–5 000 000 | Сумма кредита в тенге | `loan_amount` |
| `term` | integer | 1–2 знака | Да | 6–60 | Срок кредита в месяцах | `loan_term` |
| `consentPd` | boolean | — | Да | true | Согласие клиента на передачу персональных данных страховой компании-партнёру | `pd_consent_at` |

### Ответ
Если результат 200 — успешный. Если результат 400, 401, 404, 409, 422, 500 или 502 — неуспешный.

| Parameter | Format | Logic | Description | DB field |
| :--- | :--- | :--- | :--- | :--- |
| `status` | string | CONNECTED | Результат подключения | `insurance_status` |
| `premium` | integer | ≥ 0 | Страховая премия, ₸ | `premium_kzt` |
| `rate` | number | — | Ставка по кредиту со страхованием, % годовых | — |

### Статусы

**200.** Ответ в случае успешного выполнения метода.  
**400.** Ответ в случае, если сумма или срок вне допустимого диапазона или нет согласия на передачу персональных данных.  
**401.** Ответ в случае, если запрос выполнен без необходимой авторизации.  
**404.** Ответ в случае, если заявка не найдена или принадлежит другому клиенту.  
**409.** Ответ в случае, если заявка уже подписана.  
**422.** Ответ в случае, если клиент не подходит по возрасту или страховая компания-партнёр отказала по результатам предварительной проверки.  
**500.** Ответ в случае, если произошла внутренняя ошибка сервера.  
**502.** Ответ в случае, если страховая компания не ответила.

#### 200. Successful
```json
{"status":"CONNECTED","premium":36000,"rate":24.0}
```

#### 400. Unsuccessful — Bad request
```json
{"message":"Сумма или срок вне допустимого диапазона"}
```

#### 401. Unsuccessful — Unauthorized
```json
{"message":"Требуется вход"}
```

#### 404. Unsuccessful — Not found
```json
{"message":"Заявка не найдена"}
```

#### 409. Unsuccessful — Conflict
```json
{"message":"Заявка уже подписана"}
```

#### 422. Unsuccessful — Unprocessable entity
```json
{"message":"Страхование недоступно по возрасту"}
```

#### 500. Unsuccessful — Internal server error
```json
{"message":"Ошибка сервиса"}
```

#### 502. Unsuccessful — Bad gateway
```json
{"message":"Страховая компания недоступна"}
```

### Методы расчёта и отказа

Методы 2–5 используют ту же авторизацию (Bearer, сессия клиента), Controller и Framework, что и метод 1; ответы 401 и 500 — как у метода 1. Суммы — в тенге, ставки — % годовых.

| Метод | REST type и URL | Параметры | Ответ 200 | Ошибки |
| :--- | :--- | :--- | :--- | :--- |
| 2. Расчёт стоимости | GET `/loans/insurance/quote` | query: `amount` (integer, 300 000–5 000 000, обязательный), `term` (integer, 6–60 месяцев, обязательный) | `{"premium":36000,"rateWithInsurance":24.0,"rateWithoutInsurance":27.0}` | 400 — сумма или срок вне диапазона |
| 3. Отказ от страхования | POST `/loans/{loanId}/insurance/refusal` | path: `loanId` (string, 1–64, обязательный) | `{"refund":36000,"refundUntil":"2026-03-19","newRate":27.0}` | 404 — кредит не найден или принадлежит другому клиенту; 409 — прошло больше 14 дней, отказ уже оформлен или страхование прекращено полным досрочным погашением |
| 4. Снятие страхования с заявки | DELETE `/loans/applications/{applicationId}/insurance` | path: `applicationId` (string, 1–64, обязательный); только до подписания заявки | `{"status":"REMOVED","rate":27.0}` | 404 — заявка не найдена или принадлежит другому клиенту; 409 — заявка уже подписана |
| 5. Сведения о страховании | GET `/loans/{loanId}/insurance` | path: `loanId` (string, 1–64, обязательный) | `{"status":"ACTIVE","policyNumber":"LI-2026-000123","startDate":"2026-03-01"}`; до выпуска полиса `policyNumber` = `null` | 404 — кредит не найден или принадлежит другому клиенту |
