# Повтор первого закрытого испытания на официальной сборке

Для выпуска Max `8e8e95f4bb8a65bdd10d7e4599dd4747ffe8c803` повторяем исходное испытание IE на тех же файлах. Предыдущие отчёты по этому корпусу и часть разборов были доступны до повтора. Испытание проверяет перенос результатов между сборками. Исходные закрытые файлы не меняются. [Передача сборки](https://github.com/diiaanns07-droid/winnersOFbankCCbyMNU/blob/08d3af55446ef37d8d61d077848e63c292a47207/contracts/HANDOFF.md) · [Метод и правила дублей](../README.md) · [Хеши повторного испытания](seal.json)

Основной набор включает 24 редакции четырёх семейств, 24 заложенные причины, восемь исходно чистых документов и шесть критичных дефектов. У уже опубликованной версии эталона 1.1 добавлены редакционные причины. Оба эталона, состав парной шестёрки, команды и кандидат фиксируются до повторного запуска. Счётчик №16 закреплён за `a79a47d887bf5265c946019c004ca8d3e4f2b988`. Единица совпадения, допустимые трактовки, проверка цитат и правило один к одному берутся из исходного протокола. При несовпадении механического счёта и вывода о смысле хранитель указывает оба результата.

Каждый из 31 физических входов обрабатывается официальным CLI в режиме правил, без сети и кэша. Основные метрики считаются по 24 основным MD, отдельно показываются все статусы, ложные тревоги, критичные пропуски и техническая пригодность. Дополнительные редакции и повторные форматы не увеличивают основной знаменатель. Для документной accuracy положительным решением считается наличие хотя бы одной confirmed-карточки. Доля считается по пригодным входам вместе с их количеством.

Повторяем шесть ранее определённых сравнений редакций и обе прежние развилки ответа владельца. Для решения по каждой из двух альтернатив отдельно проверяем отчёт применения и новый независимый запуск по получившемуся тексту. Проверка задаёт конкретный вопрос для регрессии — ссылается ли отчёт после применения решения на существующий вопрос и принимает ли его штатный verify. Все идентификаторы, тексты и первичные ответы остаются у хранителя.

Измеряем офлайн-режим. На этих закрытых входах живой результат учитывается только при доступном автоматическом отчёте с совпадающим источником, фактической моделью и реальным вызовом. Состояние отдельной проверки PV-1 опубликовано [здесь](../../results/policy-variation/README.md).
