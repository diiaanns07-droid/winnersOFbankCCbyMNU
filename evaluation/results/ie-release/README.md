## Качество находок

Четыре синтетических банковских сюжета, 24 редакции в основном наборе, 24 заложенных дефекта, восемь исходно чистых документов. Редакции одной семьи зависимы. Это повтор ранее оценённого корпуса. Обе версии эталона зафиксированы до повторного запуска. Прежние агрегаты и часть разборов были доступны команде. Человеческих оценок было ноль. Полные поисковые фразы эталона не встретились в 655 проверенных файлах исходников, тестов, примеров и открытых данных официальной сборки.

Числа в таблице относятся к confirmed. На исходном эталоне при учёте всех статусов получено 0 TP, 21 FP и 14 FN на пригодных отчётах, дублей ноль. Из шести критичных причин две пропущены на пригодных документах, четыре остались без пригодного отчёта. На пяти пригодных чистых ТЗ из восьми пришлось девять подтверждённых ложных тревог. На каждом из этих пяти было хотя бы одно замечание. В эталоне 1.1 восемь TP относятся к ранее разобранным редакционным причинам. Ни одна из 24 изначально заложенных причин не получила зачёта.

Документная accuracy по критерию «есть хотя бы одно confirmed-замечание» равна 9/14 = 64,3% для пригодных основных документов при эталоне 1.0. На всех 14 агент поднял тревогу, из них девять действительно содержали исходный дефект. Для полного набора из 24 оценка этой доли отсутствует. Соседнее испытание PV-1 относится к другим документам. ## Открытый пример для Max и №07

В строке 5 входа `occurrence.md` дежурный начинает смену в 13:12. В строке 9 указано единственное требование R-001 к сервису с тем же временем. Правило RULE-TZ создаёт карточку уровня требования и указывает оба вхождения. У строки 5 нет связи с R-001. Verify возвращает код 4. В контроле изменена только минута в строке 5. Правило срабатывает и там, код verify — 0. Оба входа написаны после испытания и не включены в метрики. [Вход с повтором](example/occurrence.md) · [Однострочный контроль](example/control.md)

Сценарий запускается из корня ветки оценки с установленными зависимостями релиза и чистым продуктовым checkout.

```powershell
python evaluation/results/ie-release/example/probe.py --product ../product-8e8e95f --out ../ie-public-probe
```

На `8e8e95f` сценарий печатает `verify=4` и `verify=0` и завершает проверку кодом 1. На прежнем SHA оба кода verify равны 0. Критерий для проверки следующей сборки — обе версии ТЗ дают проверяемые отчёты, а замечание уровня отдельного требования ссылается на его собственное вхождение. Если замечание описывает несколько разделов, его уровень и опоры должны отражать этот охват. [Построение карточки](https://github.com/diiaanns07-droid/winnersOFbankCCbyMNU/blob/8e8e95f4bb8a65bdd10d7e4599dd4747ffe8c803/src/bcc_review/runtime/fallback/rules.py#L436) · [Проверка вхождения](https://github.com/diiaanns07-droid/winnersOFbankCCbyMNU/blob/8e8e95f4bb8a65bdd10d7e4599dd4747ffe8c803/src/bcc_review/verification.py#L438)

## Вопросы и применение решения владельца

На стратифицированной панели из шести документов имеются два пригодных отчёта, в них ноль вопросов. Остальные четыре отчёта содержат 16 вопросов и были отклонены. Доля полезных вопросов на пригодных карточках не определена. При сравнении шести пар редакций оба исходных отчёта и результат сравнения прошли критерии в 2/6 случаев.

Две альтернативы владельца проверены независимо на закрытом и на открытом примере. Все четыре получившихся текста побайтово совпадают с соответствующими редакциями, полученными на прежней версии. На открытом примере оба отчёта применения решения ссылаются на уже отсутствующие Q-01 и F-001, поэтому verify отклоняет 2/2. Новый запуск по каждому из двух получившихся текстов прошёл verify, 2/2. На закрытом примере применение и новый запуск не прошли verify в обеих альтернативах. Одна из двух записей решения содержит также исчезнувшую ссылку. [Открытый вход для решения владельца](../../../defense/demo/source.md)

**Фраза для защиты.** «Мы сверили 121 цитату на 24 банковских ТЗ. Все встретились в исходных строках, но проверка привязки к конкретному требованию выявила ошибки в 10 отчётах».

## Передача исполнителю

У прежнего операторского архива IE в поле `stratum` встречались метки `clean`, `conflict` и `omission`. Новый `IE-six-inputs-v2.zip` содержит те же шесть исходных MD, случайные идентификаторы и манифест без ролей и типов. Порядок файлов определяется новыми именами. Хранитель сопоставляет возврат с эталоном по SHA-256 исходных байтов. На прежнем и официальном SHA этот путь проверен реальными офлайн-отчётами всех шести входов. Состав и счёт пригодных результатов согласованы с каноническим прогоном. Из-за ранее опубликованных хешей и разборов шестёрка пригодна для повторного сравнения. Для отдельной закрытой проверки подготовлена панель PV-1. [Квитанция операторской упаковки](../../protocol/ie-release/operator-8e8e95f.json) · [Отдельная панель PV-1](../policy-variation/RUN.md)

Владелец согласованного бюджета получает только операторский ZIP. Следующие команды запускают официальную сборку из PowerShell в корне ветки оценки.

```powershell
git fetch origin bcc/integration
git worktree add --detach ../product-8e8e95f 8e8e95f4bb8a65bdd10d7e4599dd4747ffe8c803
py -3.12 -m venv ../ie-venv
$py = (Resolve-Path ../ie-venv/Scripts/python.exe).Path
& $py -m pip install -e "../product-8e8e95f[all]"
Expand-Archive -LiteralPath ../IE-six-inputs-v2.zip -DestinationPath ../ie-inputs
& $py evaluation/protocol/run.py --product ../product-8e8e95f --input-pack ../ie-inputs --input-seal evaluation/protocol/ie-release/operator-8e8e95f.json --out ../gemini-return --mode rules_plus_llm --suite panel
```

Исполнитель возвращает исходный каталог `gemini-return` с JSON и MD отчётов, паспортами запусков и журналом фактических ответов SDK. Хранитель использует свой корпус и копию того же операторского манифеста. Оба режима сравниваются по совпавшим пригодным исходникам. До реального прогона Gemini показатели качества остаются пустыми.

```powershell
& $py evaluation/protocol/score_return.py --product ../product-8e8e95f --vault ../ie-vault --returned ../gemini-return --operator-manifest ../ie-inputs/panel.manifest.json --operator-seal evaluation/protocol/ie-release/operator-8e8e95f.json --out ../gemini-score --mode rules_plus_llm
```

Для полного офлайн-повтора хранитель использует 31 файл в `../ie-vault`.

```powershell
& $py evaluation/protocol/run.py --product ../product-8e8e95f --vault ../ie-vault --input-seal evaluation/protocol/ie-release/seal.json --out ../ie-offline-repeat --mode rules_only --suite all
```

В отдельном архиве хранителя находятся исходные отчёты, обе версии эталона, цитаты и решения по каждой карточке, логи двух версий verify, все переходы и возврат нейтральной панели. [Контрольные суммы передачи](delivery.json)
