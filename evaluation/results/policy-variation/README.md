# Независимая проверка банковских ТЗ · PV-1

На официальной сборке Max `8e8e95f4bb8a65bdd10d7e4599dd4747ffe8c803` правила нашли две из восьми заранее заложенных причин. В основной форме анализ выдал пригодные отчёты для 2/16 документов. Перефразирование подняло число пригодных отчётов до 16/16. На этих входах агент снова нашёл те же две причины, пропустил обе критичные и выдал тревоги во всех восьми исходно чистых документах. Полный семантический цикл в офлайн-режиме завершился в 0/16 случаев в каждой форме. [Коммит сборки](https://github.com/diiaanns07-droid/winnersOFbankCCbyMNU/blob/08d3af55446ef37d8d61d077848e63c292a47207/release/README.md) · [Машиночитаемые итоги обеих сборок](summary.json)

## Что проверялось

Четыре синтетические банковские темы — аккредитив, зарплатная ведомость, квитанция инкассации и подтверждение смены адреса. В каждой две допустимые политики. Для каждой политики есть согласованная версия и версия с одним дефектом. Получилось 16 содержательных документов, 8 исходных дефектов и 8 чистых контролей. Для каждого документа выполнены три запуска Markdown. В одном менялся фактический порядок двух разделов, в другом менялась формулировка. Статистика относится к четырём семьям. Корпус подготовил и оценил независимый ИИ. Человеческих оценок было 0. [Исходный протокол и обязательство](../../protocol/policy-variation/README.md) · [Фиксация официальной сборки](../../protocol/policy-variation/8e8e95f/README.md)

## Качество на исходном эталоне PV-1

В таблице TP/FP/FN и precision/recall относятся к отчётам, которые прошли условия протокола. D — повтор уже зачтённой причины. Последняя колонка учитывает весь заранее назначенный набор, включая сбои.

| SHA и режим | Входы | Пригодные ТЗ / план | Дефекты по плану | TP / FP / FN | D | Precision | Recall на пригодных | Найдено из плана |
|---|---|---:|---:|---:|---:|---:|---:|---:|
| 8e8e95f, правила | Основная форма | 2/16 | 8 | 2 / 0 / 0 | 0 | 2/2 | 2/2 | 2/8 |
| 8e8e95f, правила | Переставлены разделы | 2/16 | 8 | 2 / 0 / 0 | 0 | 2/2 | 2/2 | 2/8 |
| 8e8e95f, правила | Перефразирование | 16/16 | 8 | 2 / 18 / 6 | 2 | 2/20 = 10% | 2/8 = 25% | 2/8 |
| 8e8e95f, правила | Будущая парная панель | 1/8 | 4 | 1 / 0 / 0 | 0 | 1/1 | 1/1 | 1/4 |
| 8e8e95f, правила + Gemini | Те же 8 входов | 0 запусков | 4 | не измерено | — | не измерено | не измерено | не измерено |

Прежний кандидат `f91d3b6f485e883d316c94fc5e032f1a8d6c2553` дал те же количества для каждой из четырёх офлайн-строк. Во всех пригодных отчётах замечания имели статус confirmed. При включении в знаменатель двух дублей строгая precision на перефразированных документах равна 2/22 = 9,1%. На уровне документа ответ «есть хотя бы одна тревога» при пороге в одно confirmed даёт accuracy 8/16 = 50% по исходной разметке на этой форме. Из них восемь истинно положительных документов, восемь ложноположительных, ноль истинно отрицательных и ноль ложноотрицательных. Такой расчёт не различает мотивы тревоги. У основной формы accuracy по всем 16 документам неизвестна из-за 14 сбоев.

**Критичные причины и чистый контроль.** В основной форме оба критичных входа и все восемь чистых вернули статус failed. Число пригодных чистых входов равно нулю, оценка частоты ложной тревоги отсутствует. В двух из восьми чистых провалившихся отчётов сохранилось по одной диагностической карточке. При перефразировании оценены все восемь исходных дефектов. Пропущены шесть, в том числе 2/2 критичных. Десять подтверждённых тревог пришлись на 8/8 исходно чистых документов.

**Механическое и независимое сопоставление.** Счётчик №16 на прежнем и официальном SHA дал в основной форме 0 TP / 2 FP / 2 FN на двух пригодных входах. Независимая проверка засчитала обе находки по заранее опубликованному правилу короткой цитаты. В перефразированной форме №16 дал 2 TP / 20 FP / 6 FN / 0 D. В двух случаях одно и то же замечание о сроке сформулировано вторично. Независимая проверка пометила вторую карточку в каждом документе как D. Каждый исправляемый срок даёт ровно один TP. ## Что уточнено после первого прогона

В одной семье перефразирование добавило требование к количеству запросов. Оно отдельно проверяется от содержания ответа. Дополнительная разметка PV-1.1 учитывает четыре случая объединения этих требований в одном пункте. Поправка зафиксирована после результатов прежней сборки и до измерения нового SHA. Перефразирование на обеих сборках при PV-1.1 даёт TP/FP/FN = 6/14/6 и D = 2, precision 6/20 = 30%, recall 6/12 = 50%. На 6/6 оставшихся чистых документов пришлись 8 тревог. Исходные восемь бизнес-причин и шесть их пропусков сохранены. Без этой семьи число пригодных отчётов меняется с 2/12 до 12/12. Выводы ограничены этими синтетическими документами и режимом правил. [Хеш отдельной поправки](../../protocol/policy-variation/8e8e95f/comparison.json)

**Фраза для защиты.** «На закрытой проверке из четырёх банковских тем правила сборки 8e8e95f нашли 2 из 8 заранее заложенных дефектов. На форме, где обработаны все 16 документов, пропущены обе критичные ошибки».

## Передача результатов

Для хранителя подготовлен отдельный архив с эталоном, входами, исходными отчётами, решениями по каждой карточке и воспроизводимым примером `review/replay.py`. В `review/line-by-line.md` разобраны короткая цитата, ложная тревога и критичный пропуск. Публичная ветка содержит агрегаты. Для исполнителя подготовлен отдельный архив из восьми анонимизированных входов и манифеста. В условиях этого испытания физический доступ к модели и бюджет для панели не подтверждены.
