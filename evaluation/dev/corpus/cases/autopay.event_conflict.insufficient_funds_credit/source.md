# Автопополнение мобильной связи

Открытый учебный документ корпуса bcc-eval. Семейство autopay.

## Часть A. Бизнес-требования

### Общие сведения

| Поле | Значение |
| :--- | :--- |
| **Наименование задачи** | Автопополнение мобильной связи с карты |
| **Продукт** | Мобильный банк |
| **Задача в Jira** | EVAL-202 |
| **Версия документа** | 1.0 от 01.11.2026 |

### Цели
Баланс телефона клиента не опускается ниже выбранного порога без ручных действий.

### Термины
* **Сутки** — интервал с 00:00:00 до 23:59:59 по времени UTC+5 (Asia/Almaty).
* **Уведомление о балансе** — сообщение оператора связи с номером телефона, балансом в тенге и идентификатором события.

### Функциональные требования
* **АП-1.** Клиент подключает автопополнение для одного номера телефона в формате +7XXXXXXXXXX и одной своей карты KZT.
* **АП-2.** Порог баланса задаётся целым числом от 100 до 5 000 ₸ включительно.
* **АП-3.** Сумма пополнения задаётся целым числом от 500 до 20 000 ₸ включительно.
* **АП-4.** Если уведомление о балансе сообщает баланс ниже порога, банк списывает сумму пополнения с карты и пополняет номер.
* **АП-5.** За одни сутки выполняется не больше трёх автопополнений одного номера.
* **АП-6.** Если на карте недостаточно средств, пополнение не выполняется, а клиент получает push «Недостаточно средств для автопополнения».
* **АП-7.** После отключения автопополнения банк не выполняет пополнения по этой настройке.
* **АП-8.** Если на карте недостаточно средств, банк пополняет номер в кредит и списывает сумму при следующем поступлении на карту.

### Нефункциональные требования
* **НФ-1.** Пополнение выполняется не позднее 5 минут после получения уведомления о балансе для 99 % уведомлений.

### Требования к данным
Хранить номер телефона, идентификатор карты, порог в тенге, сумму пополнения в тенге, время каждого пополнения по UTC+5 и идентификатор события оператора.

### Требования к интеграции
Приложение создаёт настройку методом createAutopay, читает её методом getAutopay и удаляет методом deleteAutopay. Методы описаны в части B. Повторное уведомление с тем же идентификатором события не создаёт второе пополнение.

### Критерии приёмки

| Исходные условия | Действие | Ожидаемый результат |
| :--- | :--- | :--- |
| Порог 1 000 ₸, сумма 2 000 ₸ | Оператор сообщает баланс 900 ₸ | Одно пополнение на 2 000 ₸ |
| Порог 1 000 ₸, сумма 2 000 ₸ | Оператор сообщает баланс 1 000 ₸ | Пополнение не выполняется |
| Три пополнения за текущие сутки | Оператор сообщает баланс ниже порога | Пополнение не выполняется |
| Порог 1 000 ₸, на карте 1 500 ₸, сумма 2 000 ₸ | Оператор сообщает баланс 800 ₸ | Пополнение не выполняется, push «Недостаточно средств для автопополнения» |

## Часть B. REST API

### Метод createAutopay

| Поле | Значение |
| :--- | :--- |
| **REST type** | POST |
| **Request URL** | `/autopay` |
| **Authorization** | Bearer, сессия клиента — владельца карты |
| **Content-Type** | `application/json` |

#### Тело запроса

| Parameter | Format | Mandatory | Logic | Description |
| :--- | :--- | :--- | :--- | :--- |
| `cardId` | string | Да | Карта клиента | Идентификатор карты |
| `phone` | string | Да | +7XXXXXXXXXX | Номер телефона |
| `threshold` | integer | Да | от 100 до 5 000 включительно | Порог баланса в тенге |
| `amount` | integer | Да | от 500 до 20 000 включительно | Сумма пополнения в тенге |

#### Логика метода
1. Проверить сессию и принадлежность карты клиенту.
2. Проверить формат номера и диапазоны порога и суммы.
3. Если настройка для карты уже существует, вернуть 409.
4. Сохранить настройку и вернуть 200.

### Метод getAutopay

| Поле | Значение |
| :--- | :--- |
| **REST type** | GET |
| **Request URL** | `/autopay/{cardId}` |
| **Authorization** | Bearer, сессия клиента — владельца карты |

Ответ 200: `{"phone":"+77001234567","threshold":1000,"amount":2000}`.

### Метод deleteAutopay

| Поле | Значение |
| :--- | :--- |
| **REST type** | DELETE |
| **Request URL** | `/autopay/{cardId}` |
| **Authorization** | Bearer, сессия клиента — владельца карты |

### Статусы

| Код | Когда возвращается | Тело ответа |
| :--- | :--- | :--- |
| 200 | Запрос выполнен | Описано в разделе метода; для deleteAutopay тело пустое |
| 400 | Номер не в формате +7XXXXXXXXXX или порог либо сумма вне диапазона | `{"message":"Проверьте параметры"}` |
| 401 | Нет действующей сессии | `{"message":"Требуется вход"}` |
| 404 | Карта или настройка не найдена либо карта не принадлежит клиенту | `{"message":"Не найдено"}` |
| 409 | Настройка для карты уже существует | `{"message":"Автопополнение уже подключено"}` |
| 500 | Внутренняя ошибка сервиса | `{"message":"Ошибка сервиса"}` |
