# Временная блокировка карты

Открытый учебный документ корпуса bcc-eval. Семейство cardblock.

## Часть A. Бизнес-требования

### Общие сведения

| Поле | Значение |
| :--- | :--- |
| **Наименование задачи** | Временная блокировка карты клиентом |
| **Продукт** | Мобильный банк |
| **Задача в Jira** | EVAL-303 |
| **Версия документа** | 1.0 от 01.11.2026 |

### Цели
Клиент сам временно блокирует карту в приложении, если не уверен в её сохранности.

### Термины
* **Авторизация** — запрос карточного процессинга на одобрение операции по карте.
* **Статусы карты** — ACTIVE (рабочий) и BLOCKED_BY_CLIENT (заблокирована клиентом).

### Функциональные требования
* **БК-1.** Клиент блокирует свою карту в статусе ACTIVE и разблокирует свою карту в статусе BLOCKED_BY_CLIENT.
* **БК-2.** Клиент указывает срок блокировки от 1 до 30 суток включительно или выбирает бессрочную блокировку. По окончании срока статус карты снова ACTIVE.
* **БК-3.** Пока карта в статусе BLOCKED_BY_CLIENT, процессинг отклоняет новые авторизации с причиной «Карта заблокирована клиентом».
* **БК-4.** Блокировка не отменяет авторизации, одобренные до блокировки.
* **БК-5.** Блокировка вступает в силу не позднее 10 секунд после ответа 200 метода blockCard.
* **БК-6.** Разблокировка доступна без ограничения числа раз.
* **БК-7.** После блокировки клиент получает push «Карта •• NNNN заблокирована», где NNNN — последние четыре цифры номера карты.

### Требования к данным
Хранить идентификатор карты, последние четыре цифры номера карты, статус, срок блокировки в сутках, время блокировки по UTC+5 и инициатора изменения.

### Требования к интеграции
Приложение блокирует карту методом blockCard, разблокирует методом unblockCard и читает статус методом getCardStatus. Методы описаны в части B.

### Критерии приёмки

| Исходные условия | Действие | Ожидаемый результат |
| :--- | :--- | :--- |
| Карта в статусе ACTIVE | Заблокировать карту на 30 суток | Ответ 200; авторизация через 10 секунд отклонена |
| Карта в статусе BLOCKED_BY_CLIENT | Запросить авторизацию на 1 000 ₸ | Авторизация отклонена с причиной «Карта заблокирована клиентом» |
| Авторизация на 5 000 ₸ одобрена до блокировки | Заблокировать карту | Авторизация остаётся одобренной |

## Часть B. REST API

### Метод blockCard

| Поле | Значение |
| :--- | :--- |
| **REST type** | POST |
| **Request URL** | `/cards/{cardId}/block` |
| **Authorization** | Bearer, сессия клиента — владельца карты |
| **Content-Type** | `application/json` |

#### Тело запроса

| Parameter | Format | Mandatory | Logic | Description |
| :--- | :--- | :--- | :--- | :--- |
| `days` | integer | Нет | больше 1 и меньше 30; без поля — бессрочно | Срок блокировки в сутках |

### Метод unblockCard

| Поле | Значение |
| :--- | :--- |
| **REST type** | POST |
| **Request URL** | `/cards/{cardId}/unblock` |
| **Authorization** | Bearer, сессия клиента — владельца карты |

### Метод getCardStatus

| Поле | Значение |
| :--- | :--- |
| **REST type** | GET |
| **Request URL** | `/cards/{cardId}/status` |
| **Authorization** | Bearer, сессия клиента — владельца карты |

Ответ 200: `{"status":"BLOCKED_BY_CLIENT","blockedAt":"2026-11-01T10:15:00+05:00","days":30}`. Поле `blockedAt` — время блокировки по UTC+5 в формате ISO 8601.

### Статусы

| Код | Когда возвращается | Тело ответа |
| :--- | :--- | :--- |
| 200 | Запрос выполнен | Описано в разделе метода; для blockCard и unblockCard тело пустое |
| 400 | Поле days меньше 1 или не меньше 30 | `{"message":"Проверьте срок"}` |
| 401 | Нет действующей сессии | `{"message":"Требуется вход"}` |
| 404 | Карта не найдена или не принадлежит клиенту | `{"message":"Карта не найдена"}` |
| 409 | Статус карты не позволяет операцию: блокировка не из ACTIVE или разблокировка не из BLOCKED_BY_CLIENT | `{"message":"Операция недоступна"}` |
| 500 | Внутренняя ошибка сервиса | `{"message":"Ошибка сервиса"}` |
