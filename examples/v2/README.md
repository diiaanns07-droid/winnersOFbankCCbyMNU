# Демо: от замечаний к готовому ТЗ

Агент не только находит дефекты, но и ведёт к исправленному документу:

1. **Вопросы владельцу** (всегда, в каждом отчёте) — приложение А: до 10 вопросов, у каждого цитаты обеих
   сторон конфликта, 2–4 проверяемых варианта ответа (первый — тот, что лучше согласуется с целью документа),
   кому адресован, блокирует ли он разработку и что сломается без ответа.
2. **Режим ответов** `--answers ответы.md` — агент пересматривает каждый затронутый дефект («снят»,
   «уточнён», «открыт» с обоснованием), ищет новые конфликты, которые порождают сами ответы, и показывает
   вердикт «до / после» на первом экране отчёта.
3. **Исправленная редакция** `--revise` — «было → стало» по каждому критичному и существенному дефекту и
   исправленный документ `<отчёт>.revised.md` рядом с отчётом: заменённые фрагменты помечены
   `[изменено: D-…]`, новые требования и критерии приёмки — `[добавлено: D-…]`. Без ответов значения, которые
   выбирает бизнес, остаются маркерами `<уточнить: …>`; с ответами подставляются выбранные правила.

## Одна команда «до / после»

```bash
python -m bcc_review release/input/requirements.md out/demo.md --answers examples/v2/answers.md --revise
```

Результат: `out/demo.md` (+ `.json`, `.html`) с блоком «До и после ответов владельца» и приложением
«Было → стало», а также `out/demo.revised.md` — исправленное ТЗ.

Проверка исправленного ТЗ тем же агентом:

```bash
python -m bcc_review out/demo.revised.md out/demo.revised.review.md
```

## Как отвечать на вопросы

Файл ответов — обычный Markdown, по строке на вопрос:

```text
Q-01: B                       — вариант B из отчёта
Q-02: А — с оговоркой …       — вариант A и комментарий (кириллические А, В, С тоже понимаются)
Q-03 [тема вопроса]: свой ответ — свой текст; тема в скобках находит вопрос, даже если номера сменились
## Решения
- общее решение владельца     — агент сам определит, какие дефекты оно закрывает
```

Ответы вида «обсудим позже», «как обычно», «?» не считаются: связанные дефекты остаются открытыми. Пример
для официального документа — [`answers.md`](answers.md).

## Двухшаговый сценарий (как в банке)

1. `python -m bcc_review ТЗ.md out/ТЗ.md` — отчёт с вопросами (приложение А).
2. Владелец пишет `ответы.md` (`Q-01: A`, …).
3. `python -m bcc_review ТЗ.md out/ТЗ.md --answers ответы.md --revise` — этапы ревью берутся из кэша
   (вопросы и их номера те же), выполняются только пересмотр и редакция.
