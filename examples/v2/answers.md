# Ответы владельца на вопросы ревью: «Уведомление о расходах по карте»

> Пример для режима ответов агента. Формат строки: `Q-01: B` (буква варианта из отчёта) или
> `Q-01 [тема]: свой ответ`. Тема в квадратных скобках нужна, чтобы ответ нашёл свой вопрос, даже если в
> новом прогоне вопросы пронумерованы иначе. Строки раздела «Решения» — общие решения владельца: агент сам
> определяет, какие дефекты они закрывают. Строки, начинающиеся с `>`, и пустые строки игнорируются.
>
> Один прогон «до / после» и исправленная редакция:

Q-01 [месяц расходов и дата операции на границе месяцев]: Месяц расходов определяется по дате и времени совершения покупки (одобрения авторизации) в часовом поясе UTC+5 (Asia/Almaty). Покупка, совершённая 31 января в 23:58 по UTC+5 и проведённая 1 февраля в 00:03 по UTC+5, относится к январю: в критерии приёмки №2 время покупки указывается с часовым поясом, ожидаемый результат — «январский счётчик вырос на 4 000 ₸, февральский не изменился».
Q-02 [лимит уведомлений в месяц при изменении порога]: Не более одного push на карту за календарный месяц, в том числе после изменения порога. После изменения порога накопленная сумма сохраняется; если push в этом месяце уже был, новый не отправляется до следующего месяца.
Q-03 [событие процессинга и момент учёта покупки]: Расходы увеличиваются по событию одобренной авторизации покупки. Отмена авторизации и возврат уменьшают расходы месяца исходной покупки; клиринг сумму не меняет, разница между суммой клиринга и авторизации учитывается в месяце исходной покупки. Событие содержит идентификатор операции, идентификатор карты, тип (покупка, отмена, возврат), сумму в тиынах, дату и время совершения, ссылку на исходную операцию для отмены и возврата.
Q-04 [операции API сохранения и чтения настроек]: Сохранение — PUT /alerts/limit с JSON-телом {"cardId","amount","enabled"}; чтение — GET /alerts/limit?cardId=… возвращает порог, признак включения и сумму расходов за текущий месяц. Метод GET данные не изменяет.
Q-05 [ответ API при ошибке проверки суммы]: Неверная сумма или неверный enabled возвращают HTTP 400 с телом {"result":"ERROR","message":"Проверьте сумму"}. HTTP 200 означает только успешное сохранение, result = OK. Код 201 не используется.
Q-06 [включение уведомления при уже достигнутой сумме]: Если при включении уведомления или изменении порога расходы месяца уже не ниже порога, push при сохранении не отправляется. Следующий push возможен только при новом переходе расходов от суммы ниже порога к сумме не ниже порога (например, после возврата), с учётом лимита одного push в месяц.
Q-07 [возвраты и повторный push]: Полный или частичный возврат уменьшает расходы месяца исходной покупки, но не ниже 0 ₸. Признак отправленного push возвратом не сбрасывается. Возврат по покупке, которой нет в хранилище, не меняет расходы.
Q-08 [единицы сумм тиыны и тенге]: Расходы хранятся и суммируются в тиынах. Порог хранится в целых тенге и при сравнении умножается на 100; сравнение целочисленное, без округления.
Q-09 [какие операции учитываются в расходах]: Учитываются покупки товаров и услуг у торговцев картой, в том числе онлайн. Переводы, снятие наличных, квази-кэш, комиссии банка и платежи в мобильном банке исключаются. Покупка в другой валюте учитывается по сумме списания в KZT.
Q-10 [содержимое push и данные карты]: В push передаются последние четыре цифры карты и значение порога, сумма расходов не передаётся. Текст: «Расходы по карте *1234 в этом месяце достигли 50 000 ₸». Последние четыре цифры сервис расходов получает из сервиса настроек вместе с порогом.

## Решения

- Признак отправки push ставится после подтверждения приёма сервисом уведомлений. При ошибке выполняется до 3 повторов с интервалом 15 секунд, все в пределах 60 секунд от получения события; после этого событие помечается недоставленным.
- Нефункциональное требование: 95 % событий передаются в сервис уведомлений не позднее 60 секунд после получения события процессинга, 99 % — не позднее 120 секунд, при нагрузке до 200 событий в секунду.
- Ключ дедупликации события — идентификатор операции процессинга вместе с типом операции. Повтор события с тем же ключом не меняет расходы и не отправляет второй push; ключи хранятся 35 дней. События одной карты обрабатываются последовательно.
- Для чужой и для отсутствующей карты метод возвращает 404 с телом {"result":"ERROR","message":"Карта не найдена"}; код 403 не используется. Все ответы с ошибкой содержат поля result = ERROR и message.
- Настраивать уведомление может держатель карты — клиент, на имя которого выпущена карта, в том числе дополнительная. Проверка «принадлежность карты» означает: карта выпущена на клиента текущей сессии.
- Активная карта — карта в статусе «действует», не заблокирована и не закрыта. Для неактивной карты и карты не в KZT метод возвращает 400 с message «Карта недоступна для уведомлений».
- При enabled = 0 параметр amount необязателен и не проверяется, сохранённый порог не меняется. В ответе amount и enabled — integer, как в запросе.
