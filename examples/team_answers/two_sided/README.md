# Два вопроса к разным сторонам одного противоречия

Ответ владельца на один вопрос, второй остаётся открытым. Редакция создаётся через
штатный CLI. Ответы в `answers.md` — **демонстрационные ответы команды**, модель
имитирует mock-провайдер движка. Сеть и ключ не нужны.

## Вход

`tests/p08/fixtures/commission_tz.md`, SHA-256 `cbbc38cae3615f5482d87d0d77974c2641856623540e3baa2988ed888cac8e91`:

| Строка | Раздел | Фраза |
| :--- | :--- | :--- |
| 5 | Функциональные требования | КП-1. «Перевод между своими счетами выполняется без комиссии.» |
| 9 | Тарифы | Т-1. «За перевод между своими счетами **взимается комиссия 0,5% от суммы перевода**.» |
| 15 | Критерии приёмки | «Перевод 10 000 ₸ между своими счетами \| Исполнить перевод \| Списано 10 000 ₸, комиссия 0 ₸» |

Движок объединяет обе стороны в одну находку F-001 (`incorrect`, `set_consistent`).
№08 задаёт по вопросу на каждую сторону: модель на этапе `clarify` вернула вопросы с
`target`. Без модели вопросы по сторонам строятся по правилам.

| Вопрос | О какой фразе | A | B |
| :--- | :--- | :--- | :--- |
| Q-01 | КП-1, строка 5 | текст не меняется; критерий (строка 15) совпадает | «выполняется без комиссии» → «выполняется с комиссией по тарифу Т-1»; критерий расходится, его нужно переписать |
| Q-02 | Т-1, строка 9 | текст не меняется; критерий расходится | «взимается комиссия 0,5% от суммы перевода» → «комиссия не взимается»; критерий совпадает |

Полные карточки лежат в `questions.md`: цель правки, роли цитат («цель правки» /
«другая сторона противоречия»), «Что изменится в тексте» и «Влияние на приёмку» для
каждого варианта.

## Ответ

`answers.md`: **Q-02 → B**, **Q-01 → «нужно уточнить»**. Пустой ответ ведёт себя
так же — вопрос открыт, решения в отчёте нет.

## Команды (из корня репозитория)

```bash
export BCC_FORCE_FALLBACK=review_individual,review_set
```

```bash
python -m bcc_review tests/p08/fixtures/commission_tz.md out/p08-comm-r1.md --provider mock --mock-script tests/p08/fixtures/mock_commission.json --no-cache --run-id p08-comm-r1
```

```bash
python -m bcc_review.decisions questions tests/p08/fixtures/commission_tz.md out/p08-comm-r1.json -o out/questions.md
```

```bash
python -m bcc_review tests/p08/fixtures/commission_tz.md out/p08-comm-r2.md --provider mock --mock-script tests/p08/fixtures/mock_commission_after.json --no-cache --run-id p08-comm-r2 --answers examples/team_answers/two_sided/answers.md --compare out/p08-comm-r1.json
```

```bash
diff tests/p08/fixtures/commission_tz.md out/commission_tz.rev-p08-comm-r2.md
```

```bash
python -m bcc_review.decisions status out/p08-comm-r1.json out/p08-comm-r2.json
```

## Результат

Редакция `out/commission_tz.rev-p08-comm-r2.md`, SHA-256
`cc57fc9e0d0b8dd25ee88b5af879e5728424ada9b737c8340158aed4d7b4fd8b`, совпадает с файлом
в этой папке байт-в-байт. Исходник не меняется. Изменена одна строка
(`agreed_edit.diff`):

```diff
-* **Т-1.** За перевод между своими счетами взимается комиссия 0,5% от суммы перевода.
+* **Т-1.** За перевод между своими счетами комиссия не взимается.
```

Строка 5 (КП-1) и строка 15 (критерий) не тронуты. В `p08-comm-r2.json`
`document.id` = `run.source_sha256` = SHA редакции, а `run.revision_of` = SHA
исходника: второй прогон прочитал записанный файл.

Статус вопросов (`status.md`):

| Вопрос | Ответ | Решение | Текст |
| :--- | :--- | :--- | :--- |
| Q-01 (КП-1) | нужно уточнить | `needs_clarification` | не менялся, вопрос открыт |
| Q-02 (Т-1) | B | `accepted` | внесено в редакцию, ожидает проверки |

В манифесте `commission_tz.rev-p08-comm-r2.revision.json`: `status:
applied_not_verified`, у Q-02 `patch_state: applied`, у Q-01 `open`.

Классификация — работа №09 (`diff` в `p08-comm-r2.json`): F-001 → `resolved`
(«внесено решение Q-02: правка заменила опорный фрагмент…»). Второй прогон
использует сценарий модели «после правки» (`mock_commission_after.json`), как в
сквозном тесте Max.

## Повторный импорт тех же ответов

Проверяет `tests/p08/test_two_sided.py::test_reimport_of_same_answers_does_not_duplicate_replacement`:

* та же команда ещё раз → вторая редакция совпадает байт-в-байт; «комиссия не
  взимается» встречается один раз;
* редакция на входе + тот же `answers.md` → «ответы относятся к другой редакции …:
  правки не применены», новых файлов нет;
* редакция на входе + ответы, перепривязанные к её SHA → «[already_applied] Q-02:
  правка уже есть в тексте — повторно не применяется», новых файлов нет.

Для правки-дописки, где новый текст содержит старый, повтор тоже не дописывает
фразу второй раз (`test_appending_edit_is_not_applied_twice`).
