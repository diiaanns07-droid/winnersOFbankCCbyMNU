Что сделать первым

  1. Типы полей расходятся между таблицами «Query-параметры» и «Ответ»: amount, enabled (integer ↔ string) — Задать один тип для amount, enabled во всех таблицах (<уточнить: тип>) и формат значения (диапазон, единицы, представление в JSON). Существенное: F-004
  2. Пример ответа 200 содержит ошибку «"result":"ERROR"», хотя для неверных данных описан код 400 — Убрать пример с ошибкой из ответа 200: для неверных данных возвращать 400 с телом <уточнить: формат ошибки>; согласовать с логикой метода, где упоминается результат с ошибкой. Существенное: F-007
  3. Под заголовком «403. Unsuccessful — Forbidden» указан ответ 404, которого нет в списке статусов — Выбрать один код для ситуации (<уточнить: 403 или 404>) и привести к нему заголовок, текст и пример; если нужен 404 — добавить его в список статусов с описанием. Существенное: F-008
  4. Метод GET для изменяющей операции «/alerts/saveLimit» — Заменить GET на POST (или PUT/PATCH для идемпотентной замены), параметры передавать в теле запроса; для чтения выделить отдельный GET-метод. <уточнить: итоговый метод и URL для /alerts/saveLimit>. Существенное: F-003
  5. Заголовок «200. Successful — Created»: фраза «Created» относится к коду 201, а не к 200 — Привести заголовок к фразе RFC 9110 «200 OK» — или, если ответ действительно 201 Created, исправить код и список статусов. Существенное: F-006
  6. Суммы в единицах «тиын» и «тенге» без правила пересчёта — Зафиксировать единую единицу хранения и сравнения (<уточнить: тиын или тенге>), правило пересчёта (1 тенге = 100 тиын) и округления (<уточнить: правило>) для всех сумм. Существенное: F-002
  7. Открытый перечень «результат 400, 401 и далее» в разделе «Ответ» — Вместо «и далее» перечислить все элементы явно: <уточнить: полный список> — или задать правило, по которому элемент входит в перечень. Существенное: F-005
  8. Повторить прогон с доступной моделью для этапов: individual, cross, verify_meaning, questions, bank

Готовность считается отдельно для разработки и тестирования: блокирует только подтверждённое критичное замечание с указанным бизнес-последствием и блокируемым решением; неполный прогон даёт «не определено», а не «можно начинать».
